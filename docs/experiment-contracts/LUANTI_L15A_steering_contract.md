# L15A v2 — 旋回振動の抑制

状態: FINITE STEERING ACCEPTANCE COMPLETE。基準 `8fa5920`。
[Evidence](../experiment-evidence/LUANTI_L15A_steering_evidence.md)。
[探索接続v1](LUANTI_L15A_exploration_connection_contract.md)の後続。
schema `l15a-terrain-resource-steering-v2`、rule `l15a-heading-persistence-v2`。
v1の保存記録を再生可能なまま維持し、修正版を別の明示modeとして提供する。

## 問題

v1は現在の5方向の最低値を毎回選び直す。
旋回で身体相対rayが変わると、同じ位置でも障害物の取得点と合成値が変わり、
逆向き旋回が最低になりうる。小差でも元の向きへ戻してしまう。
また、Foodが前方半円の射影から外れると、従来のFood方向への旋回が直前の回避旋回を取り消す。

今回変えるのは有限な行動選択と直前の操作結果の使い方のみ。
センサー、地形計算、Food/障害物/地表の係数、Worldの衝突判定、採取学習は変更しない。
World座標、未観測障害物、最短経路、将来の成功結果から操作を選ばない。

## 1. 小差なら現在方向を保つ

現在の地形がcompleteで、正面がscoredであり、
`正面total − 現在の最低total <= 0.10`（数値比較誤差1e-9）ならmove 1を選ぶ。
これはGameAI-localな許容幅。Core θ、学習結果、生物一般の能力値ではない。
partial/unavailable、blocked/no_surface、段差上限による正面除外はこの規則を通らない。
現在の物理的安全を保証するものではなく、最終的な作用は従来どおりWorldが判定する。

## 2. 実行できた旋回に、一歩だけの継続を与える

直前の操作に限り、以下をすべて確認する。

- 本人の受付済み観測・command・結果であり、実結果がturned。
- 現在のpose/body revisionが結果と対応し、実測yawが指令量と一致する。
- 同一period内、結果後の新しい取得であり、元commandの有効期限内。
- 直前の地形で旋回先がscoredだった。
- 現在も本人が同じ教示済みFood集合を観測している。比較単位はref集合で、並び順を使わない。
- 現在の地表・障害物はcompleteで、正面がscored。
- 現在正面のphysicalが計画時より悪化していない（比較誤差1e-9）。
- 現在正面のobstacleが計画時＋0.25以下。

成立すれば、今の相対最低方向が別でも、現在の身体でmove 1を一回選べる。
次の判断ではmoveの実結果を確認し、新しい観測から通常の評価に戻る。
旋回指令だけ、未報告/expired/staleの結果、古いposeを根拠に継続しない。

Foodの前方射影と、現在観測したFood集合は分ける。
局所Food観測は後方も含むため、横を向いて前方射影が空になっても、
同じFoodを現在観測できていれば地表・障害物を再検査できる。
このとき前方Foodを捏造せず、Food項が空の `current_recheck` を別に保存する。
前方Foodが空だからという理由で自動的にmoveすることはない。上の旋回実績と条件が必要。

Foodの前方射影やray標本が変わった前後のtotalを、同じ条件の量として比較しない。
継続の追加条件では、地表/障害物の寄与をそれぞれ比較し、現在のFood集合を別に確認する。
この再検査の取得が不完全なら以前の場を補完に使わずwaitする。
継続対象の直前地形がなく、前方Foodもない場合は、従来の観測済み後方Foodへの向き直しを使う。
この向き直し自体は一歩の継続を許可しない。

## 3. 一歩も進めない旋回の連鎖を有限で止める

上の継続が成立せず、次も旋回を選ぶ場合、直前の実旋回と逆符号ならその接近を止める。
同符号でも、同じ条件の実旋回が2回続いた後に3回目を要求すれば止める。
停止時はwait一回とし、現在追っているapproachの1件だけを既存のperiod内接近除外へ加え、approachを解除する。
他のFoodは除外しない。次の観測では他のFoodへの接近または既存の目印探索へ戻れる。

これは「Foodがない」「この場所は無価値」という学習ではない。
移動制御予算で一時的に接近を保留した記録であり、負のExperience・新M_B・Core Eを生成しない。
除外上限32、periodでの更新、既存24操作予算はそのまま使う。
途中のmove・wait・探索権限変更・period/期限の切替で直前旋回の連鎖は切れる。
長時間/全行動をまたぐ一般的なループ検出ではない。

## 出典・優先順位・再送

`steering` は、v1なら選んだ操作、現在の前方差、直前operation、実旋回の連鎖数、
計画時の成分、現在の再検査と各条件、停止したrefを保存する。
独立した永続storeや隠れた操作カウンタは追加しない。既存の受理済みdecision/resultから導出する。
同じ観測の再送は凍結commandを返し、旋回数・継続権限を増やさない。
個体/取得姿勢/期限の検査と一回作用は既存controllerが担当する。

pickup、所持品上限、身体対応不足、variationによる探索、Foodなしの目印探索は既存の優先順位を維持する。
変更はFood接近に限定し、自律注意・社会relation・疲労・未知の価値を同時に追加しない。

## 受入と限界

旧記録で実際に生じた45/90度の反転を再入力し、小差保持・実旋回後の一歩へ変わることを確認する。
新しい閉塞・取得不足・対象集合変更・身体不一致・期限超過では継続しないことも検査する。
同一設定の草地/自然林、各3個体×2periodをv1/v2それぞれ実Luantiで実行する。
実結果の逆符号の連続旋回、連続旋回長、Food接近中のmove/wait、取得数を別々に記録する。
単にwaitへ置換して旋回だけ減らした結果を移動改善とは扱わない。

草地の故障注入は、v1では従来のAの最初のpickup応答、v2では最初のFood接近turn応答を
Runtime受付後・身体適用前に一度捨てる。v2はagentを固定せず、誰のどの操作かを記録する。
再送で同一commandが返り、身体作用は一回であることを確認する。両版の故障起動時点は同一ではない。
これはcallback内故障注入であり、通信層の実断線ではない。

同じ位置へ歩いて戻るループ、全ての目印探索の旋回、一般的な経路到達・最短路・長期採取効率は別課題。
HTTP時刻と資源競合を含む独立runのため、短期比較だけで統計的な一般化はしない。
