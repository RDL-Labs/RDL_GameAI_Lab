# L15A — 同一作業の期限延長

用途は、期間末に接近中だった個体が、時間だけを追加したら何をするか確認すること。
`l15a-task-deadline-v1` を明示opt-inし、単一期間を16/32/64秒で比較する。
3個体・草地・seed20260928・steady・1.5倍・障害除去・疲労休憩・内部参照・目標再評価を固定する。

## 変更するもの

- 作業終了時刻と、それに束縛される操作の最終有効期限。
- 250ms周期を保つために必要な観測・操作台帳容量：個体ごと64/128/256。
- 反復診断と休憩の期間境界も同じ作業期限に合わせる。

`task_seconds` を設定時に照合し、同じrun内での期限変更を拒否する。
複数期間はこの入口では拒否。各個体の判断periodは最後まで0のまま。
既存入口の16秒期間・snapshot・設定wireは維持する。

## 変更しないもの

目印8目標、追加検討1回、目印あたり操作上限、食料接近24操作、休憩最大4回、
逆旋回停止、blocked_targetsによる再試行抑制、学習・選別・地形係数を据え置く。
通常の1指令の有効時間500msも同じ。移動距離や旋回量を増やして時間を代替しない。
期限延長は、これらの権限を再取得する操作ではない。

## 受入と解釈

各runの全wire・最終state・身体結果・観測・stockを既存監査で再生し、
個体別観測数、期間1件、判断period0、追加検討1回以下、休憩4回以下を確認する。
長い条件でも16秒地点で予算・反復の境界が更新されていないことを検査する。
stale/expired/stoppedのない比較記録を確認する。

採取・移動・停止理由・最後の接近状態を記録し、採取未達を自動的な失敗学習へ変換しない。
時間を延ばしても旋回停止や操作予算で止まった場合、その制約を次の検討材料とする。
同じseedでも実時間HTTPの時刻揺れがあるため、初期系列の一致も観測し、
倍率や時間だけに全行動差を帰属しない。まず1回ずつの有限比較であり、統計的な性能評価ではない。
