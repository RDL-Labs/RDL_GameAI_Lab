# L15A — 有限早回しの境界測定

状態: 実験用opt-in。通常設定は1倍を維持。

3個体・既存草地・steering/疲労休憩/内部参照/目標再評価・障害除去を固定する。
倍率だけを変え、16秒の1期間で1/2/4/8/16倍を測定する。
通常速度と比較し、全観測・身体結果・配送・個体分離・stockの既存replay監査を通す。
監査PASSだけでは早回し適格としない。expired/stale/stopped/結果欠測、取得枠欠落、
pending上限停止を別途数え、指令種別・量・理由・結果の系列も通常速度と比較する。

## 時計の実装範囲

`SimulationSpeed`（1〜16）はmulti-resource fixtureだけの試験設定。
既存globalstepのdtへ倍率を掛け、dedicated_server_stepを0.02/倍率秒にする。
約20msのsim刻みを狙うがOS・HTTPの遅延を保証しない。刻みを丸めて固定したり、
過負荷時に時計を止めたり、失われた取得枠をまとめて取得したりはしない。
実測最大刻み、要求倍率、World側壁時計経過をEvidenceへ保存する。

観測周期250ms、操作期限、疲労・反復・休憩・期間長・予算は同じsim単位を保つ。
HTTP timeoutは実時間のまま。従って通信のsim時間上の相対的負荷は倍率とともに増す。
待機実行から次観測までの時間で回復する既存疲労proxyにも差が入り得る。
指令一致を内部state全体の一致と呼ばない。

このWorldの身体操作は既存adapterの離散位置/yaw変更。Luanti全体の物理、落下、
ABM、日照、任意の他modまで同じ倍率で加速する機構ではない。
対象を連続物理へ広げる場合、この速度の検証をそのまま流用しない。

## 境界と余裕

破綻したrunも失敗記録として残し、低倍率へ下げて完走した記録で置換しない。
行動系列が変わり始める境界と、通信/容量が破綻する境界を分ける。
初回結果の後に確認条件を固定し、より低い倍率を長めの実行で検査する。
64秒確認は従来どおり16秒×4期間で、期間予算は更新される。
これは処理負荷の確認であり、探索の一期間を64秒へ延ばす実験ではない。
安全性の一般保証や最高速度の厳密探索は主張せず、機械・fixture・負荷に限定する。
