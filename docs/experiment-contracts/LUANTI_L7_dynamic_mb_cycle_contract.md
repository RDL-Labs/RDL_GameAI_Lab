# Luanti L7 Dynamic M_B Cycle Contract

## Status

L7 operational Dynamic M_B reference on Luanti 5.17.0.

## Purpose

Connect the L6 shadow CandidateRelation to the existing canonical review and
Dynamic M_B path while preserving the authority boundaries between World
outcome, learned material, rupture, reconstruction, and game action.

```text
three real Luanti attack outcomes
-> explicit Sleep
-> shadow CandidateRelation

independent canonical comparison
-> E
-> explicit review
-> H >= theta_eff
-> active M_delta

explicit T1 dispositions
-> T1-A material expansion
-> T1-B inspection
-> T1-C inactive M_B'
-> explicit cutover
-> fresh REENTERED comparison window
```

## Causal Separation

The Sleep candidate does not create `E`, `H`, or `M_delta`. L7 obtains the
active rupture state from an independent canonical comparison followed by an
explicit review. The two paths first meet in T1-A.

```text
CandidateRelation != rupture evidence
CandidateRelation != H
CandidateRelation != M_delta
```

## Explicit Selection Boundary

`POST /v1/luanti-t1-cutover` requires agent, Sleep-result, candidate, assessment,
reviewer, basis, evidence, and explicit dispositions. L7 v1 accepts only:

```text
CandidateRelation -> RETAIN
Experience        -> DEFER
```

The mixed Local Bias candidate is projected into three relation-specific
T1-ready candidates before material expansion. No candidate is automatically
retained merely because it exists or has strong support.

## Reconstruction And Cutover

T1-C creates a distinct inactive artifact while leaving the active parent
unchanged. The existing cutover service then archives the parent, activates the
new model, resolves the active `M_delta`, and opens a fresh comparison window.

```text
reconstruction != activation
activation != game action authority
REENTERED != reuse of the old comparison window
```

## Acceptance

1. Three real Luanti outcome cycles form one support-3 shadow candidate.
2. An independent explicit canonical review creates active `M_delta`.
3. Missing or implicit T1 dispositions are rejected.
4. Three relation-specific candidates enter T1-A with Luanti provenance.
5. T1-B retains current `M_B` and candidate materials while deferring raw Experience.
6. T1-C creates a distinct `RECONSTRUCTED_INACTIVE` artifact.
7. Explicit cutover archives the parent and activates the new model.
8. The next canonical capture is `REENTERED` and does not reuse the old comparison count.
9. No Goal, Trajectory, or action authority is granted by candidate, reconstruction, or cutover.
