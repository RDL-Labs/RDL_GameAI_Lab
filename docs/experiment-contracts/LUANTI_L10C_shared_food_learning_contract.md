# Luanti L10C — 共有Foodでの相互干渉とM_B学習

**状態:** IMPLEMENTED / ACCEPTANCE COMPLETE、2026-09-27。
実World結果・検証範囲は[Evidence](../experiment-evidence/LUANTI_L10C_shared_food_learning_evidence.md)。
基準: `0a852632`。既存の[L10](LUANTI_L10_sensory_learning_action_contract.md)と
[L10B](LUANTI_L10B_multi_agent_learning_contract.md)を再利用し、共有資源用の適用境界を分離する。

## 1. 問いと今回の範囲

同じFoodを実際に取得しようとするA/Bについて、相手の身体作用によって変わる自分の取得結果を経験し、
観測条件との有限な関係を形成・独立検査してM_Bへ採用すると、次の試行／保留が変わるか。
片方の選択の変化が、相手の実結果にも影響するところまで追う。

初版の予測入力は、既存の遠景センサーによる粗い色を維持する。色は開始条件の手掛かりである。
近景SensorFrameの現行payloadは`visible_count`のみで、相手の行動を識別する入力ではない。
この制約をWorldの他者ID・意図・勝者ラベルの注入で補わない。

今回学ぶのは「この有限装置で、この観測色のとき、自分の試行が取得に至った／至らなかった」という関係。
色の意味、相手の存在・意図の理解、相手が原因だというNPC側の同定、敵意・所有・協力の学習は主張しない。
実験者はWorld記録から共有資源の変化を検査できるが、その正解記録は予測入力へ流さない。

## 2. 共有Worldと試行の単位

- 固定A/B、Food entityは**全体で1件**、Baseは個体別に1件ずつ。通路の壁は置かない。
- 装置のWorld座標はA/Base Aが`(-4,1,0)`、B/Base Bが`(4,1,0)`、Foodが`(0,1,0)`。
  共通の色markerを`(0,1,14)`に置き、取得時だけ両個体をmarkerへ向ける。
  座標はWorldの実行・Evidenceにのみ使い、色からの予測要求へ含めない。
- Aは`fixture-life-sensory`、Bは`fixture-life-sensory-compact`、いずれもrevision 1。
  遠景は同じmarkerを取得し、両profileで既存の正面単一特徴条件を満たすことを実測する。
- 1 shared EpisodeにA/B各1操作。Episode初期化を各controllerへ任せず、共有World側の1箇所で行う。
  両方の身体処理終了・結果受付後だけ次Episodeへ進む。片方だけのresetによるFood再生成は禁止。
- Episode間で位置・向き・手持ち・Foodを初期化し、個体別の経験・M_B・台帳とWorld時計は保持する。
  独立run間ではそれらも初期化する。Baseへの累計depositはrun内の検査用に保持する。
- 近景・遠景・聴覚は各Episode開始時に各個体3frame。近景件数はその時の有限観測から取得する。
  聴覚の空窓も正常記録でよい。予測に使うのは受理済みの本人の遠景frameのみ。

他個体のExperienceをコピーしない。両者が試したEpisodeでも、本人の決定・身体試行・結果を別に記録する。
同じ資源を巡る両者の経験は統計的に独立な2票とは主張せず、shared Episode参照で依存を追えるようにする。
relationの支持は、本人の異なるEpisodeの経験だけで数える。

## 3. World実行順序を通信順から分離する

両個体のframe受理と決定受渡しが揃うまで、共有Foodへの身体操作を開始しない。
World時計は待機中も進む。この有限なEpisode開始barrierは、HTTP応答順が勝者を決める混入を避けるための装置条件。
自由な生活スケジューラーや、相手を待たず進む一般競争を検証するものではない。

| 項目 | 初版の固定条件 |
| --- | --- |
| 取得・決定 | L10と同じ完全取得条件。取得から決定要求まで最大500000µs |
| 開始barrier | 共通の取得時刻から500000µs以内に両決定が有効な状態で揃うこと |
| 開始時点T | barrier成立後、次の250000µs World枠。実際の処理時刻を記録する |
| 先行／後行 | 先行の許可時点T、後行はT+250000µs。deferでも割当を詰めない |
| 身体操作開始期限 | 本人の取得から1000000µs以内。待機や再送で更新しない |
| 身体step | 250000µsごとに最大1作用。Food方向へ最大1node移動、距離1.25以内なら取得を試みる |
| 帰還 | 取得した本人だけBaseへ最大1nodeずつ戻り、距離1.25以内で1回deposit |
| 操作上限 | 1個体1Episode最大16身体step、結果の完了時刻は決定要求から最大5秒 |

移動は既存RW2/L10と同じ有限なkinematic操作。先行／後行はWorld側の開始許可であり、NPCが学んだ速度差ではない。
初版は身体同士の衝突・押し合いを扱わず、共有Foodの消費だけを結果へ作用させる。
毎stepの開始位置から接近／取得／帰還の一つを処理し、移動した同じstepで追加の取得を行わない。
初期距離と速度は対称なので、両者が試行すれば1枠先行した方が先に取得を試みる。
同じ枠のactor処理順を入れ替えても結果が変わらないことを検査する。

取得は共有Foodの存在確認と確保をWorld側で一回処理し、その後entity除去・本人の手持ちへ反映する。
同じFoodから2人の手持ち・2回のdepositを作らない。Worldの確保記録は物理資源管理であり、心理的所有ではない。
後行者は開始時に予定の失敗を受け取るのではなく、実際に接近し取得を試みた時点の消失によって非取得となる。
通路に壁を置いて失敗を代用したり、結果boolだけを反転したりしない。

大きな時刻ジャンプで実行枠を飛び越した場合、追いつくための複数身体作用をまとめて行わない。
期限切れ、受渡し欠落、取得不完了等はrunを不成立として停止し、未完了操作に失敗Experienceを捏造しない。
停止前に実際に確定した結果は保持するが、そのrunを完全な受入や規定数の学習材料には数えない。
未知入力への試行と、未実行・未完了は別状態としてWorld記録に残す。

## 4. 観測色と開始条件

初期の標準対応は赤ならA先行、灰ならB先行。色と開始順序はfixtureが対応づける実験条件であり、
その対応表をRuntimeの予測・候補形成・action規則へ渡さない。
反転対照では形成段階から対応を逆にする。同じ色でも本人の経験に応じた逆のrelationが残ることを確認する。

現行の `sensory-food-table-v1` と「未知なら有限試行、取得予測なら試行、非取得予測なら保留」を維持する。
purposeは `predict-bounded-food-attempt-from-distant-color`、装置contextだけを
`l10c-shared-food-apparatus-v1`として分離する。contextは起動時の明示modeから固定し、任意の要求値で選ばせない。
既存の `l10-fixed-food-apparatus-v1` relationを共有資源へ暗黙適用しない。
run/epoch/agent/profile/model/clock/contextの一致を形成・解釈・結果比較で照合する。

HTTPの明示opt-inは `--luanti-learning-shared-food --luanti-learning-loop --sensory-observation`。
L10Bの `--luanti-learning-multi-agent` との同時指定は拒否する。共有flagなしの単一個体／L10B modeは
従来contextを使う。既存の学習入口とA/B分離を再利用し、要求payloadへcontext選択権を追加しない。

## 5. 帰納・検査・採用

各runの12 shared Episodeで、各個体は以下の同じ区分を使う。各区分で赤・灰を同数取得する。
Episode番号はharnessの材料分割にだけ使い、予測値や選択を決める入力にはしない。

| Episode | 役割 | 開始条件 |
| --- | --- | --- |
| 1〜6 | 形成。色ごとに本人の異なる3経験 | runの標準または反転対応 |
| 7〜8 | 未使用の検査。色ごとに別Episode/eventの1経験 | 同じ対応 |
| 9〜10 | 採用あり／inactive対照で次の実選択を確認 | 同じ対応 |
| 11〜12 | 隠れた開始順序だけを逆にするcanary | そのrunの形成時の対応から反転 |

初期M_Bはunknownで、正常な形成・検査段階ではA/Bとも試行する。片方が保留した経験を無理に埋めない。
色ごと3件の一致から形成し、別の1件が一致すればRETAIN、不一致ならREJECT、形成不一致ならDEFER。
support=3、validation=1のまま。相手の成功、同event再送、再評価を票に加算しない。

両者とも同じ経路でT1-A/B/Cとinactive artifactまで進め、指定した側だけ明示cutoverする。
reviewは引き続きharnessが明示する独立canonical count比較を使い、その観測・assessment参照も保存する。
共有Foodの消失や本人の取得失敗を、そのまま未吸収E/HやM_deltaの起動理由に変換しない。
操作結果のF/F'は、その操作の決定時に固定した本人のM_Bで比較する。

Episode 11〜12の結果は追加Experienceとして記録できても、今回2回目の再構成は行わない。
採用済み関係は相手の行動条件を完全には表しておらず、環境条件や相手のpolicyが変わると予測が破れる余地を残す。

## 6. 実Luantiの受入比較

**5独立run × 12 shared Episode = 60 shared Episode、A/Bの120操作、開始時360 SensorFrame**で検査する。
shared Episodeと個体別操作を混ぜて経験数を水増ししない。各個体の形成は6経験、検査は2経験。

| run | A採用 | B採用 | 形成時の色と先行者の対応 |
| --- | --- | --- | --- |
| both_active | あり | あり | 標準 |
| neither_active | なし | なし | 標準 |
| a_only | あり | なし | 標準 |
| b_only | なし | あり | 標準 |
| reversed_cues | あり | あり | 反転 |

主比較はEpisode 9〜10。採用側は自分の取得予測に従い、非取得を予測する色では保留する。
未採用側はunknownから試行を続ける。両者採用なら各色で一方が試行し、他方は保留する。
片方だけの採用をA/Bで入れ替え、特定agentの固定優先やprofile名の分岐では説明できないことを検査する。

canaryは単一個体L10と違い、**開始順序を反転すれば必ず実結果が反転するとは限らない**。
相手も保留すれば後行者でも残ったFoodを取得できるためである。

| canaryの条件 | 期待する記録 |
| --- | --- |
| 両者採用 | 一方が試行、他方は保留。試行者は後行でも取得でき、予測誤差が必ず出るとはしない |
| 両者未採用 | 両方試行し、反転した先行者が取得。予測unknownなのでF/F'比較は不能 |
| 片方だけ採用、採用側が取得を予測 | 両方試行し、未採用側が先行取得。採用側の実非取得を同じM_Bで比較し差-1 |
| 片方だけ採用、採用側が非取得を予測 | 採用側は保留。相手は取得。保留側が試せば成功したという反実仮想をExperienceにしない |

受入時の集計（各cellは本人の試行数 / deposit数。実記録はEvidence参照）:

| run | A | B |
| --- | --- | --- |
| both_active | 10 / 6 | 10 / 6 |
| neither_active | 12 / 6 | 12 / 6 |
| a_only | 10 / 5 | 12 / 7 |
| b_only | 12 / 7 | 10 / 5 |
| reversed_cues | 10 / 6 | 10 / 6 |

各shared Episodeで合計depositは1、各runで12となる。個別のEpisodeの参照・予測・身体記録を検査し、
この集計値だけでPASSにしない。試行減少だけから学習が常に有利、保留が最適とは判断しない。

## 7. 保存・権限・有限予算

- 1run各個体最大16決定、1再構成。合計32決定・2再構成。1操作最大1結果event。
- SensorFrameは1Episodeで各3件、1run72件。配送は個体ごと最大4frame、既存の明示ack・重複保存防止を使う。
- shared Episode参照、個体別operation/event/frame/decision/Experience/modelを保存する。
  ローカルID文字列が同じでも所有者を混ぜず、相手のcallbackと結果eventの付替えを拒否する。
- 完全な決定／結果／学習再送は旧結果を返す。内容変更は拒否し、支持数・予算・身体作用を増やさない。
- callbackは受渡しのみ。身体作用はWorld stepで許可・本人・期限を再検査し、実行前に権限を消費する。
- このmodeの身体作用はlearning decisionだけから許可する。通常observe応答の旧actionを併せて実行しない。
- 各操作の決定を再要求し、完了後の同callback再注入でも取得・depositが増えないことを実機で検査する。
- 共通のFood確保とepisode resetにも一回性を検査する。個体別操作の冪等性だけでは十分としない。
- 通信失敗時の無期限再試行、永続台帳、再起動をまたぐ保証は作らない。

World Evidenceには配置、marker、予定／実開始時刻、step、確保者、実entity除去、手持ち、Base増分を残す。
これらを受理済みframe・Runtime要求・決定・本人の結果と分離して保存する。再生は保存frameを改変せず再受理し、
本人の入力と結果から学習・選択を再現する。World Evidenceを予測の補助辞書として渡さない。

## 8. 受入項目と停止境界

以下を受入項目とする。実World、Python再生、代替adapterによるLua局所試験の範囲はEvidenceで区別する。

1. 同一Foodの実entityを巡る取得で片方の消費が他方の実試行結果へ影響し、二重取得・二重depositがない。
2. 色・agent名・Episode番号・開始順序の正解をaction規則へ埋め込まず、受理frameと本人のM_Bで予測する。
3. 形成／未使用検査を分け、A/Bの経験・profile・T1・M_Bが混線しない。
4. 採用有無と役割交換、色対応反転の5runで、決定・身体作用・本人の結果を対応づける。
5. 相手の保留による結果変化と、片方採用canaryの反例を区別する。未試行を反証・成功票にしない。
6. 再送・古い／相手のcallbackを拒否し、共有資源と各身体操作の一回性を別々に確認する。
7. 通信受渡し順・同枠のactor処理順を変えても、規定の開始枠を守る限り身体結果が変わらない。
8. 不完全取得・鮮度切れ・枠逸失・結果未完了を正常な非取得にせず、保存された確定事実を改変しない。
9. L10用relationを誤適用せず、形成材料へのcontext混在、他run/agent/frame/assessment、内容改変、17決定目、2再構成目を拒否する。
10. 固定再生、必要なPython試験、全体テストに加え、既存L10・L10B・OBS-9 faults実機回帰を通す。

実装は既存learningの装置context分離、共有World controller、起動mode、検査・再生scriptからなる。
観測器の追加や既存Observation v1の完了条件の変更は行わない。
本契約の到達点は**実相互干渉のあるWorldで、本人の経験から採用したM_Bが次の選択を変え、
その選択が相手の結果にも作用すること**。社会的な他者理解、所有、援助要請、動的神経、DNA、
自律review/Sleep、一般Goal/Trajectory、反例後の再学習、OBS-9周期取得＋Probeへの常設統合は保留する。
