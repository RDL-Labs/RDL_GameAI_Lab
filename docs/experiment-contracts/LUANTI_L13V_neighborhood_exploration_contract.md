# Luanti L13V — 目印周辺の有限探索と未発見のM_B

状態: 有限機構の実装・受入完了。Food発見目標の未達を含む実行結果は[Evidence](../experiment-evidence/LUANTI_L13V_neighborhood_exploration_evidence.md)。2026-09-27。
[L13U](LUANTI_L13U_landmark_exploration_contract.md)の観測特徴と小目標制御、
[L13S](LUANTI_L13S_learned_exploration_contract.md)の独立日・Sleep・検査・T1/M_Bを使用する。
意味基準は[Core参照](../semantic-reference/RDL_Core_T0_T1_reference.md)。

## 問いと初期能力

目印を近くで再取得した地点から、有限な周辺探索を行い、成果がなければ次の小目標へ進めるか。
その未発見を別日に検査し、採用したM_Bが同じ条件の探索を繰り返すかどうかへ作用するか。

最初から与えるのは、現在観測した特徴への接近と、二方向への短い往復という身体制御である。
Foodへ続く方向、未探索の場所の位置、地図、Worldの対象IDは与えない。
学習するのは「この取得条件から、この有限な操作・取得を行った範囲ではFoodを観測しなかった」という関係。
探索方法の発明、空間全体の探索完了、場所の恒久的な同定は主張しない。

## 通常取得枠内の二方向探索

専用schema `l13v-neighborhood-exploration-v1` を明示した入口だけを使用する。
地形、13本の水平ray、局所Food、下向き9ray、山の遠景、遮蔽、profile、身体stepはL13T/Uのまま。
一日16秒・250ms/64枠、最大30日・別日3回Food発見の停止条件も維持する。

1. L13Uの小目標が、一件の対応する `near` 特徴として再観測された時点を起点とする。
2. 起点の取得条件、観測ID、姿勢、時刻、特徴の粗色・角域・距離帯を保存する。
3. 左へ90度、move1を2回、180度向き直し、move1を2回、起点の向きへ戻す。
4. 右側にも同じ二歩の往復を行う。合計16操作、開始・中間・終了を含む17観測。
5. 各操作は通常枠の一回許可を使う。追加samplerや同枠の二重取得は作らない。
6. 取得時刻で起点から最大5秒。日末で途中終了した探索も、完了した負の材料にはしない。

独立の移動許可と実測resultを使用する。自身の相対forward/right/up/yawを積分し、
8操作目と16操作目で起点との距離0.001node以内、向き差0.01度以内を要求する。
両帰還時に、起点の粗色・対応角域15度以内を満たすnear特徴が一件あることも必要。
指令通りに帰ったとは補完しない。途中で目印が視野外へ出ることは許容する。

この往復は相対身体情報を使う小さな実行機構であり、一般的な迷子からの帰還ではない。
二方向の線状取得だけなので「周囲をくまなく調べた」とは呼ばない。
特徴の対応は外観条件の一致であり、同じ木・岩・場所の同定保証ではない。

## 結果の分離

| 結果 | 扱い |
|---|---|
| `completed_no_food` | 16操作・17完全観測・二回の帰還確認が成立し、その17観測ではFoodなし |
| `food_observed` | 完了した探索の少なくとも一観測でFoodが見えた。未発見材料にしない |
| `blocked` / `operation_not_executed` | 身体作用が予定通り実行されなかった |
| `acquisition_incomplete` | 必要な取得条件が欠ける。検出0件へ置換しない |
| `body_correspondence_unavailable` / `return_not_confirmed` | 実作用との結び付けまたは帰還確認が不足 |
| `anchor_lost` / `anchor_ambiguous` | 帰還時の対応特徴が0件または複数件 |
| `survey_deadline` / 日末途中終了 | 有限な探索が完了していない |
| `active_M_B_no_food` | 採用済み関係により、この探索を実行しなかった。新しい負の経験ではない |

終了を記録する枠はwaitし、次の取得で予算が残っていれば別の小目標を選ぶ。
粗い外観なので同様の特徴を再選択することはある。World座標による訪問済み集合は作らない。
目の前にFoodがある場合は、過去の未発見予測を理由に探索省略しない。pickup圏内は既存pickupを優先する。

## Sleep → 独立検査 → T1/M_B

初版はL13Sと同じく、一系列につき一候補・一独立検査・一回の採用を上限とする。
最初の適格な日にFood経路が形成できれば既存の正例を優先する。
そうでなければ、最初の `completed_no_food` を候補にする。
後日の全ての失敗や発見を継続的に再学習する仕組みではない。

候補は `l13v-completed-neighborhood-no-food-v1`。
本人が受理した開始までの観測・実操作列と、局所探索の開始位置、起点特徴、17観測、実行結果を参照する。
結果ラベルだけを信用せず、形成時・検査時とも受理記録から16操作・取得・身体対応・帰還を再検査する。

次の独立日に、形成日の前置き経路と局所探索を明示Probeで再生する。
前置きの取得条件・実作用が対応しない、取得不足、帰還欠測はDEFER。
探索内で一度でもFoodが見えたらREJECT。完全な有限探索が再び未発見ならRETAIN。
同日や同runの付け替えで独立検査にはしない。

支持は形成日の1 Experience。独立検査は別の1 Experienceとして区別する。
16操作・17観測・二回の帰還、後日の再評価や再送で支持数は増やさない。
日末処理はstaging後に一括公開し、途中失敗でExperienceだけ/M_Bだけを公開しない。

### Coreの差と未発見は別の根拠

未発見を `E=1` や不快量として作らない。負の候補の経路では、実際に取得した面特徴の数を
`l13v-observed-patch-count:<series>` という明示したperception ruleで既存のcount解釈へ渡す。
一日最大二断面（最初の完全取得と、そこから特徴数が変わった最初の完全取得）に限定する。

形成日内の二断面について、同じ更新前M_Bによる実際の非ゼロな特徴数の差を明示reviewし、
既存M_delta/T1入口を使用する。未発見候補のRETAIN根拠は、これとは別の独立日検査である。
特徴数の差だけでFood不在を導かない。形成日に該当する差がなければ
`review_difference_unavailable` とし、独立検査がRETAINでもM_Bへ採用しない。

日末Sleepは明示的なharness処理であり、自律的な睡眠開始や自動のCore H増加を追加しない。
正のFood候補は既存L13SのFood-count差の経路を維持する。

### 採用済みM_Bの使用範囲

`FrozenGameAIMB.interpret_neighborhood` は、個体・系列・問い・取得条件・起点特徴・探索plan・期限が
一致した場合に限り `known / predicts_food=false` を返す。
不完全取得、別の条件、現在Foodが見える場合はunknown。
controllerは起点へ接近した後、この解釈を根拠に今回の16操作を省略し、次の小目標選択へ戻る。

遠くから同じ場所を認識して避ける機構、未訪問地域の探索、別のplanへの負の予測、永続的なFood不在断定ではない。
単一の粗い条件へ二度未発見だったという有限な予測であり、将来の正しさは保証しない。

## 受入と因果比較

- 変更前と同じ草地/木立、seed20260927、最大30日、Food発見3日の二系列を実Luantiで実行する。
- 成功するよう配置やseedを調整しない。未発見・途中終了も保存する。
- wire、受理state、World実測、日末処理を保存し、現行コードで全再生する。
- 実験者用World座標による二回の帰還も独立に監査する。座標は個体の選択やM_Bへ渡さない。
- 負の候補がRETAIN/T1再構成まで通った系列は、最初の検査日までの同一履歴を二分する。
  一方はcutoverあり、他方は検査・再構成だけでcutoverなし。
- 両者の次の日だけ形成日の候補抽選seedを明示再使用する。同じ初期World・同じ観測条件への
  再進入で、最初の分岐がactive M_Bのwaitと非採用側の実turnになるか調べる。
- これは明示的な再進入対照。本人が場所を記憶して自力で帰還したという主張にはしない。
- 通常系列の発見数と、この対照での行動差を別々に報告する。

全世界の不在推論、一般経路記憶、迷路探索、多候補の継続更新、多個体、夜間、飢餓・死亡、
未知の目印の意味付けは今回の範囲外。
