# 簡易エネルギー消費場 v1

2026-10-04。基準c5410b1。FINITE FIXTURE IMPLEMENTED。

ニュートン物理の実装に先立ち、個体の身体・荷重・観測済み抵抗から最大5候補の
実行可否と消耗を見積もる純粋関数runtime.energy_field.evaluateを置く。
World全域の経路地図ではなく、現在の有限な操作候補への局所場。

四層身体の消耗倍率を(1+.1×荷重)×抵抗倍率へ拡張。抵抗倍率は1〜10、既定1。
歩行/run/climbのreserve/burst/strainとblocked試行消費へ適用し、身体余力検査も同倍率。
抵抗自体で越え高さは変えず、従来の荷重・肉体限界で決める。
restで地面からエネルギーを得ることはない。単位は既存proxy、物理ジュールではない。

候補入力はref/action/clear/resistance/goal_cost。
未知clear/resistance、blocked、身体能力不足は安価な候補にせずcost=null。
実行可能候補はgoal_cost＋reserve消費/残量＋burst消費/残量＋strain増分で順位付け。
これは設計者の初期評価規則で、学習された評価機ではない。
全候補不成立ならrestを返すが、回復不能や未達を成功とはしない。
消耗予測は既存身体stepを純粋に評価し、実作用時にWorldが現在条件で再判定する。

実験は前方と側方の2候補。前方抵抗1または5、側方1、側方の目的cost .15。
抵抗は専用Worldの局所方向設定で、草地/砂地の空間分布をまだ生成しない。
側方移動は1歩であり、目的地までの迂回完了ではない。

複数個体例はAの採取6→drop1→Bの取得→Aの再取得不成立を明示スケジュールする。
本人への入力は自己身体・荷物・局所候補のみ。他者の内部状態は渡さない。
共通時刻順に操作し、操作していない時間に暗黙の回復を与えない。
drop/pickupの動機はまだ学習せず、今回の対象は移動選択・実消耗・資源保存。

通常探索terrain/所持台帳/Sleepへのenergy_fieldの自動接続は未実装。
既存body-modeはresistance=1のまま。物理構造帯案PW-0〜4の完了とは扱わない。
