# L15A — 最大30日・資源の持ち帰り3回で終了

状態: FINITE IMPLEMENTATION / 実機結果は別Evidence。
基準: `85a6950`。既存3日版は変更せず、`l15a-landmark-return-campaign-v1`を明示opt-inする。

## 条件

A/B/C・steady・natural_meadow・seed20260928・1日64秒・1.5倍を維持。
同じWorldのまま最大30日。生成済み塔、観測、帰還規則、日中/夜間の枠、資源8地点×12単位は前回と同じ。
日ごとにWorld・在庫・本人記憶・採用済みモデルを初期化しない。
上限30日までに未達でも、その結果を保存して終了する。

## 持ち帰りの計数

初版は3個体合計3便。1便は個体×夜入りの単位であり、資源の個数ではない。
12個まとめて運んでも1便、空荷なら0便。
初めて実waitを実行した夜入り時に、実験者が以下を監査する。

- 実身体位置が塔中心から水平10以内（前回の拠点域）。
- その個体が実際に採取したoperation IDのうち、まだ持ち帰りに計上していないものがある。
- 当該の新規ID集合を一つの便として記録する。

同じ荷物を翌日も持っているだけでは再計数しない。
前日に野外へ残った荷物を後日に持ち帰る場合は、その後日の1便へ数える。
同じ個体/夜の複数wait、HTTP再送、採取数量で便数を増やさない。
拠点域外なら、本人がhome_likeと判断していても実持ち帰りには数えない。
実験者の座標・計数は移動判断へ入力せず、実験の停止判定だけに用いる。

これは実荷物を持った拠点域への到着確認であり、deposit・倉庫への移管・消費は実装しない。
在庫を勝手に空にせず、計上済みIDは実験者の台帳に分離する。

## 終了と未処理通信

3便目を確認したWorld stepで新規観測を停止し、既に送った観測/身体結果は有限にdrainする。
全個体のfinish理由は`return_target_reached`。終了時の夜が途中なら、その夜のwaitを32件に水増ししない。
未達の場合は30日=1920秒、1個体7680観測までの`time_limit`。
同時夜入り時の順序は保存した身体実行時刻と個体順で監査し、3便以降を追加計数しない。

## 長期化のための受付処理

専用agentはsensory受付前に、保存済み不変frame本体を再複製せず、変更する索引とlistを複製する。
新規frameの検証と複製、拒否時の未公開、公開snapshotのdeep copyは維持する。
既存agentの通常deep copyを変更せず、汎用deepcopyの意味も変更しない。
前回3日保存記録を全HTTP再生し、従来の命令・判断・保存状態との一致を検査する。

夜間記録整理、帰還器、M_Bの学習条件は前回どおり。
日数を延ばしただけでSleep/T1接続や経路学習が成立したとは扱わない。

## 検証

空荷・同じ在庫・12個を1便・拠点域外・後日帰還・新規便・個体合計3便上限を局所検査。
実Worldの採取ID・身体位置・夜入り実waitから、計数をPythonで独立に再構成する。
全HTTP再生・身体連続性・資源保存・取得slot・取得時刻・個体分離・夜間位置不変を検査する。
実験が上限で終わった場合、3便終了の実World正例が検証されたとは主張しない。
