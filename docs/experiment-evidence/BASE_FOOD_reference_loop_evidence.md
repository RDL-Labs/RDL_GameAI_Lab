# Base-Food Reference Loop Evidence

**Recorded:** 2026-09-18  
**Boundary:** Godot 4.7.2 mock world + opt-in localhost Python Runtime  
**Result:** v0.3 reference loop complete; reusable life-loop boundary established

## Observed verticals

The repository now carries executable evidence for all four declared stages:

1. Coarse God Statue cue -> bounded NPC observation -> short prediction ->
   Goal -> committed Trajectory -> Base deposit.
2. Follow and ignore produce distinct world consequences; successful deposits
   become finite cue-result experience.
3. Two distinct successes permit cue-free Goal formation from observed low
   stock; one success does not.
4. Generic, Threat, and Novelty candidates compare against an existing
   Trajectory without erasing it. Fixed NPC-side settings produce controlled
   response differences and resume the life loop after the candidate clears.

The final tuning comparison uses two deliberately extreme operational presets.
Under equal world and candidate observations, `trajectory_locked` continues the
Food trajectory while `context_switching` diverts toward visible Novelty and
then returns to Food. These presets are not personality, diagnosis, DNA,
dynamic neural state, affect, canonical M_B, or H.

## Authority and limits

- Godot owns precise world state and resolves movement, pickup, and deposit.
- Runtime receives only bounded observation, finite life context, and self-body
  snapshot.
- God Statue cue, interrupt candidates, and tuning presets do not carry
  canonical action authority.
- Experience and profile state are process-local and finite.
- FoodNeed shadow comparison remains isolated from the default canonical
  count-sidecar, assessment/H, T1, theta, and M_delta.

This evidence demonstrates one reusable life-loop shape:

```text
Need pressure
-> bounded context
-> short prediction
-> Goal
-> committed multi-step Trajectory
-> world resolution
-> changed observation
-> finite result experience
-> later recurrence
-> interruption and resumption
```

It does not prove that the Food-specific constants generalize unchanged to
Rest, Safety, or social behavior.

## FoodNeed admission review

Decision: **retain FoodNeed as a default-off shadow experiment**.

The loop evidence establishes operational relevance and correct frozen-window
behavior, but no observed failure currently requires changing the default
canonical model profile. Promotion would require a separately versioned model
contract, fresh-process entry, migration/rollback rules, and evidence that the
additional canonical relation improves a declared diagnostic question. None of
those should be inferred merely from successful life behavior.

The review may be reopened after at least one non-Food life loop demonstrates
whether the same admission shape is genuinely reusable.

## Next boundary
