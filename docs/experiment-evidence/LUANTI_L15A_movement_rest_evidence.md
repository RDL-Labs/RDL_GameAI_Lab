# L15A — 疲労・反復による休憩の実Luanti比較

2026-09-28、基準 `d5a1b9f`。[契約](../experiment-contracts/LUANTI_L15A_movement_rest_contract.md)。
有限な疲労proxy、反復要求の消費、最大4判断/1秒の休憩、通常観測継続、再開を明示opt-in経路に実装。
旧steering v2の既定動作は変更しない。反復検査をRuntime共通moduleへ抽出し、旧offline再生との一致を検査した。

## 事前固定した主比較

自然草地、同一配置・seed、3個体、各2期間（32秒）、8資源地点各12単位。
全個体の既存予測性profileはsteady。休憩機構だけをdisabled/fatigue/repetition/combinedへ変更。
各条件1runであり、通信・capture時刻には実時間の揺れがある。厳密に同じ時刻列の比較でも統計的な効率推定でもない。

| 条件 | 休憩開始 | 休憩wait | 有限終了で再開 | 合計実移動距離 | 採取 |
| --- | ---: | ---: | ---: | ---: | ---: |
| なし | 0 | 0 | 0 | 156.628 | 0 |
| 疲労のみ | 13 | 52 | 13 | 78.628 | 0 |
| 反復のみ | 1 | 4 | 1 | 150.628 | 0 |
| 両方 | 13 | 52 | 13 | 71.557 | 0 |

両方条件の13開始はすべて疲労由来。疲労のみとの移動距離差を反復の効果とは扱わない。
反復のみでは今回1回実起動した。前のshadowは別の保存run・mixed profileであり、v2で未到達だった結果を上書きしない。
採取改善は全条件で未確認。休憩中も各個体128観測が継続し、wait前後の身体readbackが同じことを検査した。
休憩によって既存固定往復の途中が未完了になった例もあり、正常往復だからといって起動を抑制していない。

## 何を検証したか

疲労は本人の受理済み実測移動・yawに基づくproxyであり、生理学的な筋疲労ではない。
休止が確認されたwaited結果の実行時刻から次取得までだけ回復計算する。欠測や通信待ちは回復根拠にしない。
記録の `recovery` は下限0への切詰め前の回復計算量であり、必ずその量だけ疲労が減ったとは限らない。
休憩後は現在の観測で既存選択を計算し、別方向への変更や脱出を強制しない。
全受理wire応答と最終Runtime stateを保存記録から完全再生する。
既存World監査による共有資源保存則、個体混線防止、一操作一作用、有限取得数も検査対象。

## 成果物と再実行

成果物 `tests/fixtures/luanti_l15a_movement_rest.json.gz` に4主比較と別の故障runを保存。
故障runはcontrol配置2地点を使用し、主比較から分離する。
故障runは休憩17回・68wait・再開17回、Cの採取12件。配置が異なるため、採取を休憩の改善効果へ帰属しない。
応答消失/再送、旧callback、個体混線・操作重複のguardと、旧期限の失効を既存検査で確認した。
全run、全個体の観測、実行結果、身体readback、休憩起動理由、疲労/反復量、未完了探索を保存。

計5run・15個体run・1920観測。実Luanti5run PASS。
専用12テストPASS（4.330秒）、関連回帰60テストPASS（28.888秒）、各exit code 0。
関連回帰は旧履歴診断・反復shadow・terrain接続・steering。リポジトリ全体テストは今回未実施。
専用試験には5runの完全再生、実休止後の疲労減少、disabled runの元v2への再生による全observe応答/学習/store一致を含む。
反復起動の要求消費は合成detectorを使う調停単体試験でも検査したが、実World反復の証拠とは区別する。


## 停止境界

休憩の身体作用と再観測機会は成立するが、止まるだけで循環を解消したり、新しい発見を得たりする保証はない。
疲労・反復・睡眠・神経状態を同じ量にまとめず、Core E/HやM_B更新へ昇格しない。
次の比較はこの有限結果を踏まえて決める。疲労係数・地形・探索規則を同時に調整し、成功へ合わせることはしていない。
