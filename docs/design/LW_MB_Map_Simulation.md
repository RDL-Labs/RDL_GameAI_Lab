# 観測MB地図の有限シミュレーション

2026-10-25。`--mb-simulation on` / config `mb_simulation=on`。既定off。観測した関係を内部で数段たどり、最初の行動と予測される次の観測を既存の確率的候補選択へ渡す試作。

## 記憶と入力の境界

`src/lw/learning/mb_map.jl` に、観測状態のノードと実行後の遷移を記録する有向グラフを置いた。これは一般的なMBシステム全体の実装ではなく、LWの視覚的関係に限定した観測モデル。

現在の色・距離帯・色同士の相対角度から粗い署名を作る。現在観測で区別できる色が2種類以上必要。方向の一様な回転には相対角度で対応するが、同じ色配置の別地点を混同する可能性や、見える範囲の変化による署名の分裂は残る。Worldの物体ID・地図・絶対座標は入力しない。実行結果から得る旋回量・移動量・reserve差分は、行動のフィードバックとして記録する。

実行と直後1tickの観測が結びついた場合だけ遷移を追加する。blocked、観測不足、欠けた時間間隔から成功遷移を作らない。逆方向の辺は実際に経験しない限り追加しない。単なる左右反転やWorldを参照した近道生成は行わない。

拠点は現在の接触距離内での認識、食料は現在観測で取得距離内にあることを目標ラベルとする。署名を再観測した際は目標ラベルを更新するため、以前そこにあった食料が今も存在するとは決めつけない。ノード1,280、辺5,120まで（2026-10-25に従来の10倍へ拡張）。超過時は古いものを削除し、ノード削除に伴う辺も削除する。目標ラベルを持つノードは削除順位を後ろにする。

## 内部シミュレーション

Hがthreshold以上、直接の目標が見えない場合に検討する。reserve<=20またはstrain>=0.8なら追加探索しない。安全行動が選ばれているときはこの候補生成へ進まない。身体要求によってfood/homeが切り替われば、その時点の目的を使う。

最大4段・64展開、各ノードから最大8辺、待ち行列64、再探索間隔64tick。1日相当（既定17280tick）より古い辺と目標ラベルは探索に使わない。評価は歩数に相当する基礎コスト、観測したreserve消費、少ない経験の不確実性、過去の予測不一致を加算する。重みは試作上のヒューリスティックであり、生理的な意味を持たせていない。

到達経路が見つかれば最初の辺だけを通常の候補へ追加する。歩行は現在の実行可能方向の確認を通し、実行時の衝突・身体制約も維持する。scanは記憶した旋回量を使う。runの経験は記録できるが、現在の提案はwalk/scanのみ。選択を強制せず、目的達成の報酬を先払いしない。目的評価は既存の `target_observed` を使い、歩いたこと自体を目的達成としない。

選ばれた辺の予測と次の観測を照合し、不一致なら辺のコストを増やす。観測不足はunknownとして区別する。長い計画を実行中に固定保持するものではなく、最初の動作を提案する有限版。複数tickにわたる長考状態、思考そのものの身体消費、動的ρ切り替え、多階層MBの再構成は未実装。

## 設定経路との区別

身体維持の固定的な目的切り替えは `configured_paths/` に残る。本機構の辺は観測・行動から形成され、地図の内容や経由地点をテスト用に手で指定していない。ただし観測の符号化や探索予算・評価式は実装側の定義であり、これら自体が学習されたわけではない。

## 検証と現状

単体では観測A→B→Cを経験させ、Cへの2段経路からA→Bを提案できること、逆辺を作らないこと、予測不一致の評価低下、unknownの区別、低H・身体状態・再探索間隔・古い観測による抑止、記憶上限を検証。既存LWを組み合わせた600tick試験で実観測から遷移が形成された。

[狭い拠点の1日試験](../../experiments/rock_gate/mb_map_report.md)も完走したが、目的までつながる経路が見つからず提案0。**内部探索の実装は動いたが、実世界配置での経路改善はまだ確認できない。** 長考時間を増やすだけではなく、観測間のつながり・再認識・記憶容量と抽象化の不足を切り分ける必要がある。

保持容量のみを10倍に拡張した。最大4段・64展開・待ち行列64・各ノード8辺・再探索間隔64tick、および1日相当の鮮度条件は維持する。候補辺の走査対象が増えるため、実際のCPU時間が同じとは限らない。過去の1日試験は旧上限128/512での結果として保持する。
