# 設定経路・埋め込みMB・学習経路の区別

## 固定行動を追加・有効化するときの必須ルール（2026-11-03）

**固定行動は、事前に宣言し、設定経路として隔離する。**
動作を成立させるための補助でも、無言で通常の認知・判断へ追加しない。

1. 実装・実験前に、何を固定し、何を観測するために必要なのかをユーザーへ説明する。
2. 行動の決め打ち、目的切替、優先例外、強制待機などの処理は
   `src/lw/configured_paths/`へ置き、`configured_`接頭辞で識別する。
   呼出し側は接続に留め、固定判断をlearningや通常の選択処理へ隠さない。
3. 適用条件、上書き・重み付け等の介入内容、ON/OFF方法、既定値、
   設定・発動の記録先、撤去またはMBへの置換方針を対応文書へ記載する。
4. 実行前の条件一覧と保存条件に、有効な固定設定を掲載する。
   発動したことを追跡できる記録を残し、設定下の結果として評価する。
5. 固定設定で成立した行動を、自律学習・埋め込みMB・共通機構の成果と混同しない。
   汎用性は固定設定を外した場合や別の行動への適用で改めて検証する。

宣言は説明の義務であり、既に許可された作業への追加承認手続きではない。
世界側の衝突・資源保存・所有権や実験停止条件は、個体の固定行動と区別する。
実験用の地形・初期値は実験設定として分離し、すべてを行動関数へ移す必要はない。
既存実装には未分離箇所が残るため、今回の明記を全コードの対応完了宣言にしない。
未分離箇所に手を入れる際は、所在と役割を明記し、隔離を進める。

## 兎の授乳帰巣・幼体待機（2026-11-06）

`wildlife_reproduction.jl` の `configured_rabbit_nursing!`。
`scene.wildlife.reproduction=true` のときのみ有効（既定false）。幼体は離乳まで移動・採食せず、
母親は未授乳の仔の出生位置へ既存SEARCH移動で戻る。逃走・警戒と母体の栄養維持を優先する。
出生位置の直接保持、固定離乳日齢、日ごとの授乳時機は暫定設定で、MB学習ではない。
`wildlife.reproduction` 要約に出生・授乳回数・帰巣tick、各個体に親・生まれたtickを記録する。
将来は巣・子の認識と要求による共通の目的選択へ置換する。
季節・妊娠・乳変換など世界身体の定数は `RABBIT_LIFE`、計算の安全停止はそれらと区別する。

## 旧交換評価の互換隔離（2026-11-02）

`src/lw/configured_paths/legacy_trade_evaluation.jl`に、関係モデル無効時の旧Bool成否評価と、公開在庫観測がない旧実験の固定在庫仮定を隔離した。挙動は保存し、旧チェックポイント・比較実験を壊さない。現行の関係モデル有効時は`resolve_prediction!`で凍結した複合評価と実績を比較する。固定在庫仮定は公開在庫観測がない入力では今も使用されるため、撤去済みとは扱わない。

廃止した「不足がなければ交換禁止」「物の価値だけで成否を評価」は現役CIの期待値に戻さない。旧`necessity_checks.jl`は過去の呼出し用互換入口に限り、CIは`compound_trade_checks.jl`を直接実行する。過去の仕様はGit履歴で追跡できる。現行の味・必要量・援助係数などの初期値、日次開始上限、世界側の所有権・資源収支検査は別であり、今回削除しない。

2026-11-02：LWの自発的取引開始に、個体ごとに世界内1日1回の暫定上限を導入。食料専用・物を含む取引で共通の開始枠を使用する。世界が新規提案を受理した時点で消費し、その後拒否・期限切れでも戻さない。実行不能な提案は開始と数えない。承諾・拒否・逆提案は開始枠を使わず、枠使用済みでも応答可能。A→BとB→Aは各自の枠で開始できる。保存された個体のsocial状態内のtrade_daily_startで当日・使用数・累計を保持し、再開しても当日枠を復活させない。専用の設定行動シナリオはこの自発候補の制限とは別。交渉時間・注意の費用を導入するまでの設定経路であり、MBから自然発生した制限とは扱わない。

2026-10-25。GameAIにおける設計上の用語。ここでの「経路」は移動経路だけでなく、目的や行動を選ぶ判断の接続を含む。

| 区分 | 意味 | 将来の扱い |
| --- | --- | --- |
| 設定経路 | テストを成立させ、機構を切り分けて検証するため、外から便宜的に与えた固定の行動・選択処理 | 仮設。最終的には撤去し、これに依存せず動作することを目指す |
| 埋め込みMB | モデルの初期構造として持たせるMB | 設定経路とは別区分。テスト用固定処理をこの名前で恒久化しない |
| 学習経路 | 経験によって形成される判断・行動の接続 | 形成・評価・更新の対象 |

**設定経路は「埋め込みMBの別名」ではない。単に設定経路を学習可能にすれば完成、という位置づけでもない。** 将来はMB間の圧・選択・経験によって必要な振る舞いが生じ、テスト用の固定処理を外せる構造を目指す。

## 現在の具体例

### 日次の採取・帰還計画（2026-11-03）

[当日の親計画](LW_Daily_Provision_Plan.md)の「食料・拠点・一日」は、計画機構を
切り分けて検証する**局所観測用の固定設定**である。初期の選好・終了後の滞在・
見積もり初期値・再評価間隔も実験設定として明示する。
固定設定の下での成功を、目的の自律形成や他行動への汎用性の証明にしない。
経験からの段階構成、見積もり、親の費用保持、Hによる再検討、結果学習を
共通化の対象とし、加工・取引・援助などに日次帰還ルールを持ち込まない。
現行コードの完全な分離は未完了であり、learning側にある固定値も棚卸し対象とする。

[身体維持の上位目的処理](LW_Body_Parent_Purpose.md)では、身体維持を上位に置く階層の設計と、「空腹判定ならfoodへ」「reserveが80を超えたら保留していた帰還へ」という直書きの切り替えを分けて扱う。

後者、およびそのための定時休息・待機の解除は、現段階では**設定経路**である。parent名の接続や状態辞書を持つだけで、埋め込みMBや学習済みの上位選択が成立したとはみなさない。身体維持を上位に置く設計方針自体の撤去を意味するものではない。

既存の固定行動処理も、この区分で棚卸しする。ただし物理法則、身体の実行可能性制約、観測の仕様、テストの停止条件まで一律に「撤去する設定経路」とは扱わない。個別の役割を確認して区別する。全実装の分類・置換はまだ完了していない。

## 実験結果の扱い

設定経路を有効にして成立した行動は、その設定の下での結果として記録する。自律的な学習や埋め込みMBの効果として報告しない。有効/無効を明示し、撤去後に目的の切り替え・身体維持が成立するかを別途検証する。

この文書は区分と撤去方針を明記するもので、現時点で設定経路を削除する指示ではない。

川・世界端は最終衝突判定と局所方向候補だけで扱う。凹地形からの脱出保証はない。

## 2026-11-08 兎の任意渡河（暫定固定）

地域的な草不足から移動できる候補としてRabbitSwimmingPolicyを追加。通常OFF。既存RabbitApproachPolicyを包み、探索中・岸から6以内で64tickごと（個体ずらし）に検討する。空腹と局所Hで確率上昇、近傍の観測草量で低下。対岸の草量は参照しない。
川形状・着岸点の世界実状態参照は暫定固定。陸上速度0.2/水中0.1、消費0.012/0.036（各tick）。費用予測×1.5＋余力5を満たす場合のみ候補化。岸で授乳・逃避上書きがあれば中断、水中は着岸まで継続。障害物・境界は貫通せず、巣穴幼体は泳がない。流速・溺死・体温は未実装。将来は岸の観測・身体MBへ置換。
実装はsrc/lw/configured_paths/rabbit_swimming.jl。crossing_longrun.jl第9引数rabbit_swimming=trueで有効化。conditions.jsonに条件、日別にselected/arrived/swim_ticks/interrupted累計、個体記録に選択・到着を保存。途中の目的地・乱数をチェックポイントで継承。水中に取り残すためON保存状態からOFFへの切替は拒否。

## 捕食者の流入・流出（2026-11-09）
