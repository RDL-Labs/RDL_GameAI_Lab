# ρの選択による観測・思考・行動の共通化

作成日: 2026-10-23。状態: **設計仮説 / §5.1の固定ρによる局所移動を有限実装**。動的ρ選択・思考への共通化は未実装。

## 1. 中心となる見解

地形を見る、経験をまとめる、考える、行動候補を選ぶという操作を、**どの境界Bの下で、どのρで関係差を区別し、どの構造を使うか**という共通の問題として扱う。

岩一つずつを見る場合と岩壁として見る場合、木々を見る場合と森として見る場合、足元の模様を見る場合と道として見る場合では、利用できる規則性と局所近似が異なる。思考でも個別経験と抽象化された経験では、候補の構成と比較の仕方が異なる。この共通性を、専用規則を増やす前に設計上の軸として残す。

「ρは根本的性質を決める重要要素」という発想は、**個体にとって何が区別でき、何を構造として操作できるかを左右する重要要素**として採用する。世界の性質がρだけで決まる、という主張にはしない。

SILNの正式名称は **Survival-biased Integration of Local Linear Approximations in a Nonlinear Network**。観測者が見たまとまりだけを指す語ではなく、自己側の構造も対象になる。

「ρでSILNが変わる」は、まず**同じ対象でもB・ρ・条件により見いだせる構造と利用可能な局所近似が変わる**という意味で使う。観測の切り替え、内部モデルの再構成、行為による世界の変化は別の出来事として記録する。本案でρの重要性を強調しても、Coreの必須基底要素へ格上げしたことにはならない。

## 3. 規則性と局所近似

規則性のある関係は、適切なρでは少数の関係で保持・再利用できる可能性がある。ただし「圧縮しやすい」「予測が再現する」「目的達成に役立つ」は別々に評価する。整った形だから高報酬、とはしない。

| 対象 | まとまりとして扱う例 | 保持すべき例外・限界 |
| --- | --- | --- |
| 岩・壁 | 連続する障害の縁 | 出入口の隙間、遮蔽、身体が通れる幅 |
| 道・川 | 局所的な方向と連続性 | 分岐・途切れ・渡れる場所。道と川の行動上の性質は別 |
| 森 | 木々の領域と外縁 | 内部の通路・資源・危険。未観測の内部を埋めない |
| 左右の光源 | 対になった配置 | 二つの光だけでは入口・通行可能性を確定しない |
| 経験・思考 | 複数場面で再利用できる関係 | 適用条件、失敗例、元の経験に戻る手掛かり |

群としてまとめる処理は局所近似の候補を作る入口であり、それだけでSILNの採用まで完了しない。条件付きの予測や操作を試し、持続性と適用範囲を検査する。

「非線形をρに合わせて線形化する」は全体を線形とみなすことではない。壁沿いの短い範囲では方向を近似できても、角や出口ではその近似が破れる。B・ρ・有効範囲・観測時刻を伴う局所近似として保持する。抽象度と細かさも単一の上下関係に固定しない。

## 4. 相転移の認識

従来の局所近似が成立しなくなり、別の安定した関係が現れる変化を、構造の切り替わりとして検出する案を置く。ただし以下を分ける。

- 世界側の条件が変わり、同じB・ρでも応答が変わった。
- 世界側の条件は同じだが、B・ρを変えたことで別の構造が見えた。
- 履歴の蓄積や再構成によって、個体の解釈が変わった。

これらを全て物理的な相転移とは呼ばない。物理現象との対応は別途検証が必要であり、ここでは認識・モデル切り替えの設計上の類比として扱う。

## 5. 共通の選択ループ

**問いとBを定める → 有限なρ・解釈・方法の候補を作る → 比較する → 選ぶ → 結果を観測する → 履歴を更新する**。

| 適用先 | 選ぶもの | 検査する結果 |
| --- | --- | --- |
| 地形の観測 | 区別する特徴、角度・空間粒度などの有限profile | 通路や障害の違いが必要な精度で捉えられるか |
| 思考・記憶 | 個別経験、まとめた経験、適用条件の細かさ | 条件付き予測や候補比較が改善するか |
| 行動 | 問いに適した表現と実行方法 | 目的に進展があるか、負荷や危険が増えないか |

同じ選択規則を目指しても、全領域に同じ数値ρや同じセンサー処理を強制しない。Bの変更とB内のρ変更も記録上区別する。最初は固定した少数のprofileから始める。

現在のGameAIの確率的な方法選択を、将来のρ候補にも使えるか検討する。役立った候補が選ばれやすくなる結果として持続が生じる設計とし、前回選択したという理由だけで固定しない。切り替えコストも比較対象にする。確率式・報酬式はCoreの定義ではなくGameAI固有の実験条件である。

### 5.1. ρで捉えた近似地図からポテンシャルを構築する

外出改善の追記（2026-10-23）: 観測された障害の間の見通しを通路候補にし、現在の奥行き差・反発による観測log priorを上流の確率選択へ接続した。親Hによる温度は学習側に適用し、現在の視覚情報まで同時に消さない。`rho_openings=off`で切り離せる。出口の正解位置や前回方向による固定は使わない。[初回外出の検証](../../experiments/rock_gate/exit_opening_report.md)を参照。これは有限な観測評価の接続であり、ρ選択の学習や帰還の解決とは別。

実装追記（2026-10-23）: [rho_map.jl](../../src/lw/perception/rho_map.jl)に固定profile `coarse` / `fine` を追加。まず同じ観測点の連結距離を2.5 / 1.0に変える操作的ρとする。センサー解像度の増加ではない。近似地図を既存の構造記憶・地面経路候補にも渡し、選択済みの移動方向の周囲9候補をスカラーコストで比較する。これは上流の確率的な方法選択後の決定的な局所補正であり、場そのものから確率を学習する機構は未実装。比較用の既定値は `off`。詳細と検証は[導入レポート](../../experiments/julia_migration/lw_integrated/rho_map_report.md)を参照。

移動への具体化として、**観測 → B・ρに応じた近似地図 → 目的・身体状態に応じたポテンシャル場 → 行動候補の確率的選択 → 結果による更新**という流れを置く。これはGameAI側の設計案であり、Coreが規定する必須アルゴリズムではない。

近似地図は世界の完全な地図ではなく、個体が有限に観測・保持した関係の表現とする。位置だけでなく、まとまり・連続性・隙間・未知領域・観測の確かさと時刻を持たせる。局所的な表現から始め、世界側の正解座標や未観測の接続関係を個体へ渡さない。

| 地図上の関係 | ポテンシャルへの寄与の候補 |
| --- | --- |
| 壁・障害・危険 | 身体の幅や状態、危険度に応じた反発 |
| 目的に関係する場所 | 目的と現在の必要性に応じた引力 |
| 道・連続した縁 | 観測された範囲で、その方向に沿って進みやすい勾配 |
| 未知領域 | 探索目的と危険の不確実性に応じた評価。通行可能とは確定しない |

**ρは地図で区別できる関係を変え、目的・身体状態はその関係上の勾配を変える**、という役割分担を基本にする。同じ地図でも探索中・帰還中・疲労時で勾配は変わる。ρによって壁や隙間の表現が変われば、そこから構築する場も変わる。これらの変更を別々に記録し、どちらが結果に寄与したか比較できるようにする。

ポテンシャルは候補の評価に使い、勾配が最も良い一方向へ常に固定するとは限らない。既存の確率的選択・成功履歴・失敗履歴との接続を検討する。場の合成式、各寄与の重み、確率への変換は未確定であり、ポテンシャル値をCoreのEやHと同一視しない。

進展がなければ、方向や方法の選び直しに加えて、**ρを変えた再解釈・追加観測・近似地図の更新**も候補にする。例えば「連続した岩壁」という表現で出口が見つからない場合、必要な範囲を細かく観測し、入口の隙間を区別する。ただし、元の観測にない隙間を細分化だけで作り出さない。局所的な谷や往復に陥る可能性は残るため、ρ変更だけで脱出できるとは保証しない。

成功は場の値が下がったことや移動量だけでなく、探索・帰還など元の目的への進展で検査する。検証では、同一地図で目的・状態だけを変える条件と、目的・状態を固定してρだけを変える条件を分ける。狭い入口の保持、障害との余裕、停滞、誤った接続、計算量を比較する。移動で成立した後に、思考上の候補間の関係にも同じ構成を適用できるか調べる。

## 6. H・報酬・失敗

移動できただけでは探索・帰還の目的を解決したことにならない。同様に、粗いρに変えて問題が見えなくなっただけではHを解消したことにならない。Hは候補やρの再検討を促す材料にできるが、高ρなら必ずHが増えるとは仮定しない。

比較では更新前のM_Bと比較条件を固定し、F/F′、E、Hの由来を残す。途中でρを変えるなら別の比較として扱い、異なるρのHを無条件に加算・大小比較しない。元の問いの達成を独立に検査し、比較不能と未解決も保存する。

高いHの解消に大きな報酬を与え、失敗のHを別履歴として選択に反映する既存GameAI案を接続候補にする。Eを全て失敗扱いしたり、未観測を失敗にしたりしない。目的に無関係な反復で報酬を稼げないことも検査する。実装上のHという名前だけでCoreへの完全適合を主張しない。

## 8. Juliaでの検証順序

1. 同一の凍結観測に二つの有限ρを適用し、まとまり・隙間・未知の保持を比較する。元観測にない詳細を再解釈だけで復元せず、追加取得と区別する。
2. 岩壁・狭い入口・道の分岐を使い、固定ρ同士で目的達成率と計算量を比較する。規則的な形に加え、途切れや例外も含める。
3. 有限予算内でρ選択を追加し、固定ρ条件と比較する。見落とし、切り替え回数、停滞、Hの由来を保存する。
4. 同じ選択インターフェースを経験の抽象化へ適用できるか検査する。地形で成功しただけで思考への一般化を確定しない。

指標は目的達成・所要時間・CPU時間・割当メモリ・見逃し・誤った連結・切り替えコスト。複数seedで比較し、個体の実行順や共有資源の競合条件を揃える。入口を粗い表現で消す、未観測の道をつなぐ、Hが見えなくなったことを成功扱いする場合は設計を見直す。

[ρ活用指南](RDL_GameAI_ρ活用指南.md)と[Core参照メモ](../semantic-reference/RDL_Core_T0_T1_reference.md)も併読する。中心はρを常に上げることではなく、**問いに対してどの区別が有効かを選び、その結果を検査する仕組みの共通化**である。
