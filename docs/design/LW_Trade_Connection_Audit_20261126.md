# 通常LWと取引・コミュニケーションの接続監査

2026-11-26。調査基準 f8834a9。実装変更なし。
香り・用途差取引30日試験は、ユーザー指示で23日目末保存後、24日目途中に停止した。
今回の目的は取引件数を増やすことではなく、欲求から観測・提示・実行・学習までの接続を確認すること。

## 結論

通常LWは一つの統一取引系にはなっていない。食品専用、物品・食品混合、援助、
言語実験の経路が分かれ、観測可能な情報と評価基準が異なる。
今回の用途差評価は混合取引にだけ接続されている。
倉庫非公開時に必要な「欲しい物を尋ね、返答で提供可能品を知る」経路は、
今回の通常LWランナーには接続されていない。

したがって、提示ゼロを欲求の欠如や閾値の厳しさだけで説明できない。
まず経路間の契約を揃える。非公開在庫を直接読む、提示を強制する、評価閾値だけ緩める、
という修正は今回の結論ではない。

## 実測と静的確認を分ける

[18日目の再実行](../../experiments/social_relationships/TRADE_ABSENCE18_AUDIT.md)では、
混合取引の実評価320回、相手あり202回。候補試行8,868回のうち、
等価結果5,968回、非正の主観差2,900回で、採用可能な候補がなかった。
候補試行数は数量違い・重複照合を含み、独立した取引機会数ではない。

評価時点4例のコピー比較では、実在庫を診断用に公開すると3例で食品要求の提示が出た。
閾値だけ緩めた比較では、利益-0.002の一方的な塩提供も再出現した。
相手の受諾と実移転はこの比較では実行していない。

`observed_food_candidate_count` は未観測を候補数量0へ落とす。
`open_stores=false` では全在庫は観測されず、受信提示等が候補の入口となる。
未知を「本当に持っていない」と学習しているという主張ではなく、
問い合わせ経路がない今回の構成では候補生成へ進めない、という問題。

ここまでの計測は18日目であり、停止した23日間の全判断を監査したものではない。
今回追加した全体確認はコードの接続・条件・評価経路の静的調査。

## 評価の不統一と現モデルの範囲

- 新用途差モデルは、今ある食品・塩・現在利用可能な設備から得られる「次の一食」の最大価値差。
  将来魚を得るための塩備蓄、複数段の調達、設備までの移動は評価しない。
- 混合取引では認識済み塩の従来の単体価値を除き、用途差へ置き換える。
  食品専用・要求品目選択・視覚援助には同じ置換が入っていない。
- 混合の用途差ONでは主観差<=0を棄却。OFFの旧方式は<-0.01。
  食品専用にも旧評価・閾値が残る。フォールバックにより統一評価を迂回し得る。
- 視覚援助は共通の保持費用を利用するが、提供品は手持ち先頭または最初の可食在庫。
  品目間の用途比較で選ぶ仕組みではない。交換の成立条件とも区別する。
- 観測された語句の学習と、発話の自律生成は同一ではない。実験には設定表現・文法・待機が残る。
  世界の宛先IDがあることを人物の視認・認識が完了した証拠にしない。

## 実行・学習・記録

物品世界と食品取引世界はそれぞれ所有・在庫・実行可否・receiptを管理する。
この層の収支、二重適用防止、受諾時の再検証は保持対象であり、
個体の主観判断へ寄せて外してよい制約ではない。
混合取引は選択時の評価モデルを保持し、実際の移転差を照合する。
援助の到達、交渉の成立、欲求の解消、将来の関係投資は別の成果として扱う。

既存の勾配ログは有限の候補・記録数しか保持せず、生成前の除外理由が不足する。
「未評価／観測なし／相手なし／未知の品目数量／非正の差／見送り／提示／実行不能」を
段階別の軽いカウンタで分けると、提示ゼロを事後再実行なしで説明しやすい。

## 次の順序

1. 通常LWの取引入口を一本のディスパッチへ整理する設計を決める。
   食品専用の役割・互換用途を明示し、混合見送り後の別評価を意図せず使わない。
2. 本人のMBから欲しい物・不足する用途を呼び出し、非公開の相手へ問い合わせる。
   返答で知った提供可能品・数量だけを候補へ渡す。呼びかけ・認識・交渉を通常側で明示接続する。
3. 要求品目選択、提示、応答、結果照合に、同じ状態変化の見積もりを渡す。
   同じ評価式にすることと、援助・取引の目的を同一にすることは分ける。
4. 局所で「提供可能／在庫なし／知らない／返答なし／条件不一致／受諾後在庫変化」を確認。
   正当な見送りを許し、成立数を強制しない。その後に短期→長期実験。

今回は停止・監査・文書化のみ。新規の行動変更、30日再起動、追加の完全回帰検査はしていない。
前回の用途差専用検査32項目と物品基礎検査253項目は既報結果。
既存counter_checksには変更前にも出る確率分布条件の失敗があり、全検査成功とは扱わない。
