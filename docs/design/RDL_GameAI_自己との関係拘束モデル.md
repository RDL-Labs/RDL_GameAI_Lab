# RDL_GameAI — 自己との関係拘束モデル

**状態:** DESIGN ONLY / DRAFT v0.2、2026-09-27。実装・受入試験は未実施。

**基準:** GameAI `772725f4`（L10B）。Coreの意味基準は[semantic reference](../semantic-reference/RDL_Core_T0_T1_reference.md)。

**責務:** 自己と対象の関係を、有限な関係拘束として記述し、文脈依存の解釈・予測・選択へ接続するための設計枠。

**対象:** 人・道具・物・場所・概念・共同体。以下はGameAI側の仮説と記録案であり、Core Primitiveや実在社会の普遍則ではない。

関連: [感情・履歴・関係拘束](RDL_GameAI_感情・履歴・関係拘束モデル.md)、
[神経設計](RDL_GameAI_神経パラメーター設計図.md)、[Layer計画](RDL_GameAI_NPC_レイヤー別設計計画.md)、
[L10B契約](../experiment-contracts/LUANTI_L10B_multi_agent_learning_contract.md)。

## 1. 使うときの問い

> **この対象との関係によって、今の自分の何が可能になり、何が維持され、何が変わると見込まれるか。**

「好き」「自分に近い」「自分の物」という名称だけで行動を決めず、その見え方を生む具体的な関係を残す。
関係拘束には、行為を制限する作用と、その関係があることで行為を可能にする作用の両方がある。

| 対象 | 記述する関係の例 | 関係が変化した際の問い |
| --- | --- | --- |
| 人 | 協力を得られる、返却を期待する、相手の無事を共同生活の前提とする | 協力が得られないと何ができなくなるか |
| 道具 | 操作を習得している、作業に必要な出力・フィードバックを得られる | 故障・不在でどの方法が使えなくなるか |
| 物・資源 | 継続利用を見込む、共有する、維持を引き受ける | 消費・移動で誰の予定や備えが変わるか |
| 場所 | 休息できる、帰還できる、他者と合流できる | 利用不能なら回復・帰還の見通しがどう変わるか |
| 概念 | 判断や協働の共通条件として使用する | 適用できない状況で何を見直す必要があるか |
| 共同体 | 資源利用、保護、役割、相互支援を期待する | どの条件でその期待が成立・失効するか |

対象種別に共通の記録枠を使っても、作用機構を同一視しない。人には別個の判断、道具には性能・
操作条件があり、共同体には参加者間の異なる認識や媒介がある。すべてを同じ行動関数にする設計ではない。

## 2. 三つの状態を分ける

| 区分 | 内容 | 更新する契機 |
| --- | --- | --- |
| 保持された関係 | 経験に基づく予測、依存、利用条件、相互期待など。適用条件・出典を持つ | 新しい経験、検査、明示された採用・改訂 |
| 現在の効き方 | 今の問い・観測・身体条件のもとで、その関係がどこへ作用するか | 現在入力の変化。保持関係を毎回書き換える必要はない |
| 要約表現 | 距離、重み、親密さ、所有らしさ、帰属など | 上二つから用途を固定して読み出す |

「自己との距離」と「重み」は、同じ作用を一軸で表し、対応規則を固定するなら代替表現としてよい。
近いほど重く扱うという表現のために、独立した二つの更新変数を作らない。
一方、資源利用、保全、協力、警戒などの異なる作用を一本の数値へ潰すことは要求しない。
関係は方向付き・条件付きであり、AからBとBからAの一致、三角不等式、固定順位は仮定しない。
距離を幾何学的metricとして使う場合は、別途その条件を定める。

強い関係拘束は好意だけを意味しない。脅威への警戒も選択を強く拘束し得る。
強度、作用先、期待する結果、成立条件を分けておけば、この違いを残せる。

## 3. 「自己境界」の意味

ここでの自己境界は、対象の状態・利用・維持を、どこまで自己に関わる条件として扱っているかを
記述するGameAI側の表現とする。Coreの有限境界 `B` は問い・観測・記述・操作の選択枠であり、
この自己関与の強さそのものではない。

自己に関わる対象が増えても、その対象の内部状態を取得できるようにはならない。
他個体の `F`、意図、経験、M_Bを直接コピーせず、観測可能な行動・発話・結果などを、自分のM_Bで解釈する。
相手を自分並みに重く扱う関係と、相手も同じ希望を持つという予測は別に記録する。

道具との結合では、World側の能力・取得・出力条件が変わり、それが後続する有限作用断面へ現れる。
道具オブジェクトをそのままFへ投入しない。実際に使えるかという身体側条件と、使えるという学習済み予測を照合可能にする。

## 4. 所有・親密さを関係として扱う

所有は初版の単一scalarにせず、対象・利用者・相手・条件を含む関係の束として検討する。
「Aと物」の二者関係だけでは、「AはCにこの道具を貸すが、返却を期待する」を表し切れない。

| 観点 | 残す内容の例 |
| --- | --- |
| 継続利用 | 次も使えるという予測、その用途と期限 |
| 利用条件 | 自分／相手／共同利用者に何を認め、何を期待するか |
| 返却・交換 | 誰が、何を、いつ、どの条件で返す・渡すという予測か |
| 維持・保全 | 誰の作業・負担・予定が対象の維持へ結び付くか |
| 喪失の影響 | 使えなくなった場合に、本人のどの行為・備えが変わるか |
| 相互認識 | 相手も同じ条件を認識しているという根拠、食い違った記録 |

Worldの所持・占有・操作可能性、NPCの利用権に関する信念、他者からの承認は別々に扱う。
ある物を動かせた事実だけで所有を確定せず、他者の同意や承認も観測なしに補完しない。
借りた道具への習熟と、持っているが使えない道具を区別できることが望ましい。
ここで扱うのは有限な実験内の関係であり、現実の法的所有権を判定するモデルではない。

家族・親友・赤の他人という勾配は、共有・責任・期待・相互支援等の違いとして現れ得る。
ラベル自体から固定順位を割り当てず、同じ相手に対する協力と警戒が共存することも許す。
相手の保全を重く扱うことと、相手の行動を自分が決められると期待することは異なる関係拘束である。

例として、同じFoodの取得が「取り分を失った」「共同の備えを使った」「後に融通を受けられる」と
異なって解釈されることを検査する。いずれかを正解として事前に全個体へ配布するものではない。

## 5. 文脈依存と、持続的な学習を分離する

外国で同じ国の人に出会う例は、共通関係の効き方が状況で変わる設計仮説として使う。
国内では選択差を生みにくかった共通条件が、慣れない場所での説明・援助要請では手掛かりとなり得る。

```text
保持した関係 + 現在の問い・状況
→ 共通の言葉や事情を頼れそう、という条件付き予測
→ 接近・相談などの候補
→ 実際の応答を観測
→ 本人の新しいExperience
→ 検査を経て、持続する関係を採用・改訂する候補
```

同じ国という認識があっても、言語理解・協力意思・信頼を自動成立させない。
所属や共通条件は取得元と確かめた範囲を持つ。聞いただけの情報や推測を、Worldの完全情報へ昇格させない。

最初の段階は状況依存の読み出しであり、それだけで永続的な信頼やM_B全体を書き換えない。
助けられた／断られた経験が残る更新と、同じ保持関係が別状況で強く作用する変化を、別々に検査する。

## 6. 共同体・村・国家への拡張

共同体は、共有・役割・相互期待・保護などの関係拘束が持続するまとまりとして扱う候補である。
村規模では共同作業や直接の履歴、国家規模では制度・言語・交換手段等を介した関係が検査対象になり得る。
規模が違っても同じ作用機構だとは決めず、何が関係を媒介・維持しているかを明示する。

家族、村、職業集団、国家等の境界は重なり得る。何の資源・責任・活動を問うかで作用する集合が変わり、
本人が認識する所属と、相手から認められる所属も食い違い得る。
共通の集団IDだけから信頼、全経験の共有、同じM_Bを推定しない。

集団を一つのSILNとして観測する場合は、個体とは別のPurpose / B / 取得範囲を設定する。
個体の値を足し合わせただけで国家や村の意思が得られるとは扱わない。
この節は将来参照であり、初回実験に家族・村・国家システムの実装を要求しない。

## 7. M_Bへつなぐ位置

```text
World / 他個体 / 道具との相互作用
→ 本人が取得した有限観測・直接参加の結果・出典付き伝達
→ Purpose / B / coverageを明示したRIB_B
→ 現在のM_Bによる解釈・予測
→ 有限な候補と、別途許可された行動
→ 後続の観測を同じ更新前M_Bで解釈
→ 比較可能な次元についてF/F'を比較

本人の受理済みExperience
→ 関係候補の形成・独立検査・選別
→ 契約されたT1経路によるM_Bへの明示採用・切替
→ 次の状況での解釈・予測・選択差
```

具体的な神経・身体・履歴由来の関係は、明示採用された範囲でM_Bを構成し得る。
新しい関係storeを作るだけでM_Bへ自動採用せず、M_Bの外側の近さスコアだけで推論を代用しない。
一つの比較ではモデルと比較条件を固定し、別Purpose・別model・比較不能を混ぜない。

関係の強さ、好意、損失、心理負荷を直接 `E/H` へ変換しない。
Eは比較条件を満たす解釈・予測間の不整合、Hは有限assessment後の未解消部分として扱う。
不明な所属、対象参照の欠落、比較不能を数値0・反例・拒絶へ変換しない。

現在のL10Bは、個体別経験からの有限な感覚relation採用と行動差までを検証済み。
ここに記した所有・親密さ・共同体の意味論や神経由来の動的重み付けは未接続である。

## 8. 実装契約へ渡す最小記録案

以下はフィールドの責務案であり、既存schema・API・enumの追加ではない。
具体的な型、数値尺度、上限、保持期限は最初の実験契約で固定する。

| 記録群 | 必要な内容 |
| --- | --- |
| 本人と範囲 | run / epoch / holder_agent、relation ID、Purpose / boundary参照 |
| 関係の参加役割 | 自己、相手、資源、受益者、共同利用者等の必要な役割。複数参加者を表現可能にする |
| 参照の根拠 | 各対象を何から識別したか。観測上の参照、発話の話者、実験用登録の区別 |
| 成立条件 | 用途・文脈・時点・利用可能性・適用範囲。known / unknownを区別する |
| 具体的な拘束 | 何を可能・困難にするか、何を予測・期待するか。作用先と方向 |
| 経験の出典 | 形成／独立検査のExperience・event ID、反例、未試行・未完了、変換規則と版 |
| 採用状態 | local候補か採用済みか、T1記録・model参照、失効・改訂の根拠 |
| 現在の適用記録 | 入力snapshot、凍結model、適用条件の判定、根拠となったrelation、予測・理由 |
| 要約表示 | 必要な場合だけ距離／重み。問い・尺度・導出規則・元のrelation参照 |

保持関係と現在の適用結果は別記録にする。文脈による効き方が変わってもraw Experienceを上書きしない。
不明な対象をWorld内部IDや隠れた所属情報で埋めない。遠景特徴や音検出から個体同定が未成立なら、
その参照を特定NPCへの親密さや信頼へ直接接続しない。

適用結果では「条件を満たして作用する」「条件を満たさないことが分かる」「情報不足で判断できない」を分ける。
行動側では、それとは別に現在の実行可能性・許可・期限・操作IDを照合する。関係が強いことは実行権限ではない。

単一数値への要約を採用する場合は、その数値が比較する作用・尺度・未知の扱いを先に定める。
本書は距離から重みへの特定の式、親密度の初期値、家族等の順位を指定しない。

### 記入例: 借りた道具による作業

以下は**合成の説明例**であり、実在する受付記録・API payloadではない。

| 項目 | 記入内容 |
| --- | --- |
| 保持する本人 | A |
| 問い | 指定作業を、道具Xを借りて行える見込みがあるか |
| 参加役割 | 利用者A、貸し手B、道具X。参照は過去の明示貸出と利用観測から得たものとする |
| 関係1 | 条件cでXを操作した作業が成立したという、本人の利用経験からの候補 |
| 関係2 | Bが指定期間にXを貸し、返却を受けたという、別の関係候補 |
| 出典 | 各関係の形成用と検査用で異なるExperience・eventを列挙。同eventが複数関係の根拠でも票は増やさない。Bの内心や所有の正解は入力しない |
| 現在の条件α | 今回の貸出が確認でき、Xの利用可能性・作業条件cを確認できる |
| 現在の条件β | 今回Bが貸すかは未確認。過去の貸出経験は同じ |
| 読み出し | αでは検査済み関係の適用を検討できる。βでは貸出条件が不明なままとし、拒絶とは数えない |
| その後 | 実行許可と有限操作を別途照合。実行した場合だけ本人の結果を記録する |

Xの利用能力と、Bとの利用条件を別々に検査することで、「親しいから借りられるはず」「借りられるなら
使いこなせるはず」という未検査の接続を見つけられる。α/βの違いだけでは保持関係を更新しない。

## 9. 有限比較実験の案

**すべて予定・未実施。** まず局所診断で解釈・予測差を確認し、行動へ接続する場合は別契約で権限を限定する。

| 比較 | 固定するもの／変えるもの | 観測すること |
| --- | --- | --- |
| 文脈だけの差 | 同じ保持関係・M_B・問い・身体／現在の状況や支援の必要性だけ変更 | 適用される関係と予測が変わる一方、保持記録は不変 |
| 履歴だけの差 | 同じ現在条件・選択規則／独立した過去経験だけ変更 | どの関係が候補・採用状態へ残り、予測差が生じるか |
| 借用と習熟 | 利用条件・操作経験・実能力を個別に変更 | 所有の信念、使える予測、実結果を混同しない |
| 相互認識の不一致 | 同じ資源／Aは共同利用を期待、Bは返却を期待する材料 | 各個体の予測と実応答を残し、片方の見方で相手を上書きしない |
| 複数作用の共存 | 同じ相手／協力の根拠と警戒の根拠を併存 | 一つの好感度で打ち消さず、問い別に作用を追えるか |
| 情報不足・失効 | 同じ問い／対象参照、出典、鮮度等を欠落させる | 判断不能を敵意・不在・失敗に変換しない |
| 名称への依存 | 具体的な取得条件と関係を固定／表示用の「家族・親友」等だけ変更 | 表示ラベルだけで予測・選択を変えない |
| 集団の重なり | 資源利用と作業協力など二つの問い／重なる所属を明示 | 問いごとの関係が作用し、集団IDだけで全条件を共有しない |

初回候補は **A/B・一つの共同利用対象・二つの文脈**までの小さな比較とする。
対象・相手の参照を何から得るか、形成と検査をどう分離するか、各record・問い合わせ・身体作用の上限と
失効条件を契約化してから実装する。家族・国籍等のタグを先に追加することは必須ではない。

成功条件は「必ず仲良くなる」「候補が一つになる」「所有が正しく判定される」ではなく、
何の根拠で解釈・予測・選択が変わったか、変わらなかったか、判断できなかったかを追跡できること。
次の状態は分けて保存する。

- 観測・参照が不十分で検査できない。
- 関係の適用条件を満たさない。
- 実行可能だが選択しなかった。
- 試したが予測した応答が得られなかった。
- 予測した応答が得られたが、成立範囲はその有限条件に留まる。

同eventの再送、別名の同Experience、再評価を支持回数へ加算しない。
単体の比較成功を、複数個体のWorld行動や社会制度の成立を検証したものとは扱わない。

## 10. 境界への接近・侵犯と、関係を維持する反応

以下はGameAIの設計仮説である。接近から怒り・恐怖へ直結する固定表を、生物一般の法則として置かない。
ここでの接近は、空間距離だけでなく、身体・資源利用・休息・共同活動などへ影響が及び得ることを含む。

```text
有限観測で得た相手の接近・操作
→ 現在のM_Bで、何の利用・維持・安全が変わりそうかを予測
→ その変化を許容する条件、情報不足、本人の対処可能性を検査
→ 注視・確認・警告・防衛・退避などの有限候補
→ 許可された身体操作と後続観測
```

相手を外側と認識していても、接近した事実だけで敵意や侵犯を確定しない。
親しい相手でも、共同利用は認めるが無断持出しは認めない、といった条件差を残す。
相手への協力と、特定の行為への警戒は同時に成立し得る。

維持・回復できると見込む関係への妨害が、防衛や抗議に結び付く場合を「怒りらしい」、
守り切れない損失を予測して回避・退避する場合を「恐怖らしい」と観察する仮説を置ける。
両者は排他的な状態ではなく、実際の侵犯前にも予測から現れ得る。記録の中心は感情名ではなく、
何を変化・喪失と解釈し、どの対処を可能と予測したかである。生物の感情を同定したとは扱わない。

縄張りを持つ動物を参考にしたfixtureでは、巣・採食場所・休息場所の利用関係を個別に調べられる。
土地全体の防衛、確保した資源の防衛、仲間の保全は、同じ関係や機構であるとは仮定しない。
例えば環境省の[ヒグマの解説](https://policies.env.go.jp/park/shiretoko/rausu-vc/guidetour/caution/)は、
食物への執着や取った物を取り返そうとした際の反撃を説明する一方、排他的な縄張りを持たないとする。
この記述は、人間と同じ所有概念や、特定の神経物質による機構を証明するものではない。

設計上は「取得・利用経験 → 利用できる資源という関係 → 喪失の予測 → 維持する選択」を検査候補とする。
取得前後で同じ他者の接近への予測が変わるか、その出典が本人の経験と採用済みM_Bまで追えるかを見る。
所有タグや相手の正解意図をWorldから配布して、その変化を学習と呼ばない。

## 11. 生物特性・現在状態・学習された関係

「DNA的な癖の設定」は、GameAI内では学習に先立つ構成・基準条件という設計上の対応物とする。
実在のDNA、遺伝、発達過程を再現したという意味ではない。神経値の具体的な意味と分布は
[神経設計](RDL_GameAI_神経パラメーター設計図.md)で扱い、本書で新たな値や作用式を確定しない。

| 区分 | 設計で与える／観測する内容 | 更新・比較の境界 |
| --- | --- | --- |
| 生得的な構成・基準 | 感覚チャンネル、身体構造、可能な操作、必要量、感度・保持・選別の基準条件 | 比較run内で固定。生物名や性格名から行動を直接選ばない |
| 現在の身体・神経状態 | 空腹、負傷、疲労、現在の反応しやすさ等 | 時点・出典を持つ変動。基準条件や過去経験の上書きとは分ける |
| 学習された関係 | 自分が利用・協働できた条件、妨害や喪失の経験、反例 | 有限経験から形成・検査し、契約された経路で採用・改訂する |

この三つは第2節の「保持・現在適用・要約」とは別の整理軸であり、M_Bを三つの排他的なfieldに分解しない。
現在状態が関係の効き方を変える作用と、経験の保持・次の再構成へ影響する作用を別に検査する。
OXT等の操作的ラベルを、好感度・敵認定・境界侵犯への怒りと一対一に結び付けない。
神経状態と関係解釈の相互作用は将来仮説であり、今回の会話から因果規則を確定しない。

```text
構成・基準条件 + 現在状態
→ 取得できる有限断面と、実行できる相互作用の条件
→ 本人のExperienceと、保持・検査される関係の違い
→ 明示採用されたM_Bによる解釈・予測
→ 選択・身体作用・後続観測
```

個体差の比較では、共通の構成上で感度や保持・選別傾向等を変える有限実験から始められる。
犬と人ほど異なる生物を扱う将来設計では、数値だけでなく感覚・身体・操作の構成も設定対象となる。
同じ初期構成でも経験による差を許す。これは共通のRDL枠で異なる生物らしい挙動を検査する構想であり、
特定の生物種を再現できることを確認した結果ではない。

SILNとしては、問い・有限境界・取得条件のもとで、どの関係に対しどんな作用パターンが現れるかを比較する。
似た防衛・執着・親和が現れても、内部機構や守っている関係が同一だとは推定しない。
生得条件・現在状態・経験履歴を分けて変え、入力、採用関係、予測、実行結果の対応を残す。

**この構想の実装は保留する。** Observation v1やL10Bの完了条件へ後付けせず、既存の学習経路を使う
[本線の有限実験](../../notes/experiment-roadmap.md#post-l10b-shared-resource-learning)へ戻る。

## 12. 参照元と今回の停止点

今回の会話で整理した中心は、自己との関係を共通の記述枠とし、所有・親密さ・共同体・道具習熟を
そこから検査することである。v0.2では境界反応と、生物特性・現在状態・学習関係の分離を追記した。
