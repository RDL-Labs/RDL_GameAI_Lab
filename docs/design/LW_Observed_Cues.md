# 観測特徴を目印候補にする有限実装

2026-10-25。Julia LW の `general_landmarks=on` で有効化（既定 off）。

色と輪郭、上方の輪郭、光、観測された地面のまとまり、食料の外観、動く対象、特徴同士の相対配置を共通の候補にする。塔の色 ochre も通常の色観測に含める。World の物体 ID や未観測の座標は候補生成へ渡さない。

H は候補の採用範囲を広げる。今回の threshold=2 では次の段階となる。

| H | 検討する候補 |
| --- | --- |
| 0–1 | 現在の観測で比較的区別しやすい色・輪郭・光 |
| 2–3 | 同色が複数ある、部分観測、広がった形、弱い光、地面なども追加 |
| 4以上 | 動く対象や特徴の相対配置も追加 |

段階は識別しやすさの固定的なヒューリスティックであり、学習済みの信頼度ではない。H が上がっても不確実性は消さない。選択自体は既存の確率的 BasicLoop に渡す。単に歩いたことは目的達成にならず、`target_observed` で評価する。既存の H に基づく評価・報酬を使用する。

地面・動く対象・相対配置は観察のみ。その他は近すぎず実行可能な移動方向がある場合に接近候補を作る。目標を直接観測している場合や安全処理の優先は維持する。観察候補の向きを既存の一般 scan 処理で上書きしない。

1観測の候補は重複除去後96件まで、選択記録は個体ごとに最新32件まで。キーは特徴の記述と相対方位の区分であり、世界内の対象を追跡する ID ではない。姿勢が変わっても同じ対象を認定する仕組みや、すべての種類の特徴を使った永続的な経路記憶は未実装。音・社会的観測もこのアダプタの対象外。ρ の動的な選択も今回の変更には含めない。

統計 `tower_observations` は ochre を候補として観測した回数で、塔の個体識別成功数ではない。`offered` / `selected` は段階0,1,2の順。対象が見えていないときの候補生成を集計するため、全センサー観測回数とは異なる。

再現コマンド:

```powershell
julia --startup-file=no --project=. experiments/rock_gate/run.jl outputs/food-roads-general-cues-3d-20261025 --narrow-only --days 3 --rho coarse --rho-openings on --food-roads on --general-landmarks on
```

結果は [実験レポート](../../experiments/rock_gate/general_cues_report.md) に記録する。

## Hに応じた生成の省略（2026-10-25追記）

候補を全生成してから絞る処理を、現在のHから段階を指定して生成する処理へ変更した。段階0では地面・食料外観候補を展開せず、段階2未満では動く対象と相対配置の計算を省く。色・輪郭は段階判定にグループ化が必要なため、その観測処理は維持する。センサー、安全判断、既存の他の候補群の遅延生成は対象外。身体への「思考エネルギー消費」は追加していない。

`generation_levels` は実行時に指定した段階別の呼び出し回数、`generated` は生成された重複除去後の候補数。`tower_observations` は今後、現在の段階で生成された候補内のochre観測数となる。上限96を超える観測では生成前フィルタによって従来の切り捨てとの違いが生じうるため、一般的な全入力の同値性は主張しない。
