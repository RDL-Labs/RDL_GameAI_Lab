# MBの勾配地図の記録

2026-10-31。自然言語による理由生成ではなく、社会行動を選んだときの局所的な候補評価と、想起された関係MBの構造化記録を残す。実装は `decision/gradient_trace.jl`。

## 対象と構造

表情からの自発的援助、要求へのgive/refuse、食料のみ取引、物を含む取引・逆提案へ接続。選択時点の候補の基礎重み、学習済み報酬、失敗反発、方法Hによる減点、温度、候補数補正、実際の確率、選択候補を保持する。援助・物交換では基礎重みの成分も記録する。関係の重み、照合したMB ID・一致度等・予測確率、観測した外見、自分の食料見積もりを一緒に凍結する。

全MBをコピーする地図ではなく、今回の判断で活性化した関係と候補の局所地図。キー・方法名・IDは実装上の記号であり、個体が文章を生成・理解する機構ではない。相手の非公開在庫・身体値は加えない。

要求応答は実行可能性によってgive確率が0になる場合があるため、候補のfeasibleと実際の確率を併記する。数式上の重みだけから実際の選択を誤読しない。提供された確率を使用した記録にはprobabilities_suppliedを付ける。

## 当時の評価と結果を分離

選択時の情報はdeepcopyし、その後のMB学習・在庫変化で書き換わらない。outcomesへ実行結果を追記する。提示はofferedであって交換成立ではなく、相手の応答通知が来てから交換・拒否・期限切れ等を対応付ける。援助のtransferredは食料受渡であり、相手の回復を証明しない。自発的援助の中断も記録する。

現在は受動的記録のみ。ログを参照する再探索・反実仮想・睡眠時の再評価は未接続。将来その再評価を加える場合も、当時の地図を上書きせず、別の評価を紐付ける。

## 負荷と保持範囲

- 個体ごとに直近64判断。evictedに除外数を残す。
- 判断ごとに確率上位15候補＋選択候補、最大16件。候補総数と省略確率量を保持する。選択確率を保存対象だけで再正規化しない。
- 結果は判断ごとに直近4状態。重複通知は同一内容なら追加しない。
- 元記録が既に保持範囲外なら、後から理由を作らずunmatched_resultsへ計上する。
- 関係状態の一部としてsummary/result・日次チェックポイントへ保存。完全な全判断履歴ではない。

scene.gradient_loggingは既定true、falseで記録を無効にできる。記録用の乱数を使わず、選択・学習の入力にも戻さない。ON/OFFの統合検査では、ログ関連キー以外の全結果が一致することを確認する。

## 検証

gradient_checks.jl：確率と省略量、低順位の選択候補保持、入力・H更新後の凍結、結果追記・重複排除、保持上限、ログON/OFFでの全結果一致、実際の受渡への結果接続、日次保存からの再開一致。食料・物交換の既存検査も回帰対象にする。
