# 人側共通選択：各MB自身の見込み差H

2026-11-23。通常ソースへの初回接続。長期試験は未実施。

## 共通処理

`BasicLoop` の既定 `h_mode=:forecast_difference` では親H・decision_Hによる温度上昇を使わない。
選択点は「現在評価 + log1p(学習報酬) − 候補自身のH / 既存threshold + 観測log prior」。
温度は1。候補自身のHはMethodNode、または明示的なforecast_Hから受け取る。
旧failure_H_totalは記録に残すが、同じ差を二重減点しないため新方式の選択点には重ねない。
H減点の旧上限2は外す。確率の数値安定化（指数の下限−600）は従来どおり。
非確率選択でも自身のHを減点する。旧「全候補が未解決なら最も古い候補」はlegacyのみ。

`forecast_difference.jl` は各MB固有の累積見込み・累積観測を持ち、
H=max(0,累積見込み−累積観測−許容幅) を計算する。
親へ子Hを渡さない。親子で同じ出来事を評価しても、それぞれ自分の尺度・見込みを使う。
取引の損失を表せるように符号付き観測を許容する。上振れは台帳に残る。
小さな差を毎回切り捨てず、累積差へ許容幅を適用する。

`resolve_method!` は method_forecast / goal_forecast に `(見込み増分, 観測増分)` を受け取る。
Boolの成功でHをゼロにしたり、失敗で1を足したりしない。
見込み・観測が供給されない対象はH更新を保留する。未観測と観測済みゼロは異なる。
このため未移行の呼出しに架空の見込みを補ってはいない。

## 接続した経路

- 釣りを含むacquisition：方法・場所のそれぞれに台帳を保持。活動時間を既存の固定見積もり時間で割った見込み増分と、観測した取得成果を照合する。これは現在利用可能な粗い成果尺度のアダプターであり、整数の魚目標をMB共通部に固定しない。
- 方法の未解消差がある間は、場所変更や一回の取得で方法の見込み・差を消さない。場所も同じ型で評価する。報告済み経過と成果を試行に記録し、publish/終了時の重複を避ける。
- 取引：通常の食品・物品取引が使うresolve_prediction!を接続。選択時の主観評価を使い、成立だけでは以前の差を消さない。親の見込み・観測は別引数を許容する。既定は同じ交換を親の取引目的も評価する。
- 通常dayの親残差受領：既存の親自身の見積もり由来の増分だけを共通台帳へ渡す。子経路のH増分を親へ転送する経路は新モードでは外す。

## 移行範囲と注意

- 全ての個別H生成器の移行ではない。到着モードのsaved_H復元、経路固有H、身体不安、援助専用状態などの独立実装は残る。
- 通常dayの方法側はBool評価だけの場合、Hを更新しない。親側の既存増分アダプターには成果による差の縮小を渡す処理が未接続。釣り・取引以外まで移行完了と扱わない。
- 親Hを上位の候補へ投影するには、そのMBを表す候補へ自身のHを渡す必要がある。全階層の候補構造を今回自動生成していない。
- acquisitionの既存log反発・方法反発・不安係数は残す。二階層の自律選択モデルを新設したわけではない。
- 地上捕食者の生成・継承・追跡・局所狩猟はh_mode=:legacyを明示し、従来挙動を維持。兎の独立選択は変更しない。
- BasicLoopにmodeと台帳フィールドを追加したため、古いJuliaバイナリ保存状態の新ソース復元は保証しない。旧実験は凍結ソースで再現し、新方式は初期状態から開始する。新方式同士のSerialization・RNG一致とJSONスナップショットを局所検査する。
- 実行中の長期実験・凍結ソースは書き換えていない。

## 検証

`experiments/local_relational_observer/human_forecast_h_checks.jl` は通常LWモジュールを読み込む。
見込み・成果の試験入力は人工的だが、共通選択・釣りacquisition・取引評価アダプターは本体コード。
親Hだけ変えても子分布が変わらないこと、候補Hの減点、捕獲後の残差、場所変更、
双方の主観差、成立時の不足・損失、未観測、二重適用、保存復元を検査する。

既存のacquisition_checksとfood_exchange/policy_checksは、旧成功ゼロ・失敗Boolの期待を
今回の差の台帳に合わせて更新。他の資源収支・原子的交換・保存条件は維持。
長期の行動安定性や性能改善はこの局所検査からは判断しない。
