# 睡眠時の類似関係圧縮：第一段階

2026-10-28。探索で作った `exploration_relations.links` が対象。睡眠完了時に、一般のMB記憶整理より先に実行する。探索関係機能が無効なら何もしない。場面1280件の表、MBノード・辺・成功経路は今回圧縮しない。

## 統合の材料

同じ目印ラベルについて、出発場面と、両方で得られている場合の後続場面を、共通の `mb_similarity` と個体の学習済み距離・角度重みで比較する。共通特徴2以上、両場面に対する特徴被覆率80%以上を要求する。単一色だけの一致ではまとめない。

保存近似の類似度許容値は `(1+exp(-angle_weight))/2-.02`。現行の30度刻みで、二特徴のうち一つの角度が隣接帯へずれる程度を許す初期値。学習済み角度重みが変わっても、固定の0.65を同じ角度許容幅と見なさない。認識の正解判定・帰還成功判定ではなく、保存情報をまとめるための近似基準である。係数の妥当性は未確定。

さらに、拠点からの強度・予測強度の差0.1以内、接近・到達らしさの差0.2以内、支持率の差0.15以内とする。home/foodの観測タグが違う場面、後続場面が未知の記録と既知の記録は混ぜない。直前の行動結果待ちの関係はその回の圧縮対象にしない。

これは既存情報だけを使った保守的な基準。統合可能と判定しても、世界の同じ物体・場所だと証明したわけではない。

## 保存形式と再利用

代表の出発場面・予測値を残し、支持・矛盾・失敗・選択回数を合算する。代表は既存の大きいまとまりを優先し、同数ならキー順。幾何と予測の平均値を次の統合の中心にして、少しずつ遠い記録まで吸い込む方式にはしない。

統合した元キーの全リストや永続的な別名表は保存しない。追加するのは圧縮済み関係の `represented`（何件をまとめたか）と、個体ごとの最終処理日・累積統合数だけ。同日の二重処理を防ぐ。通常の認識は共通の類似照合なので、代表以外に似た観測も候補へ寄与できる。

翌日の新しい経験が別キーで追加されることは許す。次の睡眠で再度比較する。差が出たときに新しい記録を残せる一方、統合した過去の個別記録を完全復元・自動分割する機能はない。既存の直近64件の診断記録には統合前キーが残ることがあり、現在のリンク表への有効参照とは限らない。

目標報酬・親H・移動の辺・逆向き経路は作らない。代表だけになるため候補順位・行動は変わり得る。完全同値は主張しない。

## 検証

`mb_relation_compression_checks.jl`：前提96項目＋専用16項目、計112項目PASS。統合・経験量の保存・同日の重複防止・代表を介した想起、違う特徴/強度/後続観測の分離、保留中の保護、未観測の保留、学習済み角度尺度を検査。

`probe_relation_compression.jl`：90日終了時の保存結果を読み、メモリ上のコピーで一回整理。元ファイル・checkpointは変更しない。関係の証拠量・代表件数、MBノード/辺/chunkの不変、報酬不変を検査（3個体×5項目）。
