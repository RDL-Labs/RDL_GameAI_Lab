# 移動を手段として評価する局所変更

基本基準は「そのMB自身の事前の見積もりと観測結果との差」。
共通方針の [評価の基本](RDL_Common_Relational_Policy.md) に従い、目的達成、Hの解放、効率報酬を分離する。
慣れて差が減っても、学習した低い時間・消耗の見積もりは手段を選ぶ根拠として残す。

移動の局所予測成功はH残差の更新に使い、歩けたこと自体へ基礎報酬を払わない。
LWのfood/home親目的が成立した時点で、開始時に固定した見積もりと実績の時間・消耗を比較する。
既存のmb_completion_rewardのadvantageを使い、max(0, advantage)だけを方法・経路・チャンクへの報酬として渡す。
達成の基礎報酬とH解放量はこの効率報酬に加えない。H解放そのものは別に維持する。
時間短縮と消耗増加は既存の等重み平均で相殺する。各尺度と許容帯0.1も既存設定を維持。

同じgoal/source/evaluated_usの達成記録だけを利用する。未到達・中断・別目的・古い記録には支払わない。
直近の異なる方法に対する既存の信用配分方式は維持しており、因果的に寄与を証明するものではない。
見積もり学習は既存の完了時更新を維持。現状の候補には所要操作数の費用項があるが、
道を含む全経路の消耗を最適に比較する実装の完成とは扱わない。
取引のresolve_prediction!、採取成果のacquisition_result!、legacy動物評価は対象外。
一般のresolve_method! APIには明示completion_rewardなしのH解放報酬互換経路が残るが、
LWの親達成接続は明示の効率報酬（0も含む）を渡す。
