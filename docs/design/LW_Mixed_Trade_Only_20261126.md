# 通常LWの食品専用取引経路を撤去

2026-11-26。04f083dから変更。[接続監査](LW_Trade_Connection_Audit_20261126.md)に続く整理。

通常LWの食品専用コントローラ生成、毎tickの専用観測、混合見送り後の専用判断、
専用取引実行、日末の専用集計を撤去した。食品だけの交換も `item_offer` /
`item_accept` の食品数量欄を使い、物品・食品混合と同じ経路で実行する。
混合で見送っても別評価器へ落ちない。援助は目的が異なるため残す。

`decision/food_exchange.jl` には現在も使う食品評価・観測ヘルパーを残し、
旧コントローラは `configured_paths/legacy_food_trade.jl` へ隔離した。
歴史的な局所検査用に関数定義は読み込むが、通常LWからは生成・更新・選択しない。
旧 `trade_offer` 等の行動を外部から渡した場合はエラーとし、新経路へ暗黙変換しない。

## 設定・保存の扱い

- 通常取引は `incidental_items=true`、`item_exchange=true`、物品世界とBasicLoopが必要。
  食品だけなら `loose_items=[]` でも物品世界を作れる。食品は個人別のtyped_foodを使う。
- 古い `food_exchange=true` は、新経路も有効な入力では互換宣言として許す。
  食品専用のみを要求する入力は `food_exchange_requires_mixed_item_exchange` で停止。
  勝手に物品拾い等を有効化する設定変換は行わない。
- チェックポイントの `trades` 枠は形式維持のためnothingで保存する。
  復元後に非nothingなら停止する。旧進行中交渉を捨てて黙って続けない。
  元のソースハッシュ検査も維持。過去の再現は保存した凍結ソースで行う。
- 新規結果ではトップレベル／dailyの `food_exchange` 集計を作らない。
  `world_checkpoint.food_exchange` は互換上nullで残る。
  現行の取引は `portable_items` と `incidental_items` の結果を読む。
- 言語実験とAPI実験の文字列挿入位置を、新しい混合観測位置に対応させた。
  古い凍結ソースを使う実験の挿入位置も認識する。API呼出しは検証に使わない。

今回は呼びかけの通常LW接続、用途評価の拡張、固定の開始条件や回数制限の変更は含まない。
倉庫非公開時に未知の食品を問い合わせる入口は、引き続き次の作業。
今回の撤去だけで提示が増えるとは予測しない。30日実験は停止したまま。

## 検証

`experiments/social_relationships/mixed_trade_route_checks.jl`:
旧状態生成をエラーに置換して通常LWを短い2日周期で実行する。
旧フラグON/OFFの結果、日次保存再開、専用状態・集計の不生成を確認する。
食品だけの実移転と資源収支も混合世界で検査する。
これは16秒/日の接続検査で、生活の長期挙動の検証ではない。

既存 `trade_use_connection_test.jl` で、用途差判断・受諾・実移転後評価も再検査する。

実行結果（Windows / Julia 1.13.1 / 1スレッド）:

- 新経路・復元14項目、食品のみの混合移転5項目、合計19 PASS。
  旧状態を含む保存ファイルを渡した場合の明示停止も確認。
- 用途差32項目、同時に読み込む物品基礎253項目、計285 PASS。
- 言語・API接続スクリプトの構文確認。外部APIの実行・言語長期試験は未実施。
- 旧コントローラの移動前後の関数本体一致、CIカタログの参照先存在、diff検査を確認。

新接続検査は手動機能別CIのportableへ追加。常時CIの範囲は増やしていない。
速度比較・長期生存・取引頻度の改善は今回の検査からは主張しない。
