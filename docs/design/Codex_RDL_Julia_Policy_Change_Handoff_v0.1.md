# Codexへの引継ぎ — 完全同値・コピー必須方針の見直し

2026-10-12 / v0.1  
詳細: `RDL_GameAI_Julia_Behavioral_Fidelity_Policy_v0.1.md`（リポ配置案: `docs/design/RDL_Julia_Behavioral_Fidelity_Policy.md`）

## 今回の方針変更

旧Python／旧Juliaとの完全同値を、今後の採用条件にしない。初期移植の一致確認は有用だったが、旧実装は正解そのものではない。

ユーザーは、同一性を全値・全動作列の一致ではなく「らしさ」として扱い、完全保持が重いなら外す方針を指定した。経験・現在条件・未解消に応じた関係応答が残り、実用的な費用で動くことを優先する。

## 次の局所実験で行うこと

1. `pressure_update`周辺の新規根拠0件／1件の経路を第一候補にする。毎回の全状態`deepcopy`と、変更可能な別状態を必ず返す契約を外す小さな実装を試す。その場更新を認め、必要な呼出し側も調整する。
2. 通常更新と、独立した写しを要求する`snapshot`を分ける。新規0件で元状態を維持してもよい。古い所有検査を通すためだけに全コピーを復活させない。
3. 全履歴保存も必須ではない。要約・保持窓・忘却を試せる。ただし初回から全部を足さず、API変更と記憶近似による挙動変更は可能な範囲で分ける。
4. 完全動作列・H中間値・JSONの一致は診断用にする。切替が3回から2回へ変わっただけで失敗にしない。短い対照で、経験の効果、未解消への応答、現在条件への接続を見る。
5. 同環境で新規0件／1件の時間・累積割当・参照件数を測る。増分通知やsnapshotへ費用を移した場合も、その使用分を評価する。保持量・RSSを測っていなければ改善したと主張しない。
6. 変更した契約、失う情報、残る関係応答、旧版との差、費用、未検証範囲を報告する。完全一致が維持できないことだけを理由に停止しない。

## 残す小さな境界

宣言したWorldの実行条件・資源収支、個体間の意図しない状態混線、重複適用、取得していない情報の混入は確認する。これを全履歴永久保存や、全状態不変性の要求へ戻さない。

本変更はGameAIの系設計であり、T0改訂ではない。局所H・選択の近似をcanonical E/H/T1の完成と呼ばない。canonical比較を実行する箇所だけは、その比較に必要な更新前M_B・条件を保持する。全Worldや全過去版のコピーは不要。

## テストと停止位置

旧完全一致・所有テストは旧版の診断として隔離、または新契約へ置換してよい。何を守る検査へ変えたかを短く残し、無関係なテストは緩めない。過去の結果報告は書き換えない。

変更中は関連試験と短い代表ケースを中心にし、毎修正で長期・全系列の実行を必須にしない。第一回は小さな新経路と評価報告までとし、大規模DSL・基盤構築・全面移行を先行させない。報告は「採用候補／要調整／不採用／未判定」と理由で十分。

参照基準は直前確認済みの`cd65ce510a3fbe66c582bd1b031f3d47f2d7eaa7`。実装開始時のHEAD・既存変更を確認して適用する。旧64件履歴の新規0件更新は約0.360425 ms・累積462,224 bytesだったが、別環境でその値が再現するとは限らない。

**目標は旧版を凍結することではなく、必要な「らしさ」を残しながら、試行錯誤を回せる軽さへ進むこと。**
