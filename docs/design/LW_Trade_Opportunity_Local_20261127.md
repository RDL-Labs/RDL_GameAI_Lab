# 回数上限を外す取引機会の局所試験

開始HEAD: 005333e。通常のLW全日実験には未接続。局所fixtureで
`configured_trade_opportunity_enable!(incidental_state)` を呼ぶ場合のみ有効。
状態キーがない従来実行・凍結ソース・保存状態は変更しない。

## 暫定設定と評価範囲

有効個体は呼びかけのlast_day制限、共通のtrade_daily_start制限を外す。
進行中の呼びかけ・交渉との競合排除は残す。買う／売るの本人の複合勾配を使い、
初期成立見込み0.5、呼びかけ費用0.25（勾配単位）の暫定近似で評価する。
`priority = benefit * probability - H - effort`。
試行後の見込みは `(成立件数 + 0.5)/(試行件数 + 1)`。
失敗では開始時に固定した期待成果をHへ加算し、対応する試行の成立でそのHを解放する。
身体や別の目的のHを消さない。成功の実際の栄養量・交渉費用まで計測するモデルではない。

正の候補とholdを既存の確率選択へ渡す。正の候補がなければholdだけとなる。
holdでready_homeを立て、局所のhouseアダプターから既存の自宅移動・到着後休息へつなぐ。
別の用事・高い身体要求・未決交渉は帰宅停止を妨げる。
一日ごとのHリセット、回数上限に代わる固定クールダウンは追加しない。
毎回の本人の勾配が変われば再評価される。現在は買う／売ると品目の単位で蓄積するため、
相手別・提示条件別への一般化、新しい相手の到来での再評価、通常LWの自宅からの起動条件は今後。

無返答の期限切れ・拒否は不成立として更新する。無返答を相手の在庫なしとは記録しない。
相手の呼びかけへ応答して自分の呼びかけを取り下げた場合は中断であり、
その後の別取引の成功・失敗を元の試行へ加算しない。結果の二重適用も防ぐ。

固定ショートカットは configured_paths/trade_opportunity.jl に隔離。
将来は成功見込み・手間・成果を共通MBの経験予測へ置換する。
私有在庫の覗き見は行わない。生魚が売却候補に入らない既存条件や、
腐敗前の自己消費容量の見積もりは今回変更していない。

既存呼びかけ110項目に加え、回数制限解除・無返答・拒否・中断・二重終了防止・
品目別H・利益増加時の再検討・自宅移動／休息・保存復元を検査する。
同日２回の呼びかけを確認。不成立後の同じ要求は開始せず帰宅準備へ進む。
成立通知の一部はfixtureによる注入で、長期生活下での取引率を示すものではない。
通常の取引実行・所有権移転は既存camp_trade_callsとcamp_surplus_local検査で確認する。
