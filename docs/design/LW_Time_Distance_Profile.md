# LW：距離・時間・身体消耗の暫定尺度

状態：human_scale_v1 実装、有限区間で接続確認。旧legacyを再現用に維持。
基準9ab5e9e、2026-10-07。

## 換算

水平距離1 World m = 人間の生活圏10m、World 1秒 = 人間時間5秒。
通常歩行0.5m/操作、身体操作1秒という既存値を維持する。名目歩行速度は人間換算1m/秒。
観測待ちや旋回があるため実際の平均速度はこれより低い。
高さ・身体寸法・荷物の値は従来の能力判定単位であり、一律10倍の人体モデルとはしない。
この換算は実験尺度であり、生理学的な人間再現を主張しない。

| phase | World時刻 | 人間換算の長さ |
|---|---|---|
| 方位確認 | 0〜60秒 | 5分 |
| 探索・現地休憩等 | 60〜8640秒 | 11時間55分 |
| 帰還枠 | 8640〜11520秒 | 4時間 |
| 夜間 | 11520〜17280秒 | 8時間 |

一日17280秒。探索枠は連続歩行の義務ではなく、既存の休憩・食事・危険・社会判断を含む。
夜間後半4時間相当は既存の社会処理より通常休息を優先する。
Sleep検査に必要な確認済み休息はWorld2880秒＝人間4時間。単なる時刻経過では加算しない。

## 消耗と世界時計

reserveの基礎代謝/移動/乗り越え/失敗/休息費用を旧値の1/270へ統一。
基礎代謝だけなら一日16 reserveを維持。食料1単位の回復20、初期reserve A30/B90/C90は維持。
予想消耗と実消耗は同じlayered_body.stepを参照。実行可能性のreserve閾値も同倍率。
strain蓄積/回復はともに旧値の1/60。地面抵抗と荷重の倍率は維持。
burst消費/回復・damage・歩行速度・旋回処理は従来通り。この疲労係数は暫定設計値。
旋回の消耗は今回追加していない。食料消費は既存の空腹判定による。

資源再生の日数、道の回復待ち1日と一日2 wear回復、日別帰還/Sleep/方位/経路の区切りを同じDAY_USへ接続。
短い通信期限・1秒の身体作用・250msの観測枠・認知的反復の操作数は日数とは別なので引き延ばさない。
旧の固定64秒を前提とする過去専用auditは新プロファイルへ流用せず、manifest対応の統合auditを使う。

## 実行と互換性

プロセス起動時にRDL_LW_TIME_PROFILEを固定し、途中で切り替えない。
既定環境はlegacy。新しい実験は専用launcherを使う。manifestへ換算・境界・係数を保存する。
身体ruleもlayered-body-human-scale-v1として区別。異なる時間profileのcheckpoint復元を拒否する。

`python -m integrations.lightweight.scaled_base_campaign --window-seconds 180`

は新尺度で有限180秒（人間15分）だけ動かす。window_limitであり一日完走やSleep完了とは扱わない。
`--full-day`で17280秒を実行できるが、この変更では未実行。実時間の早回し/高速化は別課題。
日数増加に伴う記録・台帳容量と長時間性能は、まだ実機運転で受け入れていない。
