# 目的との関係が強い観測対象を選ぶ比較案

2026-10-28。実装済みの実験用選択肢。30日比較の結果は未判定。

`scene.mb_navigation_mode` の既定は `explicit_join`。`goal_cues` を指定すると、覚醒探索の明示的な合流子目的を生成せず、現在見える形状目印の通常候補へ目的との関係を反映する。成功経路chunkの直接想起、睡眠経路、通常の目的への探索、局所修正、H、身体の設定経路は維持する。

## 関係の材料

目的達成経験のある同目的chunkから、接続が残る各途中地点と残り経路を取り出す。これは既存の経路記憶の索引であり、合流地点への到達を別目的として設定しない。現在観測との対応は共通の `mb_correspondences` で求め、Hに応じた検索幅、幾何学的な似かより、過去の対応付け経験を使う。

現在見えるshape候補の色ラベルが記憶場面にもあるとき、次の積を関係の強さとする。

- 共通照合の重みの2倍（既存の事前support 0.5を基準にする）。
- 成功chunkの深さ / (1 + 残り経路の推定費用)。
- 記憶場面で、その特徴へ向かう方向と成功した歩行方向の整合度。
- 現在の特徴方向と、照合から予測した歩行方向の整合度。

方向の整合度は `exp(-abs(angle_difference)/45)`。候補ごとに最大の根拠を使い、同じ特徴が多くの経路にあるだけで票を増やさない。通常候補の優先度へ `log1p(strength)` を加える。45度などの係数は実験用で、自然法則の主張ではない。単なる拠点との同時出現ではなく、その方向への行動が目的へつながった経験を使う。

新しい行動候補や強制移動は追加しない。近すぎる目印、移動不可能な方向、見えていない特徴は従来の候補生成に従う。通常の方法評価はそのまま受け、経路の成功・矛盾・実行失敗がchunkの深さを変えると、関係の重みも変わる。目印を選んだだけでは成功報酬を与えない。

## 費用・診断・限界

索引は目的別に64 World秒ごと、または目的達成によるchunk credit更新時に再構築する。記憶の鮮度制限ではなく計算用キャッシュである。使用時にも消去済みのchunk・辺を確認する。実際の深さは現在値を用いるが、索引の代表選択・費用は次回更新まで遅れる。

`mb_map[actor].goal_cues` に重みを付けた候補数、選択数、目的別選択数、直近64選択の根拠を保存する。試験runnerでは日末に選択累計を記録する。候補に関係が付いていることは、その加点が選択を変えたという因果証明ではない。

特徴は現行MBの色・距離帯・角度による場面記述であり、物体の真のIDや世界座標ではない。同色の別物への誤認はあり得る。今回はshapeの歩行候補が対象で、光・地表・他者への一般化や、任意の関係の多段伝播は未実装。場面照合に共通特徴がない場合は寄与しない。

目的への関係を完全に新規学習するモデルを追加したのではなく、既存成功経路の関係を既存目印候補へ投影した最初の比較である。
