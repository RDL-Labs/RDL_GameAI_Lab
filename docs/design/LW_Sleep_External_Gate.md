# 睡眠中の外界入力停止（2026-11-04）

scene.sleep_external_gate（既定true、falseで旧動作）で睡眠中の外界観測を停止する。
初期の入眠・起床規則はconfigured_paths/sleep_gate.jlに隔離：夜にrestがperformedとなった次tickから入眠し、翌日の開始で起床する。これは当面の固定スケジュールであり、自律的な睡眠相選択や途中覚醒のモデルではない。日中の休息は入眠と扱わない。2026-11-11改修：拠点と観測した場所での休息だけに適用する。拠点外の休息では朝までの固定遮断へ移行せず、通常の観測・選択を続ける。音・危険・空腹による途中覚醒は未実装。

睡眠個体は観測前にthinking_idsから除外し、視覚、地形、目印、他者・食料観測、通常の候補生成・学習用外界記録を行わない。睡眠の成立後も朝まで停止を維持する。日末・最終出力時の暗黙のobserve/ingestも睡眠個体では省略する。朝には新しい観測を取得する。

身体のrest更新、代謝・消化、世界の資源・他個体の時間進行は続く。睡眠個体が他者から見えなくなる仕様ではない。入眠時に観測した拠点内外の判定を保持し、睡眠中に拠点座標を再観測しない。既存の睡眠圧更新は身体の休息として継続する。

内部の睡眠処理は共通のprocess_sleep!へ分離し、覚醒側の入眠tickと睡眠専用tickの双方から呼ぶ。入眠時に既存経験を凍結し、連続休息が成立した際の一般記憶整理、MB圧縮・経路見直し、関係記憶整理等は従来のcallbackを実行する。通常の外界観測を通して睡眠処理を起動する必要はなくなった。

学習状態learning[actor].sleep.external_gateに入眠時刻、日、外界遮断tick数、入眠時の拠点認識を保存する。日末snapshotとチェックポイントにも含まれる。events.method/configured_rule=sleep_external_gateで睡眠専用処理を識別する。朝は日付不一致によりゲート対象外となり、既存の日次sleep状態初期化へ進む。

検査：sleep_gate_checks.jlで入眠・朝の解除・睡眠成立後も入力停止・内部callback一度のみを確認。統合試験outputs/sleep-gate-two-days-20261104は同一21日目の状態から22〜23日を実行し、二夜の睡眠成立、睡眠中の通常行動なし、翌日の活動再開、全tickの身体行動数、食料保存を確認する。

検証完了：単体8項目、二夜＋翌日再開の統合38項目PASS。4体とも22・23日目の睡眠成立と遮断、23日目の歩行・見回し・採取のいずれかの活動再開を確認。30日長期と同条件の性能比較は未実施。

## 将来案：不安・安全経験に応じた遮断度と途中覚醒

2026-11-04の考察。未実装の設計案であり、生物学的機序を確認した記述ではない。現行の夜間入眠・朝起床ルールは変更しない。

睡眠中の外界遮断を一律のON/OFFだけでなく、不安に応じて変える。慣れた拠点では遮断度が高く、見知らぬ外では低い状態を想定する。ただし場所名や拠点フラグだけで固定せず、その場所との関係MBにある「安全に休めた経験」と、現在の危険・食料不足などの予測を不安の材料にする。拠点でも危険な経験があれば遮断が弱まり、外でも安全経験が蓄積すれば深く遮断できる方向を検討する。

区別して設計する要素：
- 刺激検出の感度：どの程度の変化を拾うか。
- 確認頻度：粗い外界確認をどの間隔で行うか。
- 覚醒条件：拾った刺激や内部の不安を受け、いつ通常の観測・行動へ戻るか。

不安が低ければ確認間隔を長くし、弱い刺激では覚醒しにくくする。不安が高ければ確認を増やし、小さな変化にも反応しやすくする。気になる刺激を拾った際にはρを上げて確認し、必要に応じて覚醒する、という段階的な接続案とする。感度・ρ・覚醒を同じ変数の別名にしない。

計算量の面では、浅い睡眠でも毎tickの視覚・地形・候補探索一式を復活させず、まず粗い刺激検出を用いる。低コストの入力経路で何を観測できるかは別途設計が必要。未観測の危険を正解情報として不安へ直接入れない。

不安から各要素への写像、食料不安と危険予測の統合、刺激の種類、途中覚醒後の再入眠条件、睡眠中断時の記憶整理の扱いは未決定。実装時には、観測コスト・途中覚醒・睡眠成立・生存への影響を分けて検証する。
