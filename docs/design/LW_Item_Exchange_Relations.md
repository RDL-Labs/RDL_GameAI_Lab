# 交換経験による物同士の関係

2026-10-30。物の直接的な好みとは別に「これを渡すと、あれを得られた」という経験を、個体の予測へ接続する。

## 記録と更新

`incidental_items[actor].exchange_relations` に、相手・渡した束・受け取った束・必要度・成立数・拒否数を保持する。物の束は観測した色・大きさ・発光量と個数、食料は提示された種類別数量。世界の物体ID、他者の非公開倉庫、他者の評価値を記憶特徴に使わない。IDは現在の操作対象を束縛するためにだけ使用する。

提案時に特徴を固定し、実際の成立通知後に更新する。成立時は両者がそれぞれ自分から見た向きで記録する。拒否・逆提案による条件の置換は、その具体的条件への不成立経験。送信、期限切れ、物理的実行不能だけでは成立・拒否を学習しない。既存の試行解決と通知処理が重複更新を防ぐ。

最大128関係。上限時は成立実績のない古い記録から整理する。保持上限、必要度の記録区分、他者への一般化係数などは初版の実装パラメーターであり、自然法則ではない。

## 呼び出し先

1. **次の提案**：成功した束の特徴から、現在所有する物と相手の見える物に再対応付けして候補にする。食料を対価に求めた経験も再提案できる。候補は保有資源と主観的損得の検査を通す。
2. **成立予測**：束の類似度、相手、現在の必要度で経験を重み付けし、相手との社会関係による事前予測を更新する。他の相手には弱く一般化する。同じ色などの完全一致だけを採用条件にしない。Hは既存の想起予算を通じて呼び出す関係数に作用する。
3. **拾得・保有評価**：単品の物を渡して得た物・食料の直接価値から、一段先の交換可能性を推定する。現在の自己の食料在庫・味・必要度を使い、成立頻度と拒否経験で割り引く。直接的な興味と交換可能性は加算せず最大を用いる。拾得側では、新奇性が薄れても交換の用途が残り得る。

交換可能性の予測に、受け取る物のさらなる交換価値を再帰投入しない。往復交換による価値の自己増殖を避ける。複数物・食料を添えた支払いは束として記録・再提案できるが、利益全体を各構成物へ重複帰属させないため、初版の単品保有価値には展開しない。

拾った際の評価は「交換に使えそうな物を取得した」という予測上の用途であり、将来の交換成立や食料取得を世界側に計上するものではない。直接的な好みと交換用途を含む選択時の評価は試行中固定し、途中で学習が更新されても成否比較の基準をすり替えない。

## 範囲と制約

- 全員共通の相場や交換の強制ではない。似た物の誤認も起こり得る。
- 交換候補は既存の拠点内・接触範囲に限る。遠方の相手へ会いに行く計画や、多段の交換経路は未接続。
- 食料のみの既存交換系は別系統。今回の関係記憶は物を含む交換のみに接続。
- 観測した物を記録するため、非公開の他者倉庫の物は候補にできない。
- 保存・日次チェックポイントに含む。`exchange_recalled_choices` は成立経験が照合された選択回数。因果的にその経験だけで選択が変わった回数ではない。
- `experiments/portable_items/exchange_memory_checks.jl` の事前経験は検査用。通常の3日試験は未経験から開始し、固定交換は使わない。
