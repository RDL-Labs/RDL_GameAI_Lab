# 交換経験による物同士の関係

2026-10-30。物の直接的な好みとは別に「これを渡すと、あれを得られた」という経験を、個体の予測へ接続する。

## 記録と更新

`incidental_items[actor].exchange_relations` に、相手・渡した束・受け取った束・必要度・成立数・拒否数を保持する。物の束は観測した色・大きさ・発光量と個数、食料は提示された種類別数量。世界の物体ID、他者の非公開倉庫、他者の評価値を記憶特徴に使わない。IDは現在の操作対象を束縛するためにだけ使用する。

提案時に特徴を固定し、実際の成立通知後に更新する。成立時は両者がそれぞれ自分から見た向きで記録する。拒否・逆提案による条件の置換は、その具体的条件への不成立経験。送信、期限切れ、物理的実行不能だけでは成立・拒否を学習しない。既存の試行解決と通知処理が重複更新を防ぐ。

最大128関係。上限時は成立実績のない古い記録から整理する。各関係に直近32件の数量観測と、累積成立・拒否数、数量への応答モデルを保持する。保持上限、他者への一般化係数などは初版の実装パラメーターであり、自然法則ではない。

## 呼び出し先

1. **次の提案**：成功した束の特徴から、現在所有する物と相手の見える物に再対応付けして候補にする。食料を対価に求めた経験も再提案できる。候補は保有資源と主観的損得の検査を通す。
2. **成立予測**：束の類似度、相手、現在の必要度で経験を重み付けし、相手との社会関係による事前予測を更新する。他の相手には弱く一般化する。同じ色などの完全一致だけを採用条件にしない。Hは既存の想起予算を通じて呼び出す関係数に作用する。
3. **拾得・保有評価**：単品の物を渡して得た物・食料の直接価値から、一段先の交換可能性を推定する。現在の自己の食料在庫・味・必要度を使い、成立頻度と拒否経験で割り引く。直接的な興味と交換可能性は加算せず最大を用いる。拾得側では、新奇性が薄れても交換の用途が残り得る。

交換可能性の予測に、受け取る物のさらなる交換価値を再帰投入しない。往復交換による価値の自己増殖を避ける。複数物・食料を添えた支払いは束として記録・再提案できるが、利益全体を各構成物へ重複帰属させないため、初版の単品保有価値には展開しない。

拾った際の評価は「交換に使えそうな物を取得した」という予測上の用途であり、将来の交換成立や食料取得を世界側に計上するものではない。直接的な好みと交換用途を含む選択時の評価は試行中固定し、途中で学習が更新されても成否比較の基準をすり替えない。

## 数量で変わる勾配と移動との共通化

2026-10-30追記。設計の基準は[移動・交換を共通の関係勾配として扱う](RDL_Common_Relational_Policy.md)。交換条件の局所変更を、移動方向の局所変更と同じ予測・選択・更新の流れで扱う。

以前の実装（`6271e0e`）は数量を記憶キーに含み、数量差を照合上の不一致としていた。現在は次のように変更した。

### 関係と数量を分ける

関係キーは相手、両側の観測特徴の集合、食料種類の有無で作る。重複個数や具体的な食料数量、必要度の区分はキーから外した。想起は特徴の類似度・相手・必要度で重み付けする。同種の物1個と2個、同じ食料1個と3個は、数量だけを理由に照合を弱めない。種類の追加や対価なしへの変更は関係の構成自体が変わるため、別の候補にもなる。

量は、渡す物の個数と食料4種、受け取る物の個数と食料4種の計10変数で表す。対数変換した数量から、個体側のロジスティックモデルが相手の応答を予測する。渡す量の増加が有利、求める量の増加が不利という弱い初期傾向を置くが、係数は成立・拒否から更新し、符号も固定しない。これは相手の真の効用を知るモデルではなく、選択された条件についての偏りを含む有限の経験モデルである。

数量とは別に成立・拒否の経験数を保持する。大量の1取引を多数の経験として数えない。具体的数量と結果は直近の観測にも残す。旧形式の関係データを受け取った場合は同じ構成の記録を統合し、成立・拒否の総数を保持する。旧集計から失われた時系列を捏造せず、数量モデルの初期化は集計単位の近似になる。既存チェックポイントのソース一致ガードは解除していない。

自己の価値評価は食料在庫の対数効用を使い、物も観測特徴のグループごとに個数の対数効用とする。同じ物をさらに受け取る価値は増えても、その増分は小さくなり得る。食料の重みは自己の身体状態・味・加工費用による。自己の価値評価と相手の応答予測を分離し、選択時の価値基準は結果判定まで固定する。

### 共通処理と分野固有処理

`src/lw/decision/relational_gradient.jl` の `relational_transition` は、変更前後の効用差から費用を引き、成立確率を掛けた予測値を返す。`relational_best` は実行候補のその値を比較する。連続微分を強制せず、離散的な局所変更にも共通で使う。

- **移動**：`rho_descent` が位置のポテンシャルを負の効用として渡し、従来の9方向から局所方向を選ぶ。上位の確率的な行動選択、幾何計算、衝突判定は維持する。従来の最小ポテンシャル選択と同じ結果になることを検査する。
- **交換**：相手との関係・物の構成を一つの方法とし、数量違いを同じ方法の局所候補として比較する。食料の増減、物の追加・削減から有限候補を作り、各関係内の最良条件を共通処理で選んでから、関係間の選択を既存BasicLoopへ渡す。数量違いを余分な抽選券にしない。

成功条件は局所探索の出発点として使う。過去と同じ個数を今は持っていなくても、現在観測できる少ない個数に対応付けて組み直す。相手の見えていない所有物は補完しない。初期候補からの局所展開は32候補まで、最終提案は32関係まで。食料は各側合計4単位、物は各側4個までの世界APIの制限を守る。

Hによる候補拡張・確率選択、凍結した予測と結果の残差による学習は既存の共通ループを使用する。今回共通化したのは有限の状態変化評価と局所比較であり、移動の全評価器や食料のみの別交換系を一つに統合したわけではない。交換の数量刻みは1単位で、ρによる可変刻みは未実装。方向変更の応答学習と交換の数量応答モデルも同じモデルへ統合してはいない。

検証対象は、未経験の中間数量でも同じ関係を利用できること、受取量と支払量が異なる向きに作用すること、必要度や在庫で勾配が変わること、拒否が予測更新につながること。単に交換回数が増えたかだけで評価せず、移動側の予測・選択・更新も共通化後に検査する。

## 現実装の範囲と制約

- 全員共通の相場や交換の強制ではない。似た物の誤認も起こり得る。
- 交換候補は既存の拠点内・接触範囲に限る。遠方の相手へ会いに行く計画や、多段の交換経路は未接続。
- 食料のみの既存交換系は別系統。今回の関係記憶は物を含む交換のみに接続。
- 観測した物を記録するため、非公開の他者倉庫の物は候補にできない。
- 保存・日次チェックポイントに含む。`exchange_recalled_choices` は成立経験が照合された選択回数。因果的にその経験だけで選択が変わった回数ではない。
- `experiments/portable_items/exchange_memory_checks.jl` の事前経験は検査用。通常の3日試験は未経験から開始し、固定交換は使わない。
