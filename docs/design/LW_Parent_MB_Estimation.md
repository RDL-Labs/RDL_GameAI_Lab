# LW 親MBの経験から見積もりを立てる

2026-10-26。`mb_parent.jl` を導入し、LWのfood/home親目的に適用する。経路を持たない通常探索にも見積もりを使い、未達成だけの毎tick加算を置換する。安全・身体の優先処理は維持する。全AIの任意深さの再帰階層化を実装したものではない。

## 候補・見積もり・実行

各候補は、目的×探索/接近/経路の最大6種類の経験MBを参照する。探索は過去の達成までの操作数平均と分散、接近は観測距離と0.5単位の歩行見積もり、経路は既存MB辺列の長さと食料取得1操作から予測する。平均消費は達成した経験から学習する。候補の優先度には見積上限操作数の `-0.1log1p` を加え、既存の学習評価・H確率選択と合わせて選ぶ。

経験なしの初期値は便宜上設定した事前MBであり、学習済みと偽らない。探索の中心128操作・初期幅128、接近/経路の幅は最低4操作（経験2件未満では中心値以上）。経験2件以降は標準偏差を幅に使い、最低4操作の幅を残す。上限操作数は2〜4096。現在の各操作は1秒なので実行秒数は同値。確率的に校正された到着分布ではない。

選択時に親目的の見積もりを固定し、行動変更・子経路変更・観測更新で後ろへ延ばさない。同じ目的が未解決なら同じ試行を続ける。別目的・休息・安全対応中の壁時計時間は加算せず、当該親の評価対象操作と消費だけを積む。固定見回しフェーズは対象外。

探索の中間期待は、上限操作数の1/4程度の窓で新しい観測場面が得られること。初期には64操作の窓で、2窓経っても新場面がなければ差としてHへ反映する。場面キーは視覚特徴から作るので、旋回で変わる場合もあり、実際の空間探索範囲の保証ではない。保持する場面は最大64個。

## 親Hと子Hの重複を防ぐ

上限時間からの遅れ、観測場面が増えない遅れ、消費超過、子経路から受け取った逸脱量の累積の最大値を親の逸脱量とする。前回までの最大逸脱を超えた分だけHへ要求し、同じ遅れを親子で足し合わせない。子経路の残差はこの親評価を通じて一度だけBasicLoopへ渡す。操作ごとの1加算へは戻さない。

見積もり内の未達成は親Hを維持し、未到着だけで下位動作を失敗扱いしない。実際の目的達成時だけH解消・報酬を与える。H0の成功も経験学習に含むが報酬は0。身体の必要性・安全判断は別入力として残る。

達成時に操作数・分散・平均消費を経験MBへ反映し、次の試行から使う。未解決の途中経過を到着時間として学習しない。このため成功例だけの学習には楽観的偏りがあり、打切りや失敗時間からの推定は今後の課題。親の実行開始前Hを強制リセットする処理はない。

## 記録と検査

`mb_map.parent_mb` にモデル、目的別の実行中見積もり、評価回数、見積内評価数、H加算要求量、達成数、直近64評価を保存する。実行中の親は最大2、モデルは最大6。`mb_parent_checks.jl` で未発見でも初期予算内はH0、子行動変更でも見積もり固定、達成時に次回予測更新、親子残差の重複防止、二重評価、休止、接近/経路見積もりを確認する。
