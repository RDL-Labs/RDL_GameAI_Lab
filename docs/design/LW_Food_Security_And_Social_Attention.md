# 食料の将来不足と共通の他者観測

2026-10-31。現在の空腹と、将来の食料不足の見通しを分ける。実装は `decision/food_security.jl`。個人倉庫・種類付き食料・社会関係が有効な実行へ接続した。

## 食料の見積もり

移動の `mb_parent_estimate!` を使い、観測した食料への接近／未発見時の探索に必要な操作時間・エネルギーを得る。この見積もりは従来の親MBの成功・未達経験から更新される。追加で、本人の実測代謝消費の移動平均を使う。相手の在庫や世界の未観測食料は読まない。採集予定や援助の約束を確定在庫には加えない。

- 見通し期間：最大（1日、探索MBの上側操作秒）＋2日。2日分は不確実性の初期余裕であり、学習済みの値ではない。
- 必要食料：予測代謝＋探索MBの移動消費から、reserve70を超える身体余裕を引いて食料単位へ換算する。最低1単位を保持する。
- 自分の所有食料・携行・消化中の食料を比較対象にする。加工待ちの既知食料は初期係数0.65で評価し、すぐ食べられる在庫と区別する。
- 不足残差から許容幅0.1を引いた量が不安H。毎tickの加算ではなく現在の残差で置き換え、在庫増加や見通し改善で下がる。
- 時間・消費見積もりは64操作秒ごと、所有量との差は毎tick更新。記録は直近64件。状態と観測は既存の関係状態に置き、日次保存・再開へ含める。

これは常に将来を正しく予測できる保証ではない。代謝実測は移動消費そのものを含まず、移動費用は親MB側の推定で補う。食料の種類別エネルギー、加工時間の個別学習、約束からの期待入手量、備蓄の紛失認識は未対応。1日・2日・reserve70・係数0.65は初期の設計値で、現実の生理モデルではない。

## 行動への接続

不安がある場合、空腹前でも通常の食料探索／社会的接近／取引／援助要求を候補にできる。探索への目的変更には共通のH・方法評価を使う確率分布を使用する。ただしこの親目的選択自体に独立した学習試行を新設したわけではない。夜間休息・安全・即時の身体維持は維持する。不安によって食べる行動を強制しない。

食料のみ・物を含む両方の取引で、同じ予測必要量と不足軽減を評価する。援助者も自分の将来必要量を考慮する。相手への要求は手持ち食料の観測がなくても試みられるが、応答や食料入手は保証されない。相手の倉庫を透視した選択ではない。手持ちの見えない相手への予防的要求は64操作秒ごとの再検討に制限する。状態内のrequestsはこの再検討回数であり、実際の送信数ではない。現在の空腹から、食料を持っている相手へ行う要求は従来経路を維持する。

## 表情と注視

不安は設定経路の表情出力で身体由来のつらさと重ねる。外部へ不安の原因・正確なH・reserve・倉庫量は公開しない。

視野・距離12・遮蔽を満たす相手には共通の外見観測を作る。4以内は0.25刻み、注視かつ細かいρなら0.125刻み、遠方は0/1の粗い状態。注視だけで遮蔽や距離制約を破らない。遠方で0になっても内面が無問題と確定したことにはならない。現在は誤認を含む量子化であり、認識ノイズの別モデルではない。

直近64秒の取引・要求応答の相手を注視対象にする。なければ前回観測で目立つつらさ・怯えを手掛かりに注視する。頭や体の向きを強制変更する機能ではなく、既に視野に入った相手の解像度へ作用する。移動側で使う当該tickのρ基準を共有する。

取引、要求相手の選択、要求への応答、援助候補がこの同じ観測を使う。表情を社会MB照合の文脈に含め、取引結果でも保存する。表情だけで必ず譲る・必ず拒否するとは決めない。援助応答では初期の「つらそうなら渡す重み」を含み、自己の不安は保持する重みに作用する。

視認から援助のために相手へ接近する候補は今回も未実装。困窮前の取引・要求と、援助するための接近は別の接続である。
