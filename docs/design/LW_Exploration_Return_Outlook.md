# 探索中の帰還見通し（2026-10-26）

探索のfood親MBを選ぶ段階で、MB地図に帰還につながる有向経路があるかを評価する。帰還を固定行動として強制せず、通常の確率的な方法選択のpriorityへ反映する。MBシミュレーションONかつexplorationフェーズで有効。home目的、身体・安全対応、初日の設定観察へ新しい制約を加えない。

## 観測から計算する

homeと観測された記憶ノードを終点として、実行済みwalk/scanの辺を逆向きに検索し、元の方向で帰還できる経路を得る。検索方向を反転するだけで、逆向きの移動辺を新設しない。世界座標や物体IDは使わない。

経路選択コストには既存のmb_edge_cost（消費・経験回数・不一致）を使い、帰還消費は通った辺の平均消費を合計する。1回の構築は256ノード・32辺深さ・待ち行列256件まで。64シミュレーション秒ごとに共有キャッシュを更新し、候補ごとの全地図探索を避ける。忘却・home属性変更で使えなくなったキャッシュは即座に無効として扱う。

候補のmb_expected、または現在場面から同じ歩行角度（差7.5度以内）・距離（差0.1以内）で観測された一意な到達場面を使う。複数の行き先があれば未確認とする。pickup/recover/rest/eatは現在場面を使う。scanは景観キーが変化し得るため、予測先がなければ未確認のまま。

## 行動選択への接続

候補ごとに以下を記録する。

- observed_chain / unconfirmed：記憶上の接続あり／未確認。現実での帰還保証ではない。
- 帰還操作数・消費、候補の親目的消費も引いたreserveの余裕。
- 選択に作用したpressure。

既知経路があれば、余裕が20を下回るにつれてpriorityを最大2下げる。未確認は0.25だけ下げ、未確認を不可能と扱わない。現在位置から帰る見通しがなければscanへ0.25を加える。既知の帰還経路の最初の行動も、通常の探索候補として最大1件追加する。food目的のままで、帰還成功を偽造しない。数値は実験用の固定値。

mb_parent_estimateのreturn_homeにも見通しを付け、親試行開始時のコピーに残す。Hへ未確認分を毎tick加算しない。現在は候補評価を介した接続であり、帰還見通しの変化に対する専用のH残差学習は未実装。

## 限界

正確な場面キーから接続を探す初期版で、類似場面を跨いだ帰還グラフの照合は未接続。既存のhome属性上書きや場面数の増加の影響も受ける。検索予算を超える経路や未知の逆方向は未確認のまま残る。記憶の平均消費には未知の迂回・今後の危険・身体変化を完全には織り込めない。後段の連続操舵で進路が変わる場合もあり、候補評価は予測であって実績ではない。

初回に逆向きの経験がない問題を解決したとは言えない。見回し・既知接続の再確認を候補化し、探索経験が帰還経路としてつながるかを試すための段階である。往復を一つの成功経験に自動統合する専用学習も今後の課題。
