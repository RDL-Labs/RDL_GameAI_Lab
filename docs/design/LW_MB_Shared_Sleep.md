# 睡眠と覚醒のMB探索共通化

2026-10-25。`--mb-sleep on`（既定off）はmb_simulationとgeneral_sleepを必要とする。最初の有限実装であり、多階層ρや睡眠全般の統合は未完了。

## 共通部分

覚醒のmb_simulate!と睡眠のmb_sleep_review!は同じmb_searchを使用する。観測された有向辺だけをたどり、辺の消費・観測支持・予測誤差から同じコストで探索する。上限は深さ4、64展開、分岐8、待ち行列64。逆辺・未観測の接続は作らない。

覚醒では現在の観測から、Hと身体状態の条件を満たしたときに探索し、最初の行動を現在の実行可能性で絞る。睡眠では連続休息の開始時に地図を凍結し、既存の睡眠完了コールバックでその地図を探索する。最新8地点からhome/foodを各1回、最大16探索・1024展開。固定した2目的と起点の選び方は当面の計算予算設定であり、H・成功痕跡による起点選択への一般化は未実装。

## 睡眠の結果

見つかった経路を仮説として最大64件保存する。これは成功したまとまりとは別で、成功数・H報酬・辺の観測支持を増やさない。前回の仮説も1日相当まで保持する。覚醒後、起点の再認識・辺と目標の鮮度・現在の目標ラベル・身体状態・最初の動作の実行可能性を確認して候補にする。同じ最初の辺を使う候補は重複させず、覚醒探索と同じmethod ID・優先度を使用する。候補があればその決定では詳細探索を省く。

実際の選択後は共通のmb_record!/mb_observe!で予測を照合する。実際に目的Hを解消した場合だけ既存のmb_goal_result!が成功経路の形成を試みる。睡眠での到達予測に実体験の報酬は付かない。途切れた経験を架空の辺で接続しない。

## 旧処理との関係

このモードでは旧sleep_action_modelsのperformed/blockedによる候補優先度補正と、その利用管理を無効化する。入力設定にgeneral_sleep=apply・sleep_maintenance=onがあっても、mb_sleep=onが優先する。実行結果のsleep_action_modelsはnullになる。

既存の睡眠タイミング、一般経験の記録・比較、experience_bundlesの休眠管理、採集モデル処理は残す。全種類のMBや身体回復を新探索へ置き換えたものではない。探索は睡眠完了時の有限計算であり、シミュレーション時間を消費する長考フェーズや思考による身体消費は未導入。

## 検証

mb_sleep_checks.jlで覚醒探索との同一経路・同一評価、凍結後の情報を使わないこと、重複レビュー防止、身体/Hのゲート、選択後の予測照合、削除された辺を使わないこと、睡眠では報酬を作らないことを検査する。旧モードのMB検査も同時に実行する。

[3日試験結果](../../experiments/rock_gate/mb_sleep_report.md)。sleep.reviewsは睡眠探索の実施、hypothesesは未検証経路、proposals/selectedは覚醒時の候補化/選択。地図全体のselectedには睡眠由来も含むが、searches/proposalsは覚醒時の詳細探索だけを数える。
