# LW：個体から見た他者との関係

2026-10-29。FINITE PROTOTYPE。援助と物々交換の履歴を相手別に接続する。Juliaのみ。[共通方針](RDL_Common_Relational_Policy.md)と[感情・履歴・関係拘束モデル](RDL_GameAI_感情・履歴・関係拘束モデル.md)に沿い、関係全体を単一の好感度へ置き換えない。

## 何を記憶するか

`scene.social_relationships=true`で有効。指定なしはOFFで旧方式を保つ。食料実験の生成ではONを既定にする。食料交換そのものを有効にするには従来どおり`scene.food_exchange=true`が別途必要。共有倉庫でも援助・接触の関係は扱える。

個体は本人専用の表に、本人→相手の方向で記憶する。A→BとB→Aを同期しない。同じ交換でAが得をしBが損をした場合、それぞれ違う経験になる。

| 軸 | 取得する根拠 | 用途 |
| --- | --- | --- |
| 顔なじみ | 接触観測の回数・時間 | 既知の相手へ向かう小さな偏り |
| 援助見込み | 自分の依頼に対してgiven／refuseを観測 | 再依頼・依頼先の重み |
| 援助を受けた経験 | givenの累積 | 自分が譲る・交換する際の重み |
| 交換の応諾見込み | 自分の提案が成立／拒否された結果 | 相手への次の提案の重み |
| 本人の交換利得 | 凍結した価値式で評価した本人在庫の前後差 | 別条件の交換・援助へまたがる経験 |
| 未観測・実行不能 | 応答未観測、期限切れ、在庫・接触条件不成立 | 統計として分離。悪意や損害へ変換しない |

自分が譲ったことは自己側の行為記録として保持するが、「相手も自分を好きになった」という証拠には使わない。相手の応諾を予測するときは自分が提案した履歴だけを使い、自分の受諾回数を相手の性向へ加えない。

## 観測と結果の境界

接触は既存の`observe`に現れた相手参照だけを使う。未観測の相手の位置・在庫・身体・関係表は読まない。本人の観測が続いた区間だけ接触時間を加算し、観測に間隔が空いても一度に加えるのは最大1秒。顔なじみは一緒にいる時間の要約であり、友情の成立証明ではない。

援助は既存の依頼と返信を結び付けた本人の確定記録から更新する。実行されなかった依頼、返答を観測できなかった依頼、明示的拒否を区別する。成立した譲渡・自分の拒否は実行receiptから自己側の行為を記録する。

この接続の検証中に、未決依頼中に別件へ返答すると最新の実行receiptが置き換わり、実行済みの依頼を`request_not_executed`と誤分類する旧不具合を確認した。最新の結果と未決依頼の結果を最大2件だけ保持するよう修正した。解決後は次の結果更新で古い依頼分を外す。この入力証拠の修正は関係ON/OFFの両方へ適用し、受領した援助の誤分類を関係の個性として扱わない。

交換は提案時には成功として更新しない。受諾者は自分の結果receipt、提案者は自分宛の終了通知を受けて更新する。各人の利得は、既存交換方策と同じ選択時の重み・本人在庫の直前直後差から計算する。相手の評価値は渡さない。

拒否や期限切れは、相手に悪意がある証拠として扱わない。援助見込みと交換応諾見込みの分母は、比較できる明示的な成否だけを使う。未応答・実行不能は別に記録する。なお既存の行動目的Hは、取引や依頼の見積もり未達を引き続き評価する。関係履歴をHへ直接加算する新ループは設けない。

## 初期の要約・重み

援助を得た回数をg、明示的拒否をr、提案成立をa、提案拒否をd、観測した接触秒をt、本人の成立交換利得合計をv、成立交換件数をnとする。

```
援助見込み       = (1+g)/(2+g+r)
交換応諾見込み   = (1+a)/(2+a+d)
援助経験         = g/(2+g)
顔なじみ         = t/(60+t)
交換利得の要約   = tanh(v/(2+n))
```

未経験は見込み0.5、その他0で中立。出会っていない相手を参照しただけでは表へ追加しない。成功が後から増えれば、過去の拒否があっても見込みは回復する。関係の鮮度による時間減衰は加えない。

用途ごとに別の組合せを使う。いずれも[-2,2]へ制限した候補重みであり、強制行動や実行資格ではない。

| 用途 | 加える重み |
| --- | --- |
| 依頼・依頼先 | `0.75 log(2×援助見込み) + 0.25 利得要約 + 0.1 顔なじみ` |
| 譲渡への応答 | `0.75 援助経験 + 0.5 利得要約 + 0.1 顔なじみ` |
| 交換提案 | `0.75 log(2×交換応諾見込み) + 0.5 利得要約 + 0.25 援助経験 + 0.1 顔なじみ` |
| 交換受諾 | `0.5 利得要約 + 0.25 援助経験 + 0.1 顔なじみ` |

これらは初期の解釈規則。経験で更新するのは根拠となる記録・集計であり、係数や「友人」という概念を自律的に発見したものではない。将来の関係MB・文脈照合へ接続するための小さな初版とする。

## 既存の選択へどう作用するか

食料交換では、現物と個数による見積もり利得に関係の重みを加え、既存の`BasicLoop`へ渡す。関係の重み自体を物理的な交換利益に加算しない。好きな相手だから交換したという選択と、交換で食料価値が増えたかを分ける。

援助の応答では、身体の必要量・手持ちを保持する費用に関係経験を加える。手持ちがなければ譲渡できない。明示的拒否を経験しただけでは「自分も譲らない」という負点を付けず、再依頼の見込みへ反映する。

関係ONでは、旧方式の「過去の拒否時Hの最大値を使い続ける」抑制を置き換える。二重に拒否を罰したり、後で援助を受けても回復しない状態にしない。旧方式はOFFで維持する。

依頼先は現在観測した食料所持者から選ぶ。ONでは共通の`method_distribution`を使い、関係による重みと既存の援助Hを確率へ変換する。高いHでは分散し、従来の別活動を検討する候補も残す。旧モデルをさらに足して同じ援助記録を二重評価しない。時刻・本人・実験seedから作る安定した抽選値を使い、保存再開で同じ選択を再現する。

応答や取引で拒否が選ばれた場合も、相対する譲渡／受諾の重みは拒否確率に作用する。選択履歴には実際の行動と、重みが作用した候補を`applies_to`で区別して残す。

## 保存と計算量

`social_relationships[actor]`に集計と診断情報を出力し、各日末にも保存する。内部の`relations`を日末チェックポイントへ含める。過去ソースの保存は既存のソースハッシュ検査で区別する。

相手別・経験の種類別に最終receiptを保持し、同一結果の再送を再加算しない。同IDで内容が変わった入力は拒否する。古い時刻の通知も再加算しない。現在の単一tick実行契約では、同じ相手・同じ経験種類の確定結果は1tickに最大1件。

直近の経験は本人ごと32件、選択の根拠も32件、相手別の出典参照は16件。集計は履歴を打ち切っても保持する。古い全経験を再構成できるログではない。接触の観測根拠は最後の本人観測参照と時刻を保持する。毎tick更新は観測された相手だけで、重い経路探索を追加しない。

現在の相手識別は既存の観測参照に依存し、人物の外観照合・誤認・別名の統合は未実装。会話、共同作業、評判、約束、集団・家族、他者の意図推定も含まない。関係が空間的な接近・同行の独立目的を作る機構はまだなく、今回は援助・交換の候補へ接続する。
