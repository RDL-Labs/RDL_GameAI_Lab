# LW：個体から見た他者との関係

2026-10-29。FINITE PROTOTYPE / Juliaのみ。援助・交換の本人側価値、条件付き関係MB、睡眠整理、視認した相手への接近を生活ループへ接続する。[共通方針](RDL_Common_Relational_Policy.md)、[自己との関係拘束モデル](RDL_GameAI_自己との関係拘束モデル.md)、[感情・履歴・関係拘束モデル](RDL_GameAI_感情・履歴・関係拘束モデル.md)に沿い、関係全体を単一の好感度へ置き換えない。

`scene.social_relationships=true`で有効。現在の生活ループは`social_relations_state(actor; relational=true)`を作り、援助も共通`BasicLoop`の予測評価へ接続する。指定なし／OFFは旧社会処理を保つ。直接呼出しの`social_relations_state(actor)`は初版互換モードであり、現在の生活ループと区別する。食料交換自体は別途`scene.food_exchange=true`、種類付き食料、個人倉庫を必要とする。共有倉庫でも援助・関係学習・接近は利用できる。

初版の結果は[旧関係接続の記録](../../experiments/social_relationships/report.md)に保存する。新方式の検査・生活試験は[共通化版の記録](../../experiments/social_relationships/unified_report.md)を参照する。この設計文書は新方式による生存・援助・交換の改善や高速化を測定した報告ではない。

## 本人の経験から、次の予測へ

```text
本人の観測・選択時の条件
→ 相手についての関係MBを部分一致で想起
→ 本人にとっての結果を見積もり、候補を選ぶ
→ 本人が受け取った結果と固定した見積もりを比較
→ 覚醒中の関係候補を更新
→ 完了した睡眠で圧縮・採用
→ 次の依頼・譲渡・交換・接近へ使用
```

個体ごとの本人→相手という方向を保ち、A→BとB→Aは同期しない。同じ交換でAが得をしBが損をした場合、それぞれ違う経験になる。関係の強さは身体の実行可能性、実在する食料、接触や交換の成立条件を上書きしない。

| 根拠 | 保持・予測するもの | 区別するもの |
| --- | --- | --- |
| 接触を本人が観測 | 接触回数・時間、顔なじみ | 友情や相手の意図ではない |
| 自分の要求への明示的応答 | 援助成立／拒否、条件別の援助見込み | 未応答・依頼未実行を拒否へ変えない |
| 実際に受け取った食料 | 受取種類の分布、本人の価値 | 相手の未観測在庫を知ったことにしない |
| 自分の交換提案への結果 | 条件別の応諾見込み | 自分が受諾した回数を相手の応諾傾向に加えない |
| 本人の成立交換 | 選択時に固定した価値式による本人の在庫差 | 相手の評価値と、物理的な交換成立は別 |
| 自分が譲った／拒否した結果 | 自己側の行為記録 | 相手も自分を好むという証拠にしない |

接触観測は既存の`observe`に現れた相手だけを使う。接触時間は観測が続いた区間だけ加え、一度の増分を最大1秒に制限する。視認だけでは接触経験を増やさない。

援助の要求と返信は、本人の未決要求、操作receipt、相手、返信先、観測期限を結び付ける。別件の応答をしても未決要求のreceiptを失わないよう、最新の結果と未決要求の結果を最大2件保持する。受取種類は実際の譲渡結果へ付け、依頼前に相手の食材を見抜く入力として使わない。

## 援助と交換の共通予測評価

新方式の援助と交換は、[`resolve_prediction!`](../../src/lw/decision/prediction_result.jl)で目的H・方法H・報酬を評価する。Hは連続量で、拒否回数そのものではない。

選択時の期待価値を`expected`、同じ本人価値基準で評価した実結果を`actual`、初期許容幅を`ε=0.05`とする。

```text
残差圧 = max(0, expected - actual - ε, -actual - ε)
解消分 = 目的の結果が実際に成立した場合の max(0, actual - ε)
更新H  = min(32, max(0, 以前のH - 解消分) + 残差圧)
```

親と選ばれた方法の両方に同じ評価を使う。正の実利得は方法の報酬となり、許容帯を超える予測外れは別の失敗記録になる。利益は得たが見積もりに届かなかった場合、報酬と残差圧が共存できる。成立のBoolだけで過去のHをすべて0へ戻さない。H増分0、未観測、未実行、目的達成も別々に記録する。

援助では、相手の援助見込みと、本人が受け取ると予測した種類の価値から期待値を作る。受取種類の分布は本人の過去の受領経験から想起する。まだ不明なら、既知の食材種類に対する一様分布を初期仮定とする。要求時に確率、種類分布、本人の種類別価値、文脈、出典、5秒の応答期限を固定し、応答待ちの各tickで失敗を加算しない。

実際に受領した種類を、その固定価値へ当てて評価する。本人の味・空腹・手持ち数によって価値が異なる。同じ食材でも、既に多く持つ本人には追加1個の限界価値が低くなる。生原料の価値は既知の加工先と作業係数から見積もる初期規則であり、加工法を自力発明した結果ではない。

初期価値式は`need=clamp((80-reserve)/80,0,1)`、種類ごとの重みは`(0.2+0.6×need+本人のliking)×加工係数`。加工係数は可食なら1、加工が必要なら0.65。援助1個の価値は`重み×log(1+1/(1+本人の手持ち個数))`、交換価値は`Σ 重み×log(1+本人の在庫個数)`の前後差とする。消化系が無い実行では既定のlikingを使う。価値式と係数は設計者が与えたものである。

要求未実行や受取種類が観測できない結果は評価保留にする。期限まで受領を観測しなかった結果は、援助目的の見積もり未達として評価できるが、相手が明示的に拒否した学習例にはしない。

交換提案では、選択時の味・空腹に基づく重みと本人の在庫から成立時の利得を計算し、条件別の応諾見込みを掛けた期待値を固定する。自分が受諾側なら、決めた条件の成立時利得を見積もる。候補順位には条件付き利得と関係重みを使い、応諾見込みを掛けた期待値で再度順位を押し下げる二重評価はしない。成立時は本人在庫の交換直前・直後だけを比較し、途中の食事や別取引を混ぜない。拒否・期限切れ・成立不能の実利得は0。提案しない選択と、自分が拒否する選択は中立に解決する。[食料・交換の仕様](LW_Typed_Food_Processing.md)も参照。

相手との関係の重みは行動選択へ加えるが、実利得へは加算しない。「相手との過去の経験を理由に交換した」と「食料価値が増えた」を分ける。

## 条件付きの関係MBと想起

[`social_mb.jl`](../../src/lw/learning/social_mb.jl)は、移動用の場面地図に人物IDを混ぜず、本人ごとの社会関係MBを保持する。一般的な関係概念やCoreのcanonical T1形成が完了したという意味ではない。

記憶の条件は、本人の選択時に分かった食材の与える種類／欲しい種類、個数、本人の必要量`need`。`need`は現在の身体から作る初期の特徴である。受取食材や実利得は結果であり、選択前の条件には混ぜない。他者の倉庫残量・空腹・好み・内部記憶・意図は入力しない。

各関係候補は相手、用途、条件、実結果の件数、成立件数、本人利得、受取種類、出典参照・件数・digestを持つ。新しい結果は覚醒中の保留候補へ入り、睡眠前でも暫定的な予測に使える。未応答・未実行・期限切れ・成立不能は監査集計に残すが、相手の明示的な成立／拒否の教師例にはしない。

想起は正確なキー一致でなく、食材条件と数量・必要量の部分一致を使う。欠けている条件は不明として扱い、異なる食材の経験も弱い候補になり得る。支持の強い候補から検索し、共通の`mb_retrieval_budget(H)`を使ってHに応じた想起幅を取る。初期の小さいHでは1件から始まり、最大8件まで広がる。最良候補でも一致が弱い場合は、有限な範囲で追加候補を調べる。

類似性には既存の`mb_metric_update!`を再利用する。実際の成否と本人利得の違いを教師として、食材の違いと数量・必要量の違いへどれだけ反応するかを更新する。同じ意味を共有していたと仮定して成功例を作らない。経験で更新するのは条件付き結果予測とこの距離尺度であり、特徴の語彙、結果を比較する初期許容幅、用途別係数まで自律的に発見するものではない。

想起した経験は一致度で重み付けし、事前値を含む`(1+成立支持)/(2+比較可能な支持)`から見込みを作る。本人利得と受取種類の分布も、想起された経験から作る。相手ごとの全件合算は監査用に維持するが、新方式の予測を古い合算値で二重評価しない。

## 睡眠による整理と採用

夜の休息開始時に、その時点の保留候補を凍結する。凍結後の新しい経験は別の保留表へ入り、同じ睡眠の採用対象に遡って混ぜない。睡眠中でも凍結候補は暫定記憶として参照可能で、採用済み記憶との二重計上はしない。

既存Sleepが完了した時だけ、凍結候補を関係MBへ採用する。同じ保存条件の追加経験は、成否の混在をそのまま集計する。異なる数量・必要量の候補を圧縮するときは、相手・用途・食材種類を保ち、一致度0.8以上、観測された成立率と平均利得の差がそれぞれ0.2以内という初期基準を使う。違う食材や、結果の大きく異なる条件を見た目の近さだけでまとめない。圧縮は記憶の容量管理であり、想起の正解判定ではない。

中断した睡眠では採用しない。残った凍結候補は次の凍結時に保留候補へ戻し、容量内で再整理する。反復中断で無制限に増やさず、上限で落とした候補数も記録する。完了した同じ日を再適用せず、整理によって架空の成功件数・報酬・H解消を作らない。

新方式では旧`consolidate_social`による別の援助期待モデルを生活ループで作らず、現在の判断がこの関係MBを参照する。OFF時と旧単体実験では従来の社会Sleepを残す。

## 選択と、相手へ近づく行動

依頼先は接触している食料所持者から選び、既存の活動を続ける候補も常に残す。相手別の予測、経験報酬、方法H、目的Hを共通の`method_distribution`へ渡す。依頼先を選んだ後に、同じ関係で再度抽選して二重に抑制しない。譲渡／拒否の応答も共通の分布を使い、身体の必要量と手持ちを保持する費用を残す。食料を持たなければ譲渡できない。

交換提案と応答は引き続き`BasicLoop`で選び、条件ごとの関係予測を候補重みに加える。用途に応じた初期の重みは次のとおり。各重みは[-2,2]に制限し、行動を強制する資格にはしない。

| 用途 | 関係から加える初期重み |
| --- | --- |
| 依頼先 | `0.75 log(2×援助見込み) + 0.25 利得要約 + 0.1 顔なじみ` |
| 譲渡への応答 | `0.75 援助経験 + 0.5 利得要約 + 0.1 顔なじみ` |
| 交換提案 | `0.75 log(2×交換応諾見込み) + 0.5 利得要約 + 0.25 援助経験 + 0.1 顔なじみ` |
| 交換受諾 | `0.5 利得要約 + 0.25 援助経験 + 0.1 顔なじみ` |

援助経験は想起した成立支持から、利得要約は想起した本人の交換利得から作る。顔なじみは接触時間`t/(60+t)`。係数そのものは初期設定であり、友情や互恵性の概念を発見したとは扱わない。関係の鮮度による時間減衰は設けない。

食料目的で空腹のときは、現在視認した相手へ接近する候補を通常の探索候補へ加える。視覚処理はWorld幾何を観測に変換し、判断には既存の相手参照、15度刻みの方向、粗い距離帯、接触の有無だけを渡す。初期視認範囲は12、前方180度、遮蔽あり、最大16体。相手の正確な座標や所持食材は渡さない。

接近候補は、相手から援助を得る見込みと、本人の現在の食材価値による期待利得を使う。既知の受取種類分布があれば、その本人価値で評価し直す。未経験なら初期分布を使う。移動費用と粗い距離で重みを調整し、他の探索・休息などと共通の方法選択で競合する。「他者がいる」「近づいた」こと自体の報酬は置かない。

接触を観測できたことは、次の通信が可能になった証拠であり、食料を得た証拠ではない。見失ったことや距離帯が変わらないことだけでも、相手の拒否を学習しない。接近後は既存の依頼・応答・物理的譲渡の成立条件へ戻る。現在の生活接続は食料援助のための接近であり、自由な交流、同行、遠距離救援声や交換のための訪問まで接続したものではない。

## 保存・上限・未接続の範囲

関係状態、援助の未決見積もり、共通ループの学習・乱数状態、保留／凍結／採用済み関係MBを日末チェックポイントへ保存する。`social_relationships[actor]`にJSON向けの集計・診断を出力する。内部の`BasicLoop`はsnapshotへ変換し、再開には生の保存状態とソース一致検査を使う。

| 保存対象 | 上限・保持方針 |
| --- | --- |
| 関係の直近経験／選択根拠 | 各32件。相手別の累積件数は保持 |
| 相手別の出典参照 | 16件 |
| 採用済み社会関係MB | 96件 |
| 保留候補／睡眠凍結候補 | 各128件。容量による不採用・削除件数を記録 |
| 関係MBの出典参照 | 各16件と累積件数・digest |
| 関係MBの想起 | 最大8件。更新時の距離学習も比較候補最大8件 |
| 距離学習・睡眠レビューの診断 | 距離学習64件、睡眠レビュー32件 |
| 援助の詳細結果 | 32件。成否別の累積件数は別に保持 |
| 旧形式の援助観測履歴 | 新方式では直近128件。`records_pruned`に削除件数を記録 |

同じ結果の再送を経験として再加算せず、同IDで異なる内容の再送は拒否する。相手別・経験種類別の最終receiptを保持し、古い通知も再加算しない。詳細履歴を切っても監査用累積件数を保持するが、全過去経験を再構成できるログではない。学習・想起の対象は上限付きの関係候補であり、毎tickすべての過去の相互作用を検索しない。

初期設定として残るものは、相手IDによる人物識別、食材の種類と加工知識、価値式と作業係数、関係の特徴枠・初期距離尺度・圧縮基準、用途別重み、視認範囲と通信形式である。経験で変化する見込み・価値の記録・類似性尺度・選択履歴と分けて評価する。

人物の外観照合・誤認・別名統合、一般会話、語彙の学習と伝播、約束、評判、共同作業、家族・集団、相手の意図・未観測在庫・選好の推定は未実装。所有は引き続き世界側の個人倉庫制約であり、所有概念や相互承認の自律形成を意味しない。

2026-10-30に[非食料の小物](LW_Portable_Items.md)の配置・拾得・譲渡・交換をWorld側へ追加した。小物の主観価値、他者需要、物と人物の連想をこの食料用の社会MBへ接続したものではない。食料在庫評価の減少だけで、関係性を含めた交換全体の不利を確定しない。本人の評価と本人が推定する相手の評価も、今後別に扱う。
