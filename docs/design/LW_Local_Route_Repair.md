# 局所修正と全体経路の保持

2026-10-26。`mb_local_repair.jl` を追加し、同じ目的の微修正を全体経路の放棄と区別する。

## 選択と保持

実行中の経路に対して、継続・再確認・局所修正・全体変更の候補群を作る。通常の歩行、目印追跡、見回し等は局所修正として経路ID・辺列・カーソル・固定見積もりを保持する。局所修正の操作数/消費は元の経路試行の実績へ加算し、見積もりとの差からHを更新する。身体都合の強制休止は従来どおり停止時間として扱う。

全体変更は別経路の選択、または明示的な `mb_abandon` 候補（経路を放棄して見回す）とする。実際の親目的変更も従来どおり中断する。新しい経路を選ぶ前からHが高いだけでは捨てやすくせず、変更の重みは `max(1e-6,min(親H,この経路で課した逸脱量)/閾値)` とする。継続1、再確認/修正はHと不確実性に応じた重み。候補数による票数の偏りは補正し、既存の学習評価・確率選択に従う。固定ロックや無条件継続ではない。

## 再接続

局所修正後、現在カーソルの辺の始点・終点だけを視覚特徴から照合する。始点へ戻ったと推定したら同じ位置から再開、終点と推定したら1段だけ進める。類似度0.65以上、候補間の信頼度差0.1以上を条件とし、両方に似て曖昧なら保持して再確認する。遠い経路部分へのジャンプ、全経路のリセット、仮想辺の実績化はしない。

再接続は仮の認識で、確認済み遷移や報酬には数えない。1特徴でも誤対応は起こりうる。見えない/一致しない場合も修正コストが積み上がり、Hによる放棄・変更へ広がる。現段階は局所の再接続であり、任意の長い迂回路を探索して辺列を置換する一般的な再計画ではない。

## 評価

局所修正中に本当に目的を達成した場合は、保持していた経路試行の目的達成として記録する。ただしそれだけで記憶経路の正しさや因果的な寄与を証明したことにはならない。終了記録の修正回数・手数・確認済み手数を併せて見る。

`local_repairs` / `local_rejoins` は累計、`repair_records` は直近64件の再接続。終了理由 `H_abandon` と親目的変更・別経路選択を分ける。Hによる放棄は次回の経路評価を下げる材料にする。

`mb_local_repair_checks.jl` で同じ経路の保持、始点復帰・終点への1段再接続、固定見積もり、曖昧時の進行なし、追加コストからのH加算、明示的放棄、持ち越したHだけでの即放棄抑制、親目的変更を検査する。
