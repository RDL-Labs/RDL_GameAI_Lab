# D初日の帰宅停滞：到着境界の浮動小数点誤差

対象: 個人宅版10日試験（凍結9613cd6）のD初日。
元の初期入力・凍結ソースから初日を再実行し、行動実行前後の座標・方向・歩幅・
身体要求・家モードを追加記録した。通常コードや元チェックポイントは変更していない。
日別記録・行動カウンタ・イベントの3照合は一致。全内部状態/RNGの完全比較ではない。

## 原因

家の中心(2,2)、半径0.6。帰宅の到着閾値は0.6×0.8=0.48。
歩幅も距離−0.48に制限していたが、停止位置から距離を再計算すると
0.48000000000000004 または0.4800000000000001になった。
厳密な `distance<=0.48` を満たさず、次の歩幅は5.55e-17／1.11e-16。
世界座標を動かせない微小量なので座標は不変のまま、walkはperformedとして費用を消費した。

- 帰宅歩行7474回、うち座標不変7450回（99.68%）。すべて到着境界上。
- 静止歩行だけで生活尺度約10.35時間相当（1tick=5秒）。
- 最初の停止位置: (1.8344780734121595, 2.4505579783098392)。
  782秒目に到着境界へ入り、1330tick連続静止。その間strainは約0.0315→1。
- 帰宅開始774秒、身体要求で中断5727秒。再度6010秒に帰宅開始、10251秒に中断。
  10702秒に3回目を開始し、10710秒にようやく到着判定。
- 最初の停止地点の反発は0。障害物による閉塞や、取引を選び直したことが主因ではない。
  途中の休息や身体要求による中断は、この無移動の消耗に伴っている。

今回追加した家の到着処理の実装不具合。H・ρの調整や個体Dの性格で説明しない。

## 修正

`configured_house_plan!` の到着判定に世界座標スケールの8ULPを許容する。
数値丸めの吸収であり、認識の許容幅や家の広さを拡張する設定ではない。
元ログの2停止位置でrestになり、帰宅歩行カウンタを増やさないこと、
0.480001の明確な外側ではwalkを維持することを回帰検査へ追加。
通常移動の消費式や他の目的の到着判定は変更しない。

診断スクリプト:
`experiments/social_relationships/house_return_trace.jl RUN_ROOT OUTPUT [fixed]`
（fixedは修正済み帰宅関数だけを凍結ソースへ上書きして比較）。
`summarize_house_return_trace.jl OUTPUT` で静止歩行と位置を集計。
