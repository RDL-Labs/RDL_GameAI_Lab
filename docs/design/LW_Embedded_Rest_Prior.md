# 休息要求の埋め込み事前評価（2026-10-26）

休息を経験するまで場所の価値が全く分からない問題に対し、初期の身体要求と休息場所の事前評価を導入。`decision/embedded_rest.jl`に分離し、設定経路の固定行動や達成後の報酬とは別にする。現段階ではfood/homeの既存親目的へ接続する有限実装であり、任意の場所・目的を自律形成する機構ではない。

## 三つの区別

- 埋め込み性質：疲労・長い覚醒から休息を求める。
- 初期仮説：homeを休息場所として期待する。初期評価0.8、事前重み5観測。
- 経験：休息を求めて拠点にいたとき、実際にrestを実行できた割合で場所への期待を更新する。

初期仮説には世界座標、帰還経路、架空の成功経験を含めない。homeをどう見つけて辿るかは既存の観測・地図・方法選択を使う。帰還経路の探索制限を解除する変更は含まない。

## 休息の圧と選択

身体strainと覚醒時間の代理量の大きい方からneed（0〜1）を得る。代理量は非rest操作で+1、実行できたrestで-4、上限1日分。半日分でneed=1。この比率は実験上の初期設定であり、生理学的に校正された睡眠モデルではない。拠点外で休んでも身体要求は減る。

food_pressureは空腹intensityとreserve不足から求める。追加の休息場所選択確率は

`need / (1 + exp(1 + 6*food_pressure - 8*need*place_value))`

初期place_value=0.8、need=1、空腹なしなら約99.55%。need=0なら0で連続的に変化する。選ばれると既存のhome親目的へ接続し、到着済みなら既存の休息処理を使う。固定の行動ロックやHへの定数加算は導入しない。

既存の帰還要求は保持する。設定された身体維持がreplenishingの間は新たな休息要求でfoodを上書きしない。安全・摂食・社会応答・初日の観察など既存優先処理はそのまま。初日は身体代理量のみ更新し、この新しい目的選択は適用しない。乱数は既存homeループの個体別ストリームを使うため、ON/OFFで以降の乱数消費は変わる。

## 経験更新

休息要求が選ばれ、拠点が観測された機会60件を一窓にする。rest実行率を1観測として直近64件保持し、`(4 + 実行率の合計)/(5 + 観測数)`で場所評価を更新する。危険回避等で休めなかった機会は率を下げる。拠点を離れると未完了の窓は破棄。これは休息の実行可能性の経験で、身体の回復量や危険の因果を直接学習するものではない。

日次の休息報酬5とは別系統。事前評価は最初の経験へ導き、達成後の報酬は方法・経路へ価値を伝える。前回の60秒連続休息条件は維持する。

## 有効化と限界

JSONの`embedded_rest: "on"`、rock_gate runnerの`--embedded-rest on`で有効。既定off。MBとBasicLoopを必要とする。結果は各mb_mapのembedded_restに、選択回数・確率・身体代理量・場所評価・経験を保存する。試験の途中で新しい経路や安全な休息場所が得られる保証はない。既存の定時帰還・設定身体維持との全面統合は未完了。

selectionsには既存の帰還要求が続いている場合も含むため、追加機構だけが新たに帰還を起動した回数とは読まない。また、親で休息を選んでも、その秒の実行行動は安全や食事によって上書きされ得る。親の選択回数と実際の休息時間は分けて評価する。
