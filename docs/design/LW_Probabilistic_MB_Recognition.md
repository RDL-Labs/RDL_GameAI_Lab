# 不確実な対応付け・実行結果学習・睡眠整理

2026-10-25。MB地図の認識、覚醒探索、睡眠仮説の利用、成功したまとまりの利用を共通の対応付け評価へ変更する。観測キーは記録IDとして残すが、再利用時の完全一致条件にはしない。

## 認識と行動を合わせて選ぶ

現在と記憶に共通する色を取り、距離帯と相対角の整合度を評価する。共通特徴で向きを合わせ、記憶の動作を現在の身体基準へ変換する。見えない特徴は矛盾扱いしない。1特徴でも観測を保持・候補化できるが、証拠の重みは2特徴以上より低い。0特徴や不完全な視野出力は引き続きunknownとなる。

対応付けの重みは、観測の整合度と過去の一致/不一致の支持から作る。上位4件（高Hでは8件）までを計算予算として扱い、各記憶に対応したと仮定する行動候補を生成する。候補のpriorityへlogの証拠重みを加え、既存BasicLoopの確率選択へ渡す。独立した認識の抽選を先に確定するのではなく、認識仮説と行動の組を確率的に選ぶ。

記録上のrecognition_probabilityは保持した対応候補間の正規化重み。実際の行動選択確率とは異なり、校正済みの正解確率でもない。実行可能性・目的H・既存行動報酬なども最終選択に作用する。完全一致も唯一の候補である保証はなく、誤認識は許容する。

## 結果を分けて学ぶ

実行記録に、観測したキー・対応先・対応付けIDを残す。次観測を予測先と比較し、共通特徴2個以上で整合度>=0.85なら一致、<=0.65なら不一致、それ以外はunknown。

- 一致：対応付けと予測した辺の支持を増やす。
- 不一致：対応付けと辺の評価を下げる。ただし認識と遷移のどちらが原因かは確定せず、recognition_or_transition_unresolvedとして記録する。
- 実行失敗：blockedなどは実行失敗として辺のコストへ反映し、対応付けの不一致数は増やさない。
- 観測不足：unknownを記録し、誤りと断定しない。

弱まった対応も、共通特徴があれば非ゼロの重みを残す。実際に取得した生の観測ノードは統合しない。新しい辺は実際の観測→動作→次観測だけから作り、仮に認識した場所へ観測を接ぎ替えない。睡眠の予測一致だけでは支持や目的H報酬を増やさない。H報酬は従来どおり実際の目的達成時のみ。

## 鮮度による足切りを廃止

MB探索の辺・目標、成功まとまり、睡眠仮説の1日相当の期限を削除した。時刻は因果順序、次観測との対応、探索頻度の制御、診断に残す。現在の観測時刻と実行時刻が一致すべきという条件は記憶の鮮度ではない。

## 容量整理は睡眠時

覚醒中に容量へ達したら、新規ノード・辺・まとまり・対応付けの登録を抑制し、既存記憶を古さ順に削除しない。登録できなかった件数を記録する。現在観測そのものと行動は継続する。

睡眠完了時に、辺は実観測支持・予測一致/不一致、ノードは接続数と目的ラベル、まとまりは成功と予測結果、対応付けは一致/不一致と利用で整理する。上限に近いノード・辺は75%まで減らし、参照整合を保つ。睡眠仮説は実際の辺コストで最大64件を選ぶ。時刻は順位に使わない。同一睡眠の整理は一度だけ。睡眠がなければ容量の新規登録制限は続く。

## 診断と限界

recognitionに選択数、一致/不一致/実行失敗/unknown、対応付け支持、候補化阻害理由、直近64結果、睡眠整理記録を保存する。詳細探索・睡眠・まとまりでは共通の対応付けを使うが、目的Hや身体のゲート、有限探索予算は残る。

これは拠点全体の構造学習や多階層ρの完成ではない。色と距離帯の同じ場所の混同、目標ラベルの上書き、0特徴区間の経験の断絶はなお残る。接触・音・自己運動による見えない物の追跡は未実装。睡眠整理も支持に基づく有限容量管理であり、一般的な構造圧縮・分割の学習は未実装。既存の別系統の行動記憶・経験bundleの整理処理まで全面置換したものではない。
