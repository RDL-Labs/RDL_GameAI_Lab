# 拠点での倉庫観測（初版の設定経路）

2026-11-01。食材一覧から未観測の肉まで要求していた問題への初版対応。

## 条件

LWの`scene.open_stores`は既定で`true`。`false`で従来の非公開倉庫の実験へ戻せる。下位の観測関数は互換性のため既定OFFで、LW本体から明示的に設定を渡す。実際の設定は結果の`world_checkpoint.open_stores`に記録する。

観測者が拠点中心から1.25以内なら、他者の個人倉庫の食材別数量をコピーして`observed_food_stocks`として渡す。所有者が外出していても倉庫は見える。ただし交渉相手として接触できるかは従来の条件で別に判定する。倉庫内の非食料物も既存の物体観測へ載せ、所有者・色・大きさ・発光などを見られるようにする。物体観測の最大32件という上限は維持する。

これは拠点内で倉庫を見回せるという**固定の観測ショートカット**であり、埋め込みMBや観察経験の学習ではない。倉庫の建物・扉・個別の視線遮蔽・注視・ρによる数量認識は初版では再現しない。拠点外から倉庫の内容は見えない。相手の好み・身体状態・内的な必要度・価値判断はこの観測へ含めない。

## 候補への接続

- 食料だけの提案は、相手の倉庫で観測した種類と数量の範囲から要求を作る。
- 物を含む新規提案・経験からの再利用・数量修正・逆提案にも同じ食料数量上限を適用する。
- 倉庫内の物も、従来の見えている所有物と同じ特徴評価・要求候補へ接続する。観測だけで取得・譲渡は発生しない。
- 受け取った提案は提案自体を証拠として扱う。観測後の消費や移動で在庫は変わり得るため、承諾時には世界側が所有権・数量・同意を再検証する。観測は在庫の予約ではない。
- OFF時は従来の候補生成を維持するため、未観測食材への要求も再び起こり得る。

固定の初期味評価は今回変更していない。倉庫可視化の変更単独では、不足改善を必須にする制限は残っていた。その後、2026-11-01に[複合勾配による判断](LW_Compound_Trade_Gradient.md)へ移行した。倉庫可視化だけで交換成立が回復したという主張ではない。

## 検査

`experiments/portable_items/open_stores_checks.jl`で、拠点内外、外出中の所有者、コピーの独立性、種類・数量制限、物交換の数量修正と逆提案、非公開情報を直接使わないことを検査する。既存の食料交換方策・逆提案・LW統合検査も実行。LW統合検査には既定ONと明示OFFの結果記録を追加した。長期試験は今回行っていない。

今回の結果：倉庫観測の追加検査133項目PASS（同ファイルの既存世界検査を含め384項目）、食料交換方策74項目PASS、逆提案検査509項目PASS（既存世界検査の再実行を含む）、LW統合31項目PASS。食料交換の世界側検査もPASS。統合検査では日末チェックポイントからの再開と二重適用防止も確認した。
