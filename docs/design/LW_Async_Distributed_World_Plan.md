# LW 非同期個体・分散世界の将来設計案

2026-10-28。状態：将来案・未実装。現在の同期実行、進行中の試験条件、時間プロファイルは変更しない。

## 意図と現在との差

個体はそれぞれの観測・判断・行動周期を持つ。全個体を毎tick待ち合わせることを、この案の必須条件にはしない。RDL全般の同期要件を定義する文書ではなく、GameAIの実行方式の案である。

現行の `src/lw/simulation/day.jl` は、世界時刻のループ内で観測、個体の判断、行動反映、身体更新を順に行う。個体の計算が重くなると実行時間は延びるが、その計算待ちだけで世界内時間が進むわけではない。

将来は重い判断をしている個体がその場に留まる間も、世界・他個体・身体の代謝を進める。長考による予測精度と時間損失を、同じ環境内の相互作用として扱う。短時間の反射、継続中の移動、判断の中断は別途設計する。最初の候補は「判断中は移動停止、身体更新は継続」とする。

## 所有と受け渡し

- 世界担当が時刻、位置、身体、資源、取得・譲渡・接触の確定状態を所有する。
- 個体担当が個体のMB、観測履歴、判断途中の状態を所有する。世界の可変データを直接書き換えない。
- 世界は観測時刻・状態の版を付けた観測を渡す。個体は観測した情報だけで判断し、行動要求を返す。
- 世界は要求を現在の状態で処理し、成立・不成立と実際の結果を返す。古い観測という理由だけで一律に要求を捨てない。
- 思考中に食料がなくなった場合などは、結果を再観測・学習へ渡す。通信障害による不達と、世界内の行動失敗は記録上区別する。

全個体の一斉同期を外しても、有限資源の二重取得や身体更新の重複は許さない。相互作用を確定する場所で必要な順序と整合性を持たせる。

## 時間の扱い

実際の計算待ちを世界内の時間損失として許容する。CPU性能、同時実行数、OSの待ち時間、将来の通信遅延で挙動が変わり得ることも、この実験方式の性質として明記する。処理能力そのものを生物固有の感度・能力値と同一視はしない。

世界は無制限の速度で先へ進めず、現実時間に対する世界時間の進行倍率を設定する。この倍率は既存のWorld時間と人間時間の換算とは別の設定である。具体的な倍率、負荷超過時の減速方針、遅れて届いた行動の扱いは未決定。

観測時刻、判断の開始・完了、要求到着、反映時刻を記録する。可能なら計算時間と待ち行列・通信の時間も分ける。同じseedだけでは非同期実行の完全再現を保証しない。比較用の同期実行を残し、将来の再現には受理イベントの順序・時刻と初期状態を保存する方式を検討する。

## 多数PC・MMORPG型の構成

最初は一つの世界サーバーと複数の個体ワーカーを想定する。個体ワーカーは同じPCのタスク、別プロセス、別PCへ段階的に移せる境界を設ける。描画・人の操作用クライアントも世界への要求と観測の経路へ接続できる構想とする。

```text
個体ワーカー A（PC 1） ─┐
個体ワーカー B（PC 2） ─┼─ 観測 / 行動要求 / 結果 ─ 世界サーバー
個体ワーカー C（PC 3） ─┤                          時刻・身体・資源
表示・操作クライアント ─┘                          相互作用の確定
```

個体数だけでなく世界側が重くなった場合には、地域ごとの世界サーバー分割を検討する。その際も各個体・資源の確定状態には一つの担当を持たせ、地域移動時の所有権移管を明示する。複数サーバーが同じ資源を同時に確定する方式にはしない。

分散時には要求IDによる重複適用防止、個体ごとの要求順序、通信切断時の身体継続、再接続時の状態照合、保存と復帰が必要になる。ネットワークへ世界全体や全MBを毎回コピーせず、観測と結果の必要部分を受け渡す。具体的な通信方式、認証、地域分割、移管手順は未設計。

MMORPG型とは共有世界と非同期の参加者という構成上の参考であり、現段階でオンラインゲーム対応を実装・保証したものではない。

## 段階と確認項目

1. 現行同期方式を維持したまま、世界更新と個体判断の所有・入出力を分離する。
2. 同一PCで世界担当と個体判断タスクを分け、世界の進行倍率を固定した小規模実験を行う。
3. 個体ワーカーを別プロセス・別PCへ移し、遅延・重複要求・切断からの復帰を検証する。
4. 世界側の負荷が必要性を示した段階で、地域分割を検討する。

確認するのは、長考中にも他個体と身体が進むこと、資源収支の保存、同一要求の一度だけの反映、古い観測からの行動結果の記録、世界の負荷超過時の挙動、CPU・通信条件による行動差である。速度向上や行動改善は未測定で、専用スレッドを設けるだけで速くなるとはしない。
