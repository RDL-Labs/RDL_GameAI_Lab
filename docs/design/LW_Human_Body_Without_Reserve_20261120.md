# 人間の旧 reserve を身体成分へ置換

2026-11-20。人間の三栄養素身体を対象とする。実測された生理ではなくゲーム用近似。

## 状態と終了条件

- `HumanBody` は `reserve` を持たない。糖・脂肪・アミノ酸・組織と生死を保持する。
- 糖・脂肪が足りなければアミノ酸、さらに生存下限を超える組織を消費する。
- 糖・脂肪ゼロでは認知や摂食を止めない。生存中は食事・要求・取引の候補を扱える。
- 組織100から50への減少に応じて活動能力を線形に下げ、組織50以下で不可逆な死亡。
  死亡後の摂食・活動・代謝・修復は停止する。未払いエネルギーを死亡後も累積しない。
- 通常LWの死亡tickは `dead`、選択由来は `physical` と記録する。
  旧collapseスイッチOFFでも人間の死亡は無効にならない。

`energy` は独立の残量ではなく、糖＋脂肪＋アミノ酸＋消費可能な組織の派生合計（E）。
消化管と組織の生存下限は含めない。身体要求値は栄養別の不足から別途求める。
一食は20 Eで、100/232への換算を廃止。収支監査の全物質エネルギーには消化管と保護組織も含む。

## 更新と判断への接続

`step(HumanBody,...)` は疲労・瞬発力と予定活動強度を返し、栄養プールを変更しない。
実行tickの `digest!` で活動・基礎代謝・消化・修復を一度だけ適用する。
候補の消費見積もりには予定活動費を使う。`metabolize` による予測はプールのコピーを使い、
候補比較が実体の栄養を消費しない。睡眠時の強度はゼロだが基礎代謝・修復は続く。

移動・経路記録・帰還余裕・食料確保見積もりはEを使用する。
味の選択性・加工待ち費用・取引の需要・表情・補給継続は身体要求値を参照する。
備蓄必要量は成分の不足と既存の食料確保予測から求める。食料予測に旧80/100残量を再生成しない。
日次計画の要求予測は現在要求と予定消費割合による安価な近似で、栄養変換の完全予測ではない。

既存の `configured_body_purpose!` と日次計画の固定補助は残る。
今回その入力を旧残量から身体要求へ揃えたもので、自律MB化したとは扱わない。
初日研修・帰還後待機など、その他の設定経路も今回撤去していない。

## 互換性の境界

旧シーンの `reserve` は初期糖・脂肪への入力変換だけに残す。例えば70なら糖22.4、脂肪140、
組織100、アミノ酸8。実行中にこの指標を更新・再生成しない。
旧 `Body` と旧消化は動物アダプター・旧fixture・明示的な旧設定のため保持する。
動物の身体組成は今回変更していない。全リポジトリから文字列reserveを削除した変更ではない。
古い経路関数の引数名reserveが残る箇所もあるが、新人間から渡す値は実量Eである。

`MacroBody.alive`、`HumanBody`、MB予測のenergy保存キー追加は保存構造の変更。
旧チェックポイントの無変換復元は保証しない。旧実験の凍結ソースと保存状態を保持し、新規開始で検証する。
新状態の保存・復元では身体と消化側が同じ栄養プールを参照することを検査する。
