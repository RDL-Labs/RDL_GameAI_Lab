# 候補の細分化による選択重みの水増しを避ける

2026-11-22。糖予算版を比較基準に、同じ19日末から20日目を局所再実行する。

## 選択規則

既存の候補評価・学習・Hによる温度を適用した候補重みをw_iとする。
同じ関係gについてW_g=max(w_i)、内部比率p(i|g)=w_i/sum(w_j)とし、
最終重みをW_g*p(i|g)とする。全候補を一つの列として正規化し、乱数は従来と同じ1回。
「まず釣り、次に採取」等の固定順位はなく、方法を別抽選する段階も設けない。
既存の候補順、実行可能条件、H、見積もり、試行終了は変更しない。

同等・弱い地点を増やしても、その関係全体の重みは増えない。
より強い見込みの候補が加われば、代表の重みは上がる。
同じ関係内では候補間の比率を維持する。複製された候補自身の内部選択頻度まで
不変にする規則ではない。最大値は暫定の集約で、多数の独立した代替の利点は評価しない。

## 接続範囲と限界

共通関数 `relational_candidate_distribution` はBasicLoopへ追加し、獲得候補だけで使用。
関係キーは既存のtechnique（fishing/pickup/explore）。これは暫定の分類で、
関係のまとまりを経験やρから自動構築した実装ではない。
異なる採取対象もpickupにまとめることによる粗さがある。
取引をこの獲得候補列へ新たに接続したわけではない。
選択の固定順位・固定行動を追加しない。観測者の世界正解も参照しない。
