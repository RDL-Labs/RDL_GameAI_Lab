# LW：汎用的な落ち物と移転操作

2026-10-30。Julia / FINITE WORLD CAPABILITY。地面にある独立物を、種類によらず拾う、置く、保管する、譲る、交換するための世界側の基盤。光る石・貝殻・羽は初期の品目であり、取得可能な種類のホワイトリストではない。

## 世界基盤と行動接続の境界

世界基盤は、物が存在し操作できることを先に用意する。共通価格、貨幣属性、譲渡による固定好感度は追加しない。2026-10-30の行動接続では、`scene.incidental_items=true`のときだけ、通常の食料探索・帰還中に手の届く物を拾う候補を生成する。省略／falseは従来の配置のみ。弱い新奇性の初期値と経験更新の範囲は後述する。

交換できることは、実際に交換へ使うという予測ではない。同じ物・同じ交換でも、各個体の必要・好み・経験・相手との関係によって意味は異なり得る。本人の評価と、本人が推定する相手の評価も区別する。現行の食料利得だけで石の価値を決めず、物に対する経験価値と他者需要の学習は次段階へ残す。

元の[光る石の設計](RDL_GameAI_実装手順予定.md#phase-13--glowing-stone--emergent-value)では弱い誘引、収集、贈答、他者需要の学習等を想定する。今回の新奇性初期値は実験用であり、物の実用価値や石固有の価値を確定しない。[睡眠設計](RDL_GameAI_睡眠システム設計.md#8-誤接続)にある人物と物の連想は未接続。

## 世界の状態

`scene.loose_items`に有限な物体を置く。省略時は無効。旧名`portable_items`も使用できるが、両者の同時指定は拒否する。種類は1〜65535の数値ID。`src/data/item_ids.jl`の1=光る石、2=貝殻、3=羽は既定属性で、他のIDも同じ操作で扱う。食料の種類IDとは別の名前空間であり、食料個数、栄養、摂食には入らない。

```json
{"loose_items":[
  {"id":1,"kind":1,"x":0.0,"z":8.0},
  {"id":2,"kind":2,"x":1.0,"z":7.7},
  {"id":3,"kind":3,"x":1.7,"z":7.0}
]}
```

各物体はID・種類・色・大きさ・質量・発光強度、所在（地面／携帯／個人保管）、所有者、初期由来、直近の移転履歴を持つ。種類・所在は数値で保存し、ラベルは出力用。1物体は必ず一つの所在に属する。保管は食料と同じ拠点範囲の論理的な個人枠で、箱の座標や所有概念の自律形成ではない。

新しい品目は入力データだけで追加できる。例えば`scene.item_kinds`に`{"id":4242,"label":"wood_fragment","color":"brown","size":0.3,"mass":0.25}`を登録し、`loose_items`にkind=4242の物を置く。登録しない正整数種別も許可し、既定属性と物体側の属性で扱う。未知種の既定はneutral色、size=0.1、mass=0.1、発光なし、表示名item_番号。種類を追加しても拾得・譲渡・交換の条件分岐は追加しない。出力の`kind_ids`と種類別個数配列は同じ順序に対応する。

これは地面に置かれた独立物の契約。地形として固定した岩や根のある立木を、そのまま移動できるようにはしない。将来、採石・伐採等で独立物になったものを同じ契約へ渡せる。

初期の色と大きさは石cyan/0.12、貝殻cream/0.10、羽blue/0.18。石の光源強度0.02は物理的な観測入力で、報酬ではない。色・大きさ・質量・発光強度は種類表や配置時に変更できる。形状の詳細、耐久・腐敗、加工、重量による歩行消費の増加は未接続。

## 持てるかの判定

`scene.item_carry_limits={"mass":5.0,"size":1.0}`を初期の携行枠とする。massは所持する非食料物の合計、sizeは単品の最大寸法に対する制約。いずれもモデル上の仮設定で、実際の人間の身体能力を推定した値ではない。身体damageに応じて有効質量枠を`mass × (1-damage)`に下げる。

大きい・重い物も地面への配置と観測はできる。拾得／取り出しでは操作後の携行量を検査し、持てなければ`carry_capacity`で不成立になる。譲渡は受け手の余力、交換は双方の最終携行状態を検査する。交換途中の一時的な過積載だけで拒否せず、片方でも最終状態が不成立なら全品・食料を動かさない。保管や地面へ置く操作で荷を減らせる。

今回の容量は非食料の携行枠。既存の食料所持数・食料の運搬コストとの完全共通化は未実装であり、合算重量と表示しない。

上限は世界256物体、物体ごとの最近32履歴＋総件数＋初期由来、世界の最近64操作、本人向け最近32通知。有限の記録であり、全過去の受け渡しを再構成できる保存ではない。

## 観測と操作

`item_visible`は向き・距離・遮蔽を通した地面／携帯中の物を観測する。個体向けには相対位置、見える色・大きさ・発光、操作対象のrefを渡す。他者の保管物、内部価値、過去の物体履歴や、まだ扱っていない物の正確な質量は渡さない。本人の携帯・保管物、携行量・容量は別欄にある。refは世界操作の宛先で、意味の正しい認識を保証するものではない。

光は既存の`light_fan`へ接続し、携帯者の現在位置に追従する。保管中は外から見えない。**自動収集が無くても、光の追加が既存の目印観測や移動選択に影響する可能性はある。**

| 操作 | 成立条件と結果 |
| --- | --- |
| `item_pickup` | 距離1.25以内、遮蔽のない地面の物を携帯する |
| `item_drop` | 自分の携帯物を現在地へ置く。地面では所有者なしとなる |
| `item_store` / `item_retrieve` | 拠点から距離1.25以内で、自分の物だけを保管／取り出す |
| `item_give` | 接触・聴取可能な相手へ自分の携帯物を渡す。保管物は先に取り出す |
| `item_offer` | 拠点で接触できる相手へ具体的な交換条件を提示する |
| `item_accept` / `item_decline` | 提案の宛先本人だけが受諾／拒否する |

実行者には身体のreserve>0、damage<1、strain<1が必要。LWでは1操作tickを使い、既存の休止相当の身体更新と通常代謝を通す。World API単体は身体消耗を進めず、統合ループが担当する。

交換条件は両側それぞれ最大4個の物体IDと、食料4種類の個数配列。各側の食料合計も4個まで。少なくとも一方に非食料を含み、石↔貝殻、石↔果実、複数品の組合せに対応する。個人食料倉庫との交換には種類付き食料が必要。共有食料倉庫は交換対象にしない。

提案時に相手の未公開資源を確認しない。相手が持っていない物を要求することもある。期限30秒・提案者につき未決1件。受諾時に距離・所有・双方の資源を再確認し、全条件が成立した場合だけ一括移転する。重複受諾や片側だけの支払いを防ぐ。物体の種類と食料の総数・種類別収支を維持する。

## 統合と試験用の設定経路

`item_execute!`が操作入口。`lw_day`も全`item_*`操作を実行でき、観測に`items`を追加する。通常判断への拾得接続は次節の明示フラグで有効になる。小物交換・譲渡・保管・置くことの自律候補はまだ生成しない。

実操作確認のため、`configured_paths/item_actions.jl`に`scene.configured_item_actions`を用意した。`actor / us / action`と操作条件を明示した時刻表であり、学習経路でも埋め込みMBでもない。安全・食事・既存の応答・夜間休息を優先し、そのtickに他行動が決まっていれば設定操作は見送る。通常の配置入力には時刻表を入れない。

実行結果は統合ループで`item_picked_up`等の名前になり、食料取得・帰還成功へ混入しない。既存の経路は小物操作中に保持して一時停止する。移転成功から自動的に主観的な報酬を作らない。

物体、未決交換、通知、操作receipt、履歴は日末`.jls`へ保存する。設定時刻表は同一入力から再構成する。JSONの世界要約からの別コホート移転は未対応で、物体を黙って落とさず明示的に拒否する。以前のチェックポイントは従来どおり保存済みソースで再開する。

## 探索・帰還中の任意の拾得

`decision/incidental_items.jl`が独立した子BasicLoopを持つ。通常の行動を続ける候補と、現在観測している地面の物を拾う候補を、共通の確率選択に渡す。食事・安全対応・予定休息・疲労休息・初日の設定見学・帰還後の荷下ろしなど、既存の優先処理が決まったtickでは呼び出さない。選ばれることも、見送ることもある。

候補は観測された距離1.25以内、地面、所有者なし、自分の既知の寸法枠に収まる物。相対位置・色・大きさ・発光、本人の携行量と容量だけを使い、隠れた種類ID・質量・世界全体の在庫を読まない。見た目が同じ候補はまとめ、最大8候補にする。refは実行先と重複受領の確認用で、物の意味や価値を決めるキーではない。

初期のきっかけは「未経験の見た目を手に取って確かめる」弱い値0.2。未知の拾得成功率0.5、予想費用0.002も初期仮定。これは**学習済みの有用性でも、石固有の収集欲でもなく、埋め込みの仮初期値**である。似た特徴を拾った経験が増えると新奇性の値は下がる。実行成功率・実消費は経験で更新し、身体の要求と親の慣れた方法は続行側の重みに作用する。候補が多いだけで収集の総重みを増やさない。

色と大きさ・発光の類似度を共通の`mb_metric_*`で評価する。近い携行状況で実際に試した結果が似ているかを使い、特徴への重みを更新する。隠れた正解種別を教師にしない。Hが高いほど呼び出す経験を広げる。経験128件、子の方法129件、監査64件、重複拾得確認128件に上限があり、生涯全履歴を保証するものではない。現段階では睡眠時の圧縮・他者需要学習との統合はしていない。

拾得では、親のfood/home目的、既存経路ID・辺列・進行位置・選択時の見積もりを保持する。拾得に使った操作数と実消費を既存の親・経路へ加え、次の通常操作の残差評価に含める。拾得だけでは新しい親試行を作らず、食料確保・帰還成功を報告しない。手の届く物なので移動先は変更せず、次のtickには通常選択へ戻る。同じ場面での拾得なら形成中の経路履歴も保つが、観測欠落や場面・目的の変化を架空の連続経路にはしない。

この段階は**立ち止まって拾う自由度**。離れた物まで歩いてから経路へ戻る寄り道、物を贈る・交換する理由、保管／廃棄の自律判断は別途必要。設定時刻表はテスト用に残し、上記の学習選択と混同しない。子の経験、H、RNGも日末コピーへ保存する。

## 今後の設計課題：余裕・退屈と目的外行動（保留）

2026-10-30。寄り道の動機は設計を検討してから変更する。現行の拾得接続と、以下の検討案・過去の別実験を区別する。

現行の共通選択では、拾得側BasicLoopのHが大きいと候補間のスコア差が縮まり、通常は弱い拾得候補の相対確率が上がり得る。親Hはその温度へ直接渡しておらず、`max(子H, 親H)`で経験の呼出幅に使う。身体要求・夜間圧は続行側へ寄与する。Hと拾得率の関係を分離した比較はまだ実施していない。

検討する論点:

- **問題に対応するH**：帰還の困難と拾得の予測外れなど、どの関係に生じた差かを保ち、候補を広げる範囲と用途を整理する。
- **余裕**：Hの単純な逆数にしない。身体の残量、残りの経路費用、時間的猶予から、寄り道を加えても元の目的が成立する見込みを評価できるか。習熟した経路の見積もりも材料になる。
- **退屈・新奇性**：同じ活動から得られる追加経験の乏しさ、変化への要求、新しい関係を確かめる見込みを整理する。食料確保や休息による回復の価値まで、反復というだけで下げない。
- **共通化**：拾得専用の固定タイマーや単純なH反転を先に追加せず、複数の目的・関係の予想利益と費用への接続を検討する。これらは未確定の設計案であり、新しい実装仕様ではない。

### ADHD研究を参考にする際の論点（文献確認、実装保留）

2026-10-30。個体差と環境条件の相互作用を考える資料として、以下の一次研究を確認した。ADHDを単一の「退屈係数」で再現できるという根拠ではない。診断群と質問紙による特性、子どもと成人、異なる実験課題を区別する。この表は関連する代表例の確認であり、網羅的な系統的レビューではない。

| [Barack et al., 2024](https://pmc.ncbi.nlm.nih.gov/articles/PMC10878810/) | 成人457人、8分の枯渇するベリー採取課題。移動待ち1秒／5秒。ADHD質問紙の陽性群は餌場を早く離れ、この課題では報酬率が高かった | 臨床診断による比較ではない。未知の餌場を発見する課題でもなく、移動後に資源が補充される。全体の過剰滞在が小さかった結果で、一般的な生活上の優位や進化的適応を証明しない |
| [Addicott et al., 2021（オンライン2020）](https://pmc.ncbi.nlm.nih.gov/articles/PMC8027173/) | 診断されたADHD成人26人・対照23人。報酬が変動する6選択肢課題。ADHD群は探索に分類された選択が多く、獲得点が低かった | 探索の定義はモデルが推定する最高価値以外の選択で、情報を得たい意図を直接測っていない。判断温度に有意な群差はなく、確率選択の温度だけを変えれば再現できるとはいえない |
| [Fernández-Martín et al., 2025](https://www.nature.com/articles/s41398-025-03353-z) | 7–16歳、ADHD群43人・対照47人の実待機を伴う報酬選択。遅延に応じた価値低下の形は一様でなく、複数の傾向が得られた | 小標本の探索的な分類。診断名から一つの待機・報酬パラメータを決めないための参考であり、固定の5個体型を採用する根拠ではない |

**以下はGameAI側の設計上の推論で、研究が直接実証した実装ではない。**

- 「余裕があるので他の関係を試す」と「待機や単調さの負担を減らすために行動を変える」を別の動機として検討する。寄り道を低H時だけに限定するとも、高Hで一律に増やすとも決めない。
- 元の目的の利益・遅延費用、別候補から得られる関係・情報、その場の身体余力を分けて見積もる。報酬の遅延評価、待機の負担、注意の切替、刺激内容への関心は同じ個性値に束ねず、関連するかも検証対象とする。これらの研究尺度をHやρそのものと同一視しない。
- 資源が減る環境、継続して学ぶ価値が高い環境、移動費用が高い環境を分ける。研究ごとの対象・課題が異なるので、環境だけが結果差の原因と断定せず、LW側で条件をそろえて調べる候補にする。
- 生活基盤の安定を先に進める。過去のL14B/L15A/Julia反復圧と照合する研究課題として保持し、今回は動作・係数・設定を変更しない。

## 実行

```text
node experiments/acorn_food/prepare.cjs outputs/portable-base.json
node experiments/portable_items/prepare.cjs outputs/portable-base.json outputs/portable-input.json 3
julia --startup-file=no --project=. experiments/portable_items/checks.jl
julia --startup-file=no --project=. experiments/portable_items/integration_checks.jl
julia --startup-file=no --project=. experiments/portable_items/incidental_policy_checks.jl
julia --startup-file=no --project=. experiments/portable_items/incidental_cost_checks.jl
julia --startup-file=no --project=. experiments/portable_items/incidental_integration_checks.jl
julia --startup-file=no --project=. experiments/portable_items/run.jl outputs/portable-input.json outputs/portable-placement-3d
```

配置生成は既存マップ・食料を保持し、拠点周辺の乾いた、障害物と重ならない場所へ各3個を置く。設定操作・収集フラグは入れない。`run.jl`はソース・入力・日末コピーを保存し、`scene.incidental_items`で配置のみ／任意拾得を切り替える。いずれも物と食料の保存を検査し、拾得を強制する時刻表は許可しない。

任意拾得を有効にする場合は、生成コマンドの末尾へ`incidental`を指定する：`node experiments/portable_items/prepare.cjs outputs/portable-base.json outputs/portable-incidental.json 3 incidental`。既存の配置JSONなら`scene.incidental_items=true`を明示して同じrunnerへ渡せる。

実施した検査は[実装・検査記録](../../experiments/portable_items/report.md)を参照。
