# 複合勾配による取引判断

2026-11-01。食料だけの交換と、物を含む交換・逆提案に共通の評価を接続した。

## 必要性の門から、合成評価へ

「本人が食料不足であること」「交換で本人の不足が減ること」を提案・受諾の必須条件にしない。相手も同じ不足改善条件を満たす必要はない。候補の状態変化を `trade_compound_gradient` で評価する。

| 成分 | 評価するもの |
| --- | --- |
| material | 自分の味・保有量・物への関心・学んだ交換用途。取得価値と手放す負担の差 |
| security | 自分の必要食料見積もりから、交換前後の不足がどう変わるか |
| aid | 見えている相手の困窮に対し、食料を純移転することの主観的な意味 |
| relationship | 自分の経験から想起した便益・援助経験・親しみ |
| cost | 取引の小さな初期費用 |

合計から候補を評価し、成立見込み・関係による選択の重み・共通BasicLoopの経験/H/確率選択へ渡す。物資だけで損でも、援助や関係を含めて良いと感じれば受諾できる。拒否・逆提案・通常活動継続は残る。両者はそれぞれの情報と評価で判断し、世界側は双方の同意・所有権・数量を検証する。

総合評価が−0.01未満の条件は候補にしない。これは食料不足の必須条件ではなく、既存の「明確に主観的に不利な条件を確率だけで承諾させない」許容帯である。条件が良くても必ず成立するわけではない。

## 初版の評価式と境界

必要量の見積もりは従来どおり、身体と自身のfood-security予測を使う。食料相当量も従来の換算を使う。不足を `d` とすると、安全維持成分は `0.5 × ((1+d_before)^2 − (1+d_after)^2)`。不足が深いときにさらに渡す負担が大きくなるが、絶対的な禁止条件ではない。

援助成分は、観測された困窮度、恐怖による割引、関係からの係数、純移転食料量の `log1p` を掛ける。純移転は自分が失った食料相当量の正の部分であり、同量を行き来させて援助量を水増ししない。相手の表情が観測できなければ、この成分は0。相手の身体・未来の不足・価値評価を直接読まない。

係数、困窮した相手に食料を渡すと価値を感じること、食料換算、初期の味の好みは初版の設定である。援助価値の係数そのものを学習する実装ではない。食料予測・相手との経験・交換経験・候補の学習は既存MBに接続する。表情の誤認はあり得る。

## 成立後も同じ尺度で学ぶ

選択時の自己の必要量・消化中の量・相手の観測・関係係数を保存する。成立後は実際に移転した前後の所有量を使い、同じ評価式で計算する。途中の食事や別取引を当該取引の成果に混ぜず、援助として選んだ取引を食料の減少だけで失敗に戻さない。

成立前の提案には成果を付けない。拒否・期限切れ・実行不能では移転価値0。旧チェックポイント内の保留試行で新しい評価情報を持たないものは、当初の旧評価で決着させる。

**援助成分の成立後評価も「渡せたことを自分がどう評価したか」であり、相手が実際に回復した証明ではない。** 回復の後続観測による援助効果の学習は別途必要。従来の視覚的な直接援助行動全体を、この変更で置き換えたわけではない。

## 頻度・観測・記録

2026-11-01：[所有物・観測特徴・交換前価値の判断内共有](../../experiments/portable_items/trade_preparation_day29.md)を追加。同一チェックポイントからの29日目比較で183.00→179.96秒、累積割当91.29→89.11 GB。勾配ログを含む全JSON結果が一致した。単発で約1.7%の小差であり、安定した速度倍率とはしない。

2026-11-01：続く[処理速度の検査](../../experiments/portable_items/trade_recall_speed.md)で、数量に依存しない交換記憶の照合を判断内で再利用した。評価や頻度は変更せず、制御した提案ケースで約2.3～2.7倍の局所高速化を確認した。全シミュレーションの倍率ではない。

必要性で早期終了する省略は外したが、新規提案の64秒間隔、保留中の重複提案防止、継続候補、逆提案の回数上限は維持する。性能は長期実行で再評価する必要があり、高速化したとは主張しない。物交換では同一判断中の相手・文脈の関係想起を再利用する。

要求する種類と数量は直前に接続した倉庫観測に従う。勾配ログには `compound_gradient` として各成分と前後の不足を残す。過去の `need_skipped` は保存形式の互換性のため残すが、現方式では増やさない。下位APIの旧 `require_need=false` 呼出しは受け付けるが、`true` は廃止した条件の再導入になるためエラーにする。

## 検証

`experiments/portable_items/compound_trade_checks.jl`で、余裕があるときの提案、相手の困窮による受諾の変化、自身の不足による拒否、成立後の同一評価、未成立時の価値0、二重適用防止を確認。旧 `necessity_checks.jl` はこの新仕様の検査入口へ変更した。

制御した食料交換例では、物資評価−0.1653、援助+1.0986、費用−0.002から合計+0.9313となり受諾した。物を含む例でも物資−0.3424に対して援助+1.6094、合計+1.2651となった。同じ提案でも相手の困窮観測がなければ承諾しない。これらは観測と提示条件を設定した検査で、通常マップの自然発生件数ではない。

短縮時間のLW統合試験（512秒×2日、3個体、食料機能なし、物のみ）では、自律提案25件、拒否23件、成立2件、実行不能0件。取引条件を台本で指定していない。チェックポイントからの再開で世界・個体・社会関係の結果が一致した。通常の30日・180日生存試験や性能比較はまだ行っていない。

複合勾配の専用検査127項目PASS（共通の世界検査込み378項目）。倉庫観測、食料交換方策、逆提案、数量勾配、社会関係、勾配ログの既存検査もPASS。旧仕様を前提に「不足がないなら判断しない」とした検査は、新仕様の機会・拒否・頻度検査へ更新した。社会関係による確率差の検査は、合成評価でも受諾可能な提示条件で比較し、明確な総合損失を確率で受け入れさせる検査にはしない。
