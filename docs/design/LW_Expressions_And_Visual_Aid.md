# 固定の表情と、観測からの食料援助候補

2026-10-31。食料不足による交換と、相手の困窮を見て助ける行動を分ける初版。

## 表出と観測

`configured_paths/expression.jl` の `configured_expression` は固定の表出アダプター。穏やかさ・つらさ・怯えをそれぞれ0～1で表す。つらさは低いreserve・疲労・損傷・将来食料不足の不安の最大値から出す。怯えは既存の夜間恐怖Hを0～1に写す。全員分を観測前に作るため、同じtickでの個体の実行順によって表情の取得時点を変えない。恐怖は前tickまでに更新された値を使う。

これは生理学的な表情モデルではなく、ユーザー指定の暫定的な固定表出。痩せた体形や長期栄養不足の蓄積は未実装。画面上の顔アニメーションも追加していない。

`social_sight` は既存の視野・遮蔽を通った相手のうち、全ての可視相手に粗い外見を付ける。距離4以内は0.25刻み、注視＋細かいρなら0.125刻み、それより遠方は0/1の粗い表現となる。粗い0を内面の無問題の確定と解釈しない。reserve、損傷量、食料在庫、空腹という原因ラベルは渡さない。空腹・疲労・負傷が似た表情になり、食料で助けられるという予測は間違い得る。

## 援助候補と実行

`decision/visual_aid.jl` は `social_relationships=true` の通常LWへ接続する。初版は接触可能な相手への食料援助に限定し、遠方の相手へ救助に向かう移動は作らない。

- 既存の安全・自身の食事・メッセージ応答・予定休息を先に処理する。初日の固定見学中は起動しない。
- 自身のreserveが80以上、身体が動け、自分の次の一食を残せる余裕がある場合に候補を作る。相手が既に食料を持っていると接触観測で分かる場合は追加しない。相手の倉庫や胃の中は調べない。
- 拠点外では自分の倉庫を余裕に数えず、携行食料と消化中の分で判断する。
- つらそうな表情から「食料が役立つかもしれない」という初期の重みを作り、自己の余裕・相手との関係と共に既存BasicLoopで継続候補と比較する。表情が強くても必ず援助するわけではない。怯えは、食料が役立つという初期予測を弱める。
- 手持ちに可食食料があれば渡す。手持ちが空で拠点の個人倉庫に可食食料があれば、既存のretrieveを選び、次のtickで視認・接触・自分の余裕を再確認してgiveへつなぐ。移動して見失った場合は中断する。援助用の加工・共有倉庫の取り出しは今回の対象外。
- 候補の再評価間隔は64操作秒、選択後は300操作秒の待ち時間を置く。これは固定の初期予算・頻度制限であり、学習済みの社会習慣ではない。

世界側 `communicate!` に、要求への返信を必要としない明示的な `unsolicited=true` のgiveを追加した。接触・所有食料・操作IDによる一度限りの移動を守る。架空の要求メッセージは作らない。既存の要求への応答仕様は既定のまま残す。取り出し中に同じ相手から要求が来て、既存応答がgiveを選んだ場合は、その実行で援助試行も完了できる。

## 経験・結果・制約

表情のdistress/fearを社会MBの文脈へ追加。既存の関係照合を使い、援助者は渡せた／渡せなかった結果を更新する。受け手は実際に受け取った食料の種類と自己評価を関係経験に残す。相手の価値を援助者へ共有しない。

**今回の成功判定は下位の `food_delivered`（食料を渡せた）まで。相手が回復した・空腹だった・援助が本当に役立ったという判定ではない。** 表情変化を後から観測して援助の効果や原因を学ぶ接続は未実装。疲労を空腹と取り違えて渡す場合もあり、この初期推測を学習済みと呼ばない。交換側の「両者の食料量が増える必要性」は援助には適用しない。

選択・中断・移動結果は `social_relationships[actor].visual_aid` に記録する。記録は32件まで、累積数は別途保持する。状態は日次チェックポイントに含み、出力時はBasicLoopをsnapshotへ変換する。

検査：`experiments/social_relationships/expression_checks.jl`。表情の曖昧さ・視野・遮蔽・自己食料の保護・要求なしの移動・重複防止・倉庫からの援助・収支・再開一致を確認する。

将来不足と共通観測の接続は[食料不安・注視](LW_Food_Security_And_Social_Attention.md)を参照。現在は取引・要求応答でも同じ外見観測を使う。
