# LW 経路全体を一つのMB試行として扱う

2026-10-26。確率的認識に加え、経路の選択・進行・結果を共通化する。

## 動機

直前の30日試験ではCが2日目に作った2動作の食料チャンクから974回動作を選んでいた。しかし経路の各位置を毎回検索しており、見回しだけの反復も起こる。選択回数は経路完遂回数ではなかった。

## 実装

`src/lw/learning/mb_routes.jl` が経験チャンク、睡眠仮説、覚醒時探索に共通する実行状態を持つ。同じ目的・同じ辺列には同じ経路IDを付ける。新規選択は経路の先頭から入り、選択後は辺列とカーソルを保持する。次の候補はその経路の次の辺とする。反復する観測キーがあっても途中のどこかを毎回推定し直さない。

候補選択そのものは既存の確率的選択に従う。継続の強制や慣性ボーナスは設けない。他の通常候補に切り替われば中断し、別目的・身体要求・安全制約にも従う。途中再開と経路を構成する上位MBの多段階階層化はまだ行わない。

実行された動作の次観測でカーソルを進める。一特徴などの判定不能は仮の進行であり、認識一致数とは分ける。認識矛盾・実行不能・観測喪失では試行を終了する。終端直後の食料取得は親目的の結果につなげられる。

経路終端に達しただけでは報酬を付けない。実際の親目的達成とH低下に対応した操作だけを成功・報酬として記録する。途中で目的が達成された場合も成功になるため、成功数と全辺実行数は別物。終端でも目的が未解決なら `unresolved`、別行動への切り替えは `interrupted` として分離する。

経路ごとの成功／未解決／blocked／mismatch／lostを次回候補の重みに反映する。中断だけでは失敗罰を付けない。旧チャンクの形成成功数とは別に `routes.stats` の実行結果を使う。経路統計は最大256件まで新規登録、詳細イベントは直近64件。既存の容量整理で辺が消えた経路は喪失として扱う。統計上限後の新経路は集計・詳細イベントのみとなる制約がある。

## 検証

`experiments/julia_migration/lw_integrated/mb_route_checks.jl` でカーソル進行、親目的への報酬結合、重複報酬防止、中断、実行不能、終端未解決、由来をまたぐ経路ID一致、判定不能と確認済み進行の分離、未解決による重み低下を確認する。実環境の結果は別途記録する。

## 2026-10-26更新：Hによる継続・再確認・変更

上記の即中断・即喪失方式を次の方式に更新した。前節は初版の履歴であり、以下を現行仕様とする。

- 有効な経路継続、経路を保った再確認、別候補への変更を三つの候補群として扱う。既存BasicLoopの確率選択と学習スコアを使う。
- 親目的Hと閾値の比を `h=max(1e-6,H/threshold)` とする。候補群への重みは継続1、再確認h（位置不確かな場合は1+h）、変更h。各群の候補数で割り、多数の変更候補だけで票数が増えないよう補正する。これは初期の有限な設計係数で、低H時の継続を保証する固定ロックではない。学習済み評価・現在の適合度も選択確率へ反映される。
- 観測不足、対応なし、矛盾、実行不能、記憶辺の欠落は経路を削除せず `uncertain` と理由を保持する。別行動がH選択で選ばれた時点で終了する。削除済み辺は現実行動で捏造せず、再確認または変更へ進む。
- 実行後に観測が消えた場合は実行済みの辺を保留する。再観測と予測終点の類似度が0.65以上なら仮に進行する。一特徴でも再対応は可能だが、確認済み遷移や報酬には数えない。この閾値は近似的で、別地点との誤対応は引き続きあり得る。
- 再確認では見回しを行うが、経路カーソルを直接進めない。終端到達でも目的未解決なら再確認/変更の対象となる。
- 歩行・旋回の実行だけでは親Hを下げず、既存の親目的評価に従う。再確認しても目的未解決ならHは増え、変更候補が広がる。親Hを経路ごとにリセットしたり、別の独立Hを追加したりはしない。そのため開始時から高Hなら初手から変更しやすい。
- 上位の目的変更、安全行動は優先する。候補選択外の同目的の休息・食事・連絡は経路を一時保持する。身体要求を経路継続で押さえ込まない。

`routes.uncertainty` は理由別の発生回数（同じ問題を複数tickで数える場合あり）、`controls` は実際に選んだ候補群の累計、`decisions` は直近64回のH・不確実性・群別選択確率。終了イベントにもHと理由を付ける。前版の `lost` とは定義が変わるので、単純な減少を性能改善とはしない。上位MBの一般的な再帰階層化は未実装。

## 2026-10-26更新：見積もりとの差でHを更新

経路を実行中の親目的評価を、未達成1tickごとの加算から見積もりとの差分に変更した。経路外の通常探索・身体要求はこの変更の対象外で、経路選択前に蓄積したHも自動リセットしない。

開始時に、辺数・所要操作数（食料取得は終端で1操作追加）・実行秒数・各辺の平均エネルギー消費の累積値を固定する。現在のモデルは各操作1秒なので実行秒数と操作数が等しい。休息等で経路を一時停止している壁時計時間を締切超過に数えない。移動距離からの長距離到着予測や、実測分散を学習した所要時間分布はまだ持たない。

進行位置に対して、次の1操作と1操作分の余裕を認める。操作数がその許容数を超えた差、当該進行位置までの期待消費を超えた差、実行後の認識矛盾数から逸脱量を計算する。消費差は経路の平均1操作消費（最低0.01）で量子化し、1単位の余裕を引く。時間/操作と消費と矛盾を重複加算せず、その最大値を採る。前回までに課した逸脱量の最大値を上回る分だけ親Hへ加算を要求する。親Hの上限32は維持。

見積もり内で未到着なら親Hを維持し、下位動作にも未到着だけで失敗罰を与えない。これは成功・報酬・確認済みの遷移を意味しない。実際に親目的が解決した時にHを0へ戻し、その差が報酬になる。Hがすでに0なら、目的達成は成功として経路を終了するが報酬は0。

`routes.forecast` に評価回数、逸脱0の未達成評価数、H加算要求量、直近64評価の根拠を保存する。H加算要求量は上限到達時などを含むため実際のH増分と同一ではない。終了イベントの `estimate` / `effort` で固定見積もりと実績を追跡できる。

検査は `mb_estimate_checks.jl`。途中進行でH維持・報酬なし、待ち続けると遅れ分が加算、同じ評価の二重加算防止、固定見積もり、休息を時間/消費に加算しないこと、消費超過・矛盾による加算、真の目的達成とゼロH成功を確認する。

親目的と通常探索の現行見積もりは [LW_Parent_MB_Estimation.md](LW_Parent_MB_Estimation.md) を参照。上の「経路外の通常探索は従来評価」という記述は経路単独導入時点の履歴。

## 2026-10-28: 成功経路を「深い河道」として再利用する第一段階

物理的な川ではなく、経験によって選択されやすくなった関係経路の比喩。実装は成功経路chunkの検索順と候補の重みに作用する。地形ポテンシャルを直接書き換えたり、経路へ強制吸着させたりはしない。

- 目的が一致する成功chunkの各辺の始点を、途中合流の照合候補にする。認識は既存の不確実な対応付けを使い、真の座標や物体IDは使わない。
- 照合した地点から終点までの接続済みの残り経路を、一つの経路MBとして提案する。元chunkのIDと開始位置を保持し、実行カーソルと固定見積もりは残り経路の先頭から始める。元chunkの辺列は変更しない。
- 暫定的な深さは `(log1p(successes)+log1p(reward))/(1+misses+execution_failures)`。従来の加点上限2を外し、成功で緩やかに深まり、矛盾・実行失敗で弱まる。到達確認なしの予測や途中合流だけでは成功報酬を与えない。
- 地点の検索順には、そこに接続する同目的chunkの深さの最大値を使う。多数のchunkが同じ地点を共有しても加算で票を増やさない。幾何学的一致度・認識確率の計算式自体は変更しない。
- Hに応じた検索幅の拡張、実行中の局所修正と経路保持、残差による別経路・放棄候補は既存機構を使う。固定慣性は追加しない。

低Hでは検索が狭く、似た途中地点を先に採用することもある。成功したまとまりが正しく再認識される保証ではない。始点だけを候補にしていた検査のライフサイクル用fixtureはH=8にして始点と途中地点の双方を照合する。これは低Hの正解率を保証するテストとは区別する。

新しい経路予測ニューラルモデルやNPUは未接続。多様な地点への汎化、深さの係数、過度な固定化の有無は長期行動試験で評価する。途中合流した残り経路の成功統計は、その経路IDに蓄積し、元の全経路を実行した成功と混同しない。
