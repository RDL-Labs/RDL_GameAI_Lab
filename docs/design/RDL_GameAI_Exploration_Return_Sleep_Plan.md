# L15A後続 — 探索・帰還・睡眠を数日通す初版

状態: DESIGN ONLY / 初回条件確認中。基準 `d539f86`。
現在の32秒探索は、帰還・身体としてのSleep・翌日への連続運転には未接続。
この文書は実行済みEvidenceではない。

## 問い

同じWorld・複数個体で、探索、帰還、夜間休止、記録整理、翌日の探索をつなぐと、
停止・再試行・採取・帰還未達がどう推移するか。
初版は3日を候補とし、1.5倍で運転する。探索成功や改善を必須にしない。

## 先に固定する境界

1. 探索終了で個体を拠点へ移さない。実帰還を別の有限な身体操作として行う。
2. 帰還未達と帰還成功を区別する。帰れなければその場で夜を迎える案とする。
3. 身体が休止したこと、Sleep処理を呼んだこと、候補ができたこと、採用されたことを別に記録する。
4. World位置・資源残量・採取後の在庫は日境界で初期化しない。
5. 本人の記録・既存の採用済みモデルは個体別に保持する。
6. 翌朝に更新する有限な行動枠を明示する。昼の停止や通信再送で更新しない。

## 暫定帰還の案

本人の受理済み指令と実身体結果から、実際に動いた区間を逆順にたどる。
これは取得済み身体履歴を使う初期制御であり、学習済み目印経路や最短経路とは呼ばない。
Worldの経路探索API、未観測の拠点方向、全体地図、帰還成功の強制は使わない。

移動結果が欠けた区間、姿勢対応が失効した区間、逆走時のblockedは未解決として止める。
同じ指令の逆向きが同じ場所へ戻ることは保証しない。身体の実結果を再確認する。
帰還点の推定とWorld側の実到着監査を分ける。実験者の到着判定を移動指令へ逆流させない。
帰還元は各個体が最初に取得した自身の開始断面に固定し、野外で寝た場所を自動で拠点へ改名しない。

帰還方法と3日という規模はユーザーへ確認中。既存の目印学習を要求する場合は、
この暫定方式のまま学習済み帰還と称して進めない。

## Sleepの既存実装との関係

`learned_exploration.py` のL13S日末処理には、本人の記録整理・独立Probe・採用の経路がある。
ただし現在のL15A複数個体・連続Worldと同じ入力契約ではなく、日末処理だけで実帰還や身体睡眠は成立しない。

`SleepConsolidationCoordinator` は、safeな休息地点・Sleep decision・対応する実結果・
受理済みExperienceの窓を要求する。現在の移動ログをそのままこのExperienceへ偽装しない。
帰還未達の野外休止を、Worldからsafeラベルを無条件付与して既存Sleep成功へ変換しない。

実装時には以下を別状態として扱う。

- 帰還結果：到着確認／推定のみ／blocked／対応不明／期限超過。
- 身体結果：休止開始／実休止時間／中断／完了。
- 記録整理：対象記録と出典／対象なし／入力契約不足。
- 学習：候補なし／候補あり未検査／検査済み／採用済み。

単なる夜間waitを既存Sleepの受入完了と呼ばない。
睡眠による学習差を主張する場合には、身体休止を揃えた記録整理なし対照が別途必要。

## 翌日に残すものと更新するもの

保持するものは、資源・身体の実状態、本人の過去記録、既存の採用済みモデル、
帰還結果、整理・検査・採用の出典。
更新候補は、その日の目標数、再検討回数、接近試行などの一日用の実行枠。
期間内blocked_targetsを更新する場合も、前日の停止理由を記録から消さない。
疲労は日境界でゼロにせず、実休止結果に基づく回復を使う。

## 見る結果

日ごと・個体ごとに、探索/帰還/休止時間、採取量、訪れた資源、移動距離、
逆旋回停止、同じ対象への再突入、帰還到達、野外での休止、翌日の初手、
引継ぎモデル参照を残す。
日数やseedだけで動きが変わった場合と、記憶や採用済みモデルによる差を混同しない。

まず帰還・休止・翌日という実行境界を受け入れ、その後にSleepによる行動差を評価する。
