# L15A後続 — 探索・帰還・睡眠を数日通す初版

状態: DESIGN ONLY / 帰還は目印基準に固定。基準 `d539f86`。
現在の32秒探索は、帰還・身体としてのSleep・翌日への連続運転には未接続。
この文書は実行済みEvidenceではない。

## 問い

同じWorld・複数個体で、探索、帰還、夜間休止、記録整理、翌日の探索をつなぐと、
停止・再試行・採取・帰還未達がどう推移するか。
初版は3日を候補とし、1.5倍で運転する。探索成功や改善を必須にしない。

## 先に固定する境界

1. 探索終了で個体を拠点へ移さない。実帰還を別の有限な身体操作として行う。
2. 帰還未達と帰還成功を区別する。帰れなければその場で夜を迎える案とする。
3. 身体が休止したこと、Sleep処理を呼んだこと、候補ができたこと、採用されたことを別に記録する。
4. World位置・資源残量・採取後の在庫は日境界で初期化しない。
5. 本人の記録・既存の採用済みモデルは個体別に保持する。
6. 翌朝に更新する有限な行動枠を明示する。昼の停止や通信再送で更新しない。

## 目印による帰還

ユーザー指定により、帰還は本人が観測・記憶した目印を基準とする。
迷子・誤対応・帰還未達を許容する。実移動履歴の逆再生は採用しない。
Worldの経路探索API、未観測の拠点方向、全体地図、帰還成功の強制は使わない。

既存の目印観測は、有限な視野内の粗い色・方向区間・距離帯を返す。
`patch`参照は各frame内の参照であり、別frameの同じ参照文字列を同一物体IDとして使わない。
同じ外観の木や岩が複数あれば対応は曖昧になり得る。実験者の対象IDで解消しない。

初版で必要なのは、開始地点で取得した目印の組と、探索中に再観測した目印の記録を
本人別に保持し、帰還時の現在観測と照合する経路である。
身体の実結果は直前の観測との姿勢対応に使えるが、それを逆走指令列へ変換しない。
記録には取得時刻・姿勢・外観・coverage・元観測参照を保持し、未観測区間を補完しない。

帰還先の選択は現在見える対応候補から行う。候補がない、複数あって決められない、
取得が不完全、対応が失効した場合を別々に残す。
有限な見回しで追加観測しても決まらなければ、帰還未達としてその場で夜を迎える。
帰還用の取得・操作枠は明示的に有限化し、迷子を理由に無制限に更新しない。

本人の「開始地点らしい」という再認と、World側の実到着監査を分ける。
似た目印による誤再認も記録する。実験者の到着判定を移動指令へ逆流させない。
野外で寝た場所を自動で元の拠点へ改名しない。

最初の比較には、目印が再取得できる条件、似た目印で曖昧になる条件、
目印が見えなくなる条件を含める。帰還率100%を受入条件にはしない。
現行の `LandmarkExplorationDay` は一時的な目印への接近制御であり、
複数日の帰還用目印記憶が実装済みという意味ではない。

## 拠点の目印：遠くから見えやすい塔

初期Worldでは拠点に高めの塔を置き、周囲の木や岩から区別しやすい外観を持たせる。
出発時に本人が取得した塔と周辺の見え方を、帰還時の照合材料にする。
塔は帰還の手掛かりであり、塔のWorld ID・正確な座標・常時取得できる拠点方位を渡さない。

「高いので見えやすい」はWorld配置と実際の観測で成立させる。
現行の目印センサーは水平fanであり、塔を高くするだけでは、手前の遮蔽物の上に出た
塔上部を観測できるとは限らない。実装時に有限な上向き取得が必要かを確認し、
取得範囲・距離・遮蔽・予算を明示する。塔専用の透視や距離無制限の検出は行わない。

見えている塔の対応候補へ向かえる場合、遮蔽・視界外・距離外で見失う場合、
似た外観によって誤対応する場合を区別する。塔が見えることと、そこまで通行可能なことも分ける。
到達時は塔への接近と拠点の再認を記録し、帰還未達や誤再認も実験結果に残す。

## Sleepの既存実装との関係

`learned_exploration.py` のL13S日末処理には、本人の記録整理・独立Probe・採用の経路がある。
ただし現在のL15A複数個体・連続Worldと同じ入力契約ではなく、日末処理だけで実帰還や身体睡眠は成立しない。

`SleepConsolidationCoordinator` は、safeな休息地点・Sleep decision・対応する実結果・
受理済みExperienceの窓を要求する。現在の移動ログをそのままこのExperienceへ偽装しない。
帰還未達の野外休止を、Worldからsafeラベルを無条件付与して既存Sleep成功へ変換しない。

実装時には以下を別状態として扱う。

- 帰還結果：到着確認／推定のみ／blocked／対応不明／期限超過。
- 身体結果：休止開始／実休止時間／中断／完了。
- 記録整理：対象記録と出典／対象なし／入力契約不足。
- 学習：候補なし／候補あり未検査／検査済み／採用済み。

単なる夜間waitを既存Sleepの受入完了と呼ばない。
睡眠による学習差を主張する場合には、身体休止を揃えた記録整理なし対照が別途必要。

## 翌日に残すものと更新するもの

保持するものは、資源・身体の実状態、本人の過去記録、既存の採用済みモデル、
帰還結果、整理・検査・採用の出典。
更新候補は、その日の目標数、再検討回数、接近試行などの一日用の実行枠。
期間内blocked_targetsを更新する場合も、前日の停止理由を記録から消さない。
疲労は日境界でゼロにせず、実休止結果に基づく回復を使う。

## 見る結果

日ごと・個体ごとに、探索/帰還/休止時間、採取量、訪れた資源、移動距離、
逆旋回停止、同じ対象への再突入、帰還到達、野外での休止、翌日の初手、
引継ぎモデル参照を残す。
日数やseedだけで動きが変わった場合と、記憶や採用済みモデルによる差を混同しない。

まず帰還・休止・翌日という実行境界を受け入れ、その後にSleepによる行動差を評価する。
