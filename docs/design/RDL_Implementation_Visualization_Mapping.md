# RDL用語と実装と可視化の対応設計

状態: **DESIGN ONLY / 共通スキーマ・可視化UIは未実装**  
作成: 2026-10-12  
照合基準: GameAI `388c652`、[Core意味論参照](../semantic-reference/RDL_Core_T0_T1_reference.md)
`86a0d4f3`（BASE v2.3.1 / SPEC v2.5）。

RDLの抽象度を保ちながら、実装の状態と変化を追える対応を定める。
**Bは「境界」であり、目的そのものではない。** 目的・問いは、その境界を設定し、
何について評価するかを具体化する条件として分ける。GameAIの行動語彙を共通層へ
埋め込まず、将来の植物・地形などの記述にも使える構成を目指す。

これはCoreの定義変更でも、既存変数の一括改名でもない。
Julia移植と可視化の設計指針であり、新しい更新式・行動権限を導入しない。

## 1. 境界を共通の入口にする

Bは、観測・認識・記述・操作のための有限な選択枠組みである。
空間の外周だけでなく、関係の範囲、時間断面、比較次元、作用条件などを含み得る。
物理的な身体境界、所有境界、コミュニティー境界を、常に同じBとみなすわけではない。

- **B:** どの範囲・関係・条件を扱うか。
- **目的・問い:** その境界で何を記述・比較・操作するか。
- **M_B:** その境界のもとで保持する有限な関係拘束構造。

共通データに「食料確保」や生物学的な主体の目的を必須項目として埋め込まない。
ただし、比較の用途・問いを省略してよいという意味ではない。非生物系では、
モデルを構成する観測者が設定する問いと、系自身に仮定する機能を区別する。
植物や地形に意識的な目的を付与せずに有限なモデルを記述できる。

複数のBは重なってよく、常に木構造とは限らない。
親子M_BはGameAI側の構成として表現できるが、包含・参照・作用・競合の関係を
すべて「親子」に圧縮しない。表示上の階層と計算上の依存関係も分ける。

## 2. 用語と記録と表示の対応

以下の「記録」は共通化の提案であり、既存フィールドとの自動対応ではない。

| 用語 | 保持したい記録 | 可視化で確認すること |
| --- | --- | --- |
| B | 境界参照・版、選択条件、時間断面、関係・比較次元 | 何を含め、何を対象外としたか |
| SILN | 当該境界で扱う構造の参照と適用条件 | どの構造を一つのまとまりとして扱うか |
| RIB_B | 有限作用断面の出典、取得条件、coverage、時刻 | 実際に取得できた作用側の材料 |
| M_B | 構造参照・版、関係拘束、保持・採用の根拠 | どの構造を保持し、今どれを使用したか |
| F / F' | 同じ更新前M_Bによる解釈、比較条件、前後の出典 | 何と何を対応させたか |
| E | 比較対象・次元・差、比較規則 | 何についてどの差が現れたか |
| H | 評価済みの未解消残存、出典、吸収・解消の履歴 | 何が残り、なぜ残っているか |
| θ | 保持限界の規則・評価値・条件 | 維持／局所更新と再編の判定境界 |
| M_Δ / M_B' | 再編入場、検査・選別・再構成、更新先の参照 | 再編がどこまで進み、何へ復帰したか |
| ρ_B | B内部の区別の細かさと版、変更根拠 | 同じ境界で何を細かく／粗く区別しているか |
| ξ | 有限境界に伴う未回収関係という留保 | 取得済み断面を全体と誤認していないか |

Eの共通名は「差」。現行Core参照の比較条件は維持する。
同じ更新前M_Bで形成したFとF'を比較し、モデル更新を途中へ挿入しない。
欠測・比較不能・Worldの変化・直接の快不快を自動的にEへ変換しない。
HはEの全量や全履歴の単純和ではなく、吸収・解消されなかった残存である。
θ超過だけで新しいM_Bが生成済みになるわけではない。

ξは未観測セル数や乱数の大きさとして表示しない。
coverageの不足は測定可能な取得状態として別表示する。

## 3. 実装上の三つの区分

共通の名称を使う前に、各フィールドへ意味の区分と対応根拠を付ける。

| 区分案 | 例 | 表示上の扱い |
| --- | --- | --- |
| `core_bound` | 既存canonical経路で条件を満たすE/H、T1の記録 | Core参照・契約・出典を表示 |
| `gameai_local` | 目的／方法の局所H、切替閾値、警戒や反復の残存 | 局所規則名を添え、canonicalと区別 |
| `world_body` | 座標、資源stock、reserve、burst、strain、抵抗 | World／身体値として単位・proxyを表示 |

このタグは将来の設計案であり、付けるだけで意味適合を保証しない。
既存のcost・疲労・蓄積値を名前だけE/Hへ変えない。例えば、候補のエネルギーcostは
選択への評価寄与であり、それだけではCore EでもHでもない。
局所閾値による方法切替を、T1再構成やcanonical M_Δへの入場と呼ばない。

異なる境界・単位・規則のHは、表示のためにも無条件で合算しない。
親子間に寄与を渡す場合は、投影規則と同じ経験の二重計上を避ける条件を示す。

## 4. 場としての表示と関係構造

M_Bの関係拘束を、現在候補への評価寄与として投影すれば、場として表示できる。
ただし、**場の図はM_B全体そのものではなく、あるB・時刻・問いでの投影**である。
地形上のヒートマップだけでなく、関係グラフ、候補間の比較、時間推移を使い分ける。

例として、食料確保の下に探索・接近・採取がある場合、現在選択された方法だけでなく、
利用可能だった候補、拘束によって除外された候補、比較不能だった候補を区別する。
同点、寄与の相殺、未知、物理的実行不能を同じゼロ色にしない。

World全体を表示する実験者画面と、個体が取得した断面の画面を分ける。
表示用の全体地図や正解を個体の判断入力へ戻さない。

## 5. 生物と地形への拡張例

以下は未実装の適用例。共通の記述形式を使えても、更新方程式が同じとは限らない。

| 系 | 境界の例 | 各系で別途定めるもの |
| --- | --- | --- |
| GameAI個体 | 本人の取得範囲、身体条件、食料確保に関する有限関係 | 経験採用、目的／方法選択、身体作用の権限 |
| 植物 | 局所の光・水・根・葉の関係と時間断面 | 成長・吸収・資源収支、何を差として比較するか |
| 地形と水流 | 流域の一部、地表・流量・侵食の有限関係 | 流量・土砂の収支、境界での流入出、更新則 |

Worldのモデル規則、World状態の更新、個体が保持するM_Bを分ける。
植物・地形のモデルを作っただけで、自己学習やT1を実装したとはしない。
[2.5D SILN World計画](RDL_GameAI_25D_SILN_World_Plan.md)の責務分離を継承する。

## 6. 全体を計算しないための境界と解像度

すべての相互作用を同じ細かさ・頻度で直接計算することを目標にしない。
広い記述可能性と、各時点で実行する有限な計算を分ける。

| 操作 | 変えるもの | 区別すべきこと |
| --- | --- | --- |
| Bの変更 | 扱う関係や断面の範囲・条件 | 単なる詳細化と同一ではない |
| ρ_Bの変更 | 同じB内部の区別の細かさ | Float精度や画面解像度だけではない |
| 更新周期の変更 | いつ計算するか | 自動的にρ変更と呼ばない |
| 参照・計算の省略 | どの既知結果を再利用するか | 観測の追加や新しい知識獲得ではない |

植物の成長は粗い周期、接触や目前の身体作用は細かい周期、といった構成は候補になる。
ただし安全性や速度向上の保証ではない。省略中の重要な作用、境界間の交換、古い値の
有効期限、収支、詳細化の起動条件を各系で検証する。細分化だけで未知情報を作らない。

## 7. Julia移植と可視化への適用順

1. 既存の各経路について、実装変数・契約・Core対応・局所近似を棚卸しする。
2. 名前を揃える前に、同一入力に対する状態更新と選択の同等性を検査する。
3. 境界／モデル参照と版、取得・比較・受理の時刻、評価規則、遷移理由を結び付ける。
4. 同じ記録から、個体断面・関係グラフ・場・遷移時系列を読み取り専用で表示する。

表示用のレコード案は、`boundary_ref / boundary_revision / model_ref / model_revision /
semantic_scope / rule_ref / source_refs / capture_time / evaluation_time / transition_reason`。
Purposeや問い、比較可能性、単位は該当する評価記録で明示する。
生物固有の`agent_id`をすべての系へ必須化せず、構造・観測者・操作主体の参照を分ける。

常時の巨大なsnapshot出力を必須にしない。境界・モデル・評価状態の変化時に出典付きの
記録を残す案とし、完全再生に必要な記録とは別契約にする。ログを削ることと、本人の
記憶や計算状態を削ることを混ぜない。

現時点の[ALL Julia A0](../../experiments/julia_migration/all_loop/report.md)は、幾何・身体・
有限候補評価の最小ループである。本書の共通対応、M_B/E/H/θ、Sleep、社会関係の
移植はまだ含まない。今回の文書追加で実装状態やCore参照点は変えない。

## 8. 対応を実装する際の受入条件

- 表示したBとM_Bの版から、実際の比較条件・出典へたどれる。
- Core準拠と局所近似、World真値と個体観測を識別できる。
- 比較不能・未取得・ゼロの差・未解消なしを混同しない。
- 表示やログの有無で、判断・身体作用・学習状態が変わらない。
- 境界／解像度／更新周期の変更理由を別々に追え、変更だけでHを消さない。
- 非生物系の記述に、意識・食料目的・個体の行動権限を必須としない。
