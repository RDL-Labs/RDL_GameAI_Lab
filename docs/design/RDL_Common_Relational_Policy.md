# 共通実装方針：関係拘束の強さを頼りに世界を渡る

2026-10-28。ユーザーとの反復した設計確認を、今後の実装・レビューの注意事項としてまとめる。GameAIの開発方針であり、RDL Core定義の改訂ではない。既存コードすべてがこの方針へ移行済みという意味ではない。

## 基本

**個体は正解を照合して世界を渡るのではなく、観測と経験から生じた関係拘束の強さを頼りに予測し、行動し、結果から関係を更新する。**

「らしさ」は見た目だけ生物的な行動を足すことでも、設計者が想定した正解行動への近さでもない。経験・現在条件・関係の強弱によって、認識と選択が持続し、変化する仕組みを指す。誤認や失敗も通常の過程として扱う。

この方針は場所、目印、経路、食料、他者、目的達成の認識に共通する。問題のたびに専用の正解判定や強制行動を追加して解決する方向へ戻さない。

## 共通の流れ

観測 → 関係するMBの想起 → 予測と候補の重みづけ → 行動 → 結果との照合 → 関係の更新。

- 強い関係を優先して呼び出す。絶対的な採用保証にはしない。
- 部分的な一致でも候補になり得る。完全一致、不一致の二択だけに閉じない。
- ρは何をどれだけ区別するか、感度は捉えた差への反応の強さとして分ける。固定感度という現在の個性設定を、この文書だけで学習対象へ変えない。
- Hは単なる未到着回数ではなく、見積もりに対して吸収できず残る差に対応させる。Hに応じた候補拡張・再検討を共通の仕組みとして用いる。
- 行動後の観測が予測と合えば関係を強め、外れれば再検討・更新へつなぐ。誤認から戻れるようにする。
- H増分0、許容範囲内、観測不足、目的達成を同一視しない。数値の0を禁止する必要はない。

具体的な更新式・重み・許容幅は実験で定める。この文書は万能な単一式や全候補の常時総当たりを要求しない。

## 同じ議論へ戻らないための注意

### 局所の成功は、その目的の範囲で評価する（2026-11-03）

上位目的を保持することと、成立しなくなった実行計画・見積もりを保持し続けることは
別である。観測から計画の前提が崩れた場合は、旧計画を未達として残し、別の目的・
見積もりを持つ実行計画へ切り替える。親の累積費用は残し、新計画へ旧計画の期限切れや
残差を無条件に引き継がない。新計画も実際に残っている時間・身体資源の制約に従う。

子の成功を、親の成功・完了・H解消・休止へ無条件に昇格させない。
帰還できたことは帰還の成功、食料を取得したことは取得の成功であり、
「取得した食料を持ち帰る」という親目的には、その目的自身の成立証拠が必要。
子の成功は親の予測や候補の材料にはなるが、成否をそのままコピーしない。
結果の記録だけでなく、計画を閉じる制御と停止条件も同じ範囲を守る。
局所修正・空帰還で親の開始時刻、固定見積もり、期限、累積費用をリセットしない。
休息の必要性・備蓄の余裕による中断は別の選択であり、成功の代用にしない。

今回の適用・検査範囲は日次食料確保、帰還段階、終了後の固定認知停止。
他の全MB階層を一括で検証済みという意味ではない。備蓄予測・食料不安から
一日休む候補を選ぶ接続は、次の独立した課題として残す。

### 局所観測用の固定設定を一般原理にしない（2026-11-03）

特定の機構を切り分けて観測するための目的・期限・段階・初期の選好は、
局所観測用の固定設定（設定経路）として明記する。例えば日次の食料持ち帰りは
実験条件であり、「あらゆる目的が一日で拠点へ戻る」という共通規則ではない。
共通化するのは関係からの候補構成、見積もり、親の経過・費用保持、Hによる
再検討、全体と部分を分けた経験更新である。固定設定下の結果と汎用性を区別し、
未抽出の固定値も明記する。詳細は[設定経路の区分](RDL_Configured_Paths.md)を参照。

### 強い関係で足りる間は内部を展開しない（2026-11-02）

目的に関係するMBを強い順に呼び出し、現在の観測と行動候補を支えられる間は弱い関係の詳細を読まない。不十分なら次の束を開き、Hが高い場合は最初から広い束を読む。「問題なし」は暫定的な予測上の評価であり、目的達成や正しい認識を保証しない。

初回接続は移動の`goal_cues`。目的別の成功経路端点を深さ／(1+費用)順に並べた派生索引を既存の64秒更新・成功報酬更新境界で保持する。呼出しのたびに全端点の観測特徴を比較・再ソートしない。開いた候補だけ現在の照合経験を読み、既存の照合重み0.25とHによる束幅を使う。似ていても有効な歩行経路・現在の目印候補に接続しなければ次へ広げる。削除済みノード・辺・経路は採用しない。

索引の強さは更新間隔内では近似であり、現在の認識や所有・衝突の正解ではない。順序変更による行動差を許容する。通常の覚醒経路探索、全社会評価、MBの階層的要約への全面適用は未実装。`recognition.retrieval.records`の`ordered_retrieval`、`eligible`（索引掲載数）、`examined`（開いた件数）で削減を確認する。速度改善は別途実測する。

### 移動・交換を共通の関係勾配として扱う（2026-10-30追記）

**移動と交換は、関係拘束から現在の状態での勾配を見積もり、状態を変える候補を選び、結果から更新する共通の仕組みへまとめていく。** 分野ごとに独立した選択・学習規則を増やすより、既存の予測・確率選択・H・ρ・経験更新を共通化する。

| 共通の役割 | 移動 | 交換 |
| --- | --- | --- |
| 変える状態 | 位置・向き | 提示する物の組み合わせ・数量 |
| 目的への作用 | 目的地へ近づく見込み | 欲しい物や満足を得る見込み |
| 対抗する作用 | 障害物・消費・危険 | 手放す負担・作業費用・不成立の見込み |
| 局所修正 | 移動方向や歩幅を変える | 対価を追加・削減・交換する |
| 結果との照合 | 予測した接近・到着と実績 | 予測した応答・取得・満足と実績 |

ここでの勾配は「どの変化がどれだけ選ばれやすいか」を表す。物の種類や数量が離散的でも、隣接する候補の予測差として扱える。全分野を滑らかな関数や同一の数式へ無理に変換する必要はない。分野固有の観測・作用・実行制約を受け渡す部分と、予測・選択・更新の共通部分を分離する。

**数量は関係の勾配を変える変数として扱う。** 「石1個と食料2個」「石1個と食料3個」を互いに無関係な正解表にせず、同じ物同士の関係を想起し、今回の数量・在庫・身体状態から作用を見積もる。受け取る量が増える作用と、渡す量が増える負担は区別する。量の作用は比例に固定せず、飽和や必要度による変化も扱えるようにする。

数量による作用の強さと、経験を重ねたことによる予測の確かさも別に保持する。大量に交換した1回を、多数の独立した成功経験として数えない。具体的な数量は経験と世界の収支に残し、数量の完全一致を想起の必須条件にしない。

候補の予測変化・費用・不確実性から重みを作り、共通の確率選択へ渡す。予測から外れた未吸収分がHとなり、別方向や別条件への候補拡張・再検討につながる。未到着や未合意だけで毎回Hを加算しない。ρは位置や数量などをどの粒度で比較するかに関わり、差への感度とは分離する。

交換相手も独自の関係勾配を持つ。こちらの評価が改善しても相手の受諾は保証されない。相手の勾配は観測・提案・応答から推測し、非公開の評価値や在庫を直接読まない。移動の衝突判定と同様に、交換の同意・所有権・正確な数量収支は世界側で厳密に守る。

実装は、関係の想起 → 状態変化の候補 → 予測と費用 → 選択 → 実行結果 → 経験更新の境界を揃え、移動と交換の両方で検証しながらまとめる。**これは共通化の設計方針であり、現在すでに同じ評価器・候補生成器を使っているという宣言ではない。** 交換の現状と移行箇所は[交換経験による物同士の関係](LW_Item_Exchange_Relations.md)に記載する。

2026-10-30実装追記：移動のρによる局所方向修正と、物を含む交換の数量条件修正が、`relational_transition` と `relational_best` を共用するようになった。数量を関係キーから分離し、数量への応答を経験更新する。分野固有の効用・候補生成・実行制約は残り、全機能の統合済みを意味しない。

### 局所専用の正解判定へ戻さない

経路への合流を例にすると、「所定の地点で共通特徴2件、一致度0.65を満たしたら接続」という門だけでは、関係の強さに応じて進みながら確かめる過程を表せない。閾値を少し下げるだけで共通化したとはしない。

目指すのは、見覚えから成功経路が候補になり、部分的な一致から暫定的に利用し、その先の予測との整合によって利用の重みが変わる構成である。ただし、実際に経路へ接触しているのか、内部の進行判断だけが先行しているのかは診断で分ける。調査なしに全てを照合閾値の問題と決めつけない。

拠点や食料についても、内部で「達成したらしい」と判断することと、世界で実際に取得・到着・休息が成立したことは分ける。個体へ正解ラベルや未観測の座標を渡して誘導しない。誤認を許すことを、架空の取得や成功報告を許すことにしない。

## 世界の整合性と個体の認識は別

2026-11-01：[取引の複合勾配](LW_Compound_Trade_Gradient.md)を接続。不足改善を双方の必須条件にせず、物の価値・自分の将来不足・観測した困窮への援助・相手との関係を合成する。援助的な条件も専用の強制承諾ルールを作らず、この同じ評価から選ぶ。成立後も同じ尺度で学ぶが、相手の回復を確認したこととは区別する。

2026-11-01：初版の[倉庫観測](LW_Open_Stores.md)を接続。拠点内では個人倉庫を公開された観測として見られる設定経路を設け、交換の要求を観測した種類・数量へ制限する。相手の評価や内的必要度を公開するものではない。精密な視覚や知識形成が完成した扱いにはしない。

世界側の衝突、有限資源、二重取得防止、身体作用、操作ID、通信の重複排除などは厳密に扱える。認識を確率的にするために、世界の収支まで曖昧にする必要はない。

数値安定性、身体の実行可能性、計算予算などに必要な境界も排除しない。ただし、その境界を「個体が正解を知っている」という意味へ流用しない。確率的な認識も、根拠のない一様乱数選択を意味しない。

テスト用の固定見学・日次目標などは、[設定経路](RDL_Configured_Paths.md)として目的・適用範囲を明記する。埋め込みMB、経験から形成した関係、暫定的な試験用処理を混同しない。

## 実装・レビュー時の確認

1. その認識・選択は、個体が得た情報と経験に依存しているか。世界の正解を直接渡していないか。
2. 既存の照合、関係の強さ、予測、H、ρへ接続できるか。局所専用の合否判定を足していないか。
3. 部分一致・誤認・予測外れから、継続や見直しへ移れるか。固定成功や永久拘束になっていないか。
4. 強い関係と弱い関係、似た場面と異なる場面、予測どおりと予測外れで、重みや行動がどう変わるか。成功率だけでなく関係への応答を確認したか。
5. 厳密な世界制約と、個体の暫定的な判断を区別したか。必要な設定経路・未移行箇所は明記したか。
6. 移動・交換などで共通化できる予測・選択・更新を重複実装していないか。数量による勾配変化と、経験回数による確信の更新を混同していないか。

これは新たな承認手続きを追加するものではない。通常の実装判断とレビューの基準とする。既存挙動との完全一致は必須にせず、変更した意味、経験への応答、費用、未検証範囲を報告する。

## 関連

### 他者関係のρによる詳細化（2026-11-02）

LWの`scene.social_peer_rho`（既定true、falseで比較可能）を接続。物を含む交換と食料専用交換は、現在観測された接触相手から共通の`social_peer_scope!`で詳細検討する相手を選び、その相手について候補・社会MB評価を展開する。低ρでは最大2人、高ρでは観測範囲の全員まで広げる。残りは件数として保留し、個々の記憶を消去・統合しない。

初版の制御は`ρ=1-exp(-(H/8)^2-4p^2)`。pは自身の予測食料不足を4食単位で正規化した値と、観測した相手の困窮・恐怖表情の最大値。ρは個別化の度合い、Hと必要度はその制御入力であり同一概念ではない。係数と最低2人は試験用の初期設定。

相手ごとの観測済み接触時間・交換経験・受けた援助・現在見える表情から、軽い重みを作り非復元抽選する。未知の相手にも正の初期重みを残す。強い関係は注目されやすいが、取引価値の高さや採用を保証しない。抽選は既存の個体・目的別RNGを使用し、選ばれた後の候補順序は元の相手順を保つ。届いた提案の応答・逆提案はこの抽選を通さず、1日1回の自発開始制限も維持する。

これは候補展開前の認知的詳細化を近似する第一段階で、全員の幾何観測・関係更新・援助判断の間引きはまだ行わない。低ρの集団MBを学習する機能も未実装。`social_relationships.*.peer_resolution`に対象数・詳細化数・保留数と直近64件のρ・H・相手を保存する。行動変化を伴うため、性能改善と長期生存への効果は別途実験で評価する。

### 所有物の目的別・間欠観測（2026-11-02試験）

`scene.item_attention=true`で、所有物の詳細観測を毎tickの一括作成から、交換・拾得の判断機会へ移す。既定はfalseで従来比較を残す。移動・障害物・食料・他者の表情の観測周期は今回変更しない。

- 交換：既存の交換検討間隔と未解決提案を確認し、検討が必要なときだけ現在の所有物・公開倉庫を詳しく見る。接触可能な相手から届いた提案は待機中でも確認する。応答・成立通知は毎tick受け取り、観測の省略で学習が止まらない。
- 拾得：判断機会に粗い周辺確認を行い、遮蔽・向きを満たす地上の物を「なし／少数／多数」で捉える。3件で走査を打ち切り、特徴辞書を作らない。物があれば手の届く範囲だけ詳細化する。粗い観測は対象IDや位置を記憶へ与えない。
- 初版の周期はシミュレーション秒で `clamp(16*(1+身体等の緊急度)/(1+H/8),2,32)`。これは試験用の固定設定で、生理学的定数や学習された注視方策ではない。Hによる再確認と身体の緊急度による寄り道抑制を分ける。
- 観測省略は不在や失敗の証拠としない。過去の詳細一覧を現在の実行可能対象として再利用しない。観測履歴の予測・ρの連続制御・対象への学習された注意配分・倉庫数量の概数化は未接続。全認知を統一した完成形ではなく、所有物観測に限定した第一段階である。
- 所有権・有限数量・持ち運び容量・遮蔽等の世界側検査は維持する。注意の統計は個体の`attention`として日次出力・チェックポイントに残す。

実験では行動や学習結果の変化を許容し、観測回数・交換・生存・処理時間を評価する。機械的な軽量化のような完全一致を合格条件にしない。
