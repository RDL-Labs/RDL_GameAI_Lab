# 共通実装方針：関係拘束の強さを頼りに世界を渡る

2026-10-28。ユーザーとの反復した設計確認を、今後の実装・レビューの注意事項としてまとめる。GameAIの開発方針であり、RDL Core定義の改訂ではない。既存コードすべてがこの方針へ移行済みという意味ではない。

## プロジェクトの目的：人同士の関係が絡み合う過程を楽しむ

2026-11-06。プロジェクト全体の目的として明記する。

**目指すのは、人同士の関係が経験によって生まれ、複雑に絡み合い、変わっていく過程を観察して楽しめる世界である。生活できることは、そのための土台であり、最終ゴールではない。**

食料を集め、帰還し、食べ、休み、長く生きる仕組みは、個体が経験を重ねる時間と場所を作る。
生活の安定性を整える作業は必要だが、生存率や採取効率だけでプロジェクトの達成を評価しない。
安定した生活の先にも、欲しいもの、好み、関心、相手との経験によって行動が変わる余地を残す。

### 世界の豊かさが関係を生む理由になる

味・食材・加工技能・品質・備蓄・所有物・場所・野生動物は、他者と関わる理由や状況を生む材料である。
例えば、欲しい食材を持つ相手、好みの料理を作る相手、困ったときに助けてくれた相手では、
同じ人の見え方や、その人へ向かう行動が変わり得る。物と物、場所と目的の関係が、人への関係にもつながる。
これらは将来の設計例であり、加工依頼などが全て実装済みという意味ではない。

「世界を豊かにする」は、特徴や行動を無制限に増やすことではない。
その追加がどんな要求差、役割、出会い、やり取り、経験の違いを生むかを考える。
生存に必須でない物や行為にも意味が生まれる余地は持たせるが、交換や交流を必ず発生させるために
必要性・好意・対立を強制しない。関わる理由がないときに何も起きないことも許容する。

### 関係は各個体の側から生まれる

人間関係は、作者が定めた関係図や一つの共通評価を配るのではなく、観測・予測・行動・結果の経験から更新する。
同じ交換でも、双方の好み・備蓄・身体状態・過去の経験によって、有利不利や援助の受け取り方は異なる。
Aから見たBと、Bから見たAが一致する必要はない。誤解、部分的な理解、期待外れも関係の変化に含める。
援助、交換、協力、警戒、回避などが互いに影響する可能性を持たせるが、それぞれを必須の展開にはしない。

人・動物・物への注意も、共通の入口を使う。
**注意が向く → 観測する → 関係するMBを想起する → 現在の要求や目的と合わせて選ぶ → 経験で更新する。**
動いたことだけで逃げたり、見えた相手に必ず話しかけたりはしない。
兎を食べられると知っているか、人に助けてもらった経験があるかなどで、同じ観測から違う候補が生まれる設計を目指す。

### 実験と観察で確かめたいこと

- 身体・資源・帰還・睡眠が成立しているかは、生活基盤の検証として測る。
- 誰が、誰に、何を求め、どの経験を経て接近・援助・交換・拒否・回避を変えたかを追えるようにする。
- 関係の履歴が、その後の選択に実際に作用したかを確かめる。接触回数や取引成立数だけを成果にしない。
- 複数の要求や相手への関係が重なったときの変化を観察する。面白さを単一の数値へ固定しない。
- 観察者が見られる世界の真の状態と、各個体が知る・予測する内容を区別する。
  記録は個体の選択を追う材料であり、未実装の理解や内面を説明で補わない。

現在の生活・性能改善は、この目的を支える基礎作業として位置づける。
2026-11-06時点の兎接続は動体による注意・外見観測までで、外見から危険や食料としての関係を評価する接続は未実装。
この方針の文書化は、全機能の接続完了を宣言するものでも、ただちに社会機能を一括追加する指示でもない。

## 援助の資源条件と相手予測（2026-11-06）

援助要請では、公開倉庫観測から得た食料種類・数量・劣化した外見と、
手持ちの有無・表情を同じ相手MBの文脈へ渡す。相手の内部備蓄目標や不安値は読まない。
倉庫は既存の `open_stores` 暫定公開設定（既定true、拠点でのみ観測）を継続し、
視認や会話による把握を実装済みと扱わない。設定OFFや拠点外は未観測でありゼロではない。
観測を更新するたびに資源文脈を置換する。古い観測を別の交流文脈へ自動注入しない。

資源可用性・表情からの留保の初期仮説と、過去の援助応答から学んだ関係予測を
候補の重みと結果予測へ接続する。観測された可食備蓄ゼロかつ手持ちなしは、
今回の即時援助計画の候補にならない。生素材の加工後援助は未実装。
承諾・拒否の記録にも要請時の同じ資源文脈を保持し、共通の類似照合・学習へ渡す。

受け手が通常の応答選択で援助を選んだときだけ、手持ちが空なら可食備蓄を
通常の `retrieve` で1個取り出し、次に `give` する短い計画を保持する。
接触喪失・期限切れは中断、食料が取り出せなかった場合は拒否する。
帰還後認知停止の既存ゲートは、この未完了計画がある間は停止しない。
援助を強制する固定行動や新しい回数制限は追加しない。
手持ちは現行観測では有無だけであり、その種類・可食性まで相手が確定しているわけではない。

## 基本

**個体は正解を照合して世界を渡るのではなく、観測と経験から生じた関係拘束の強さを頼りに予測し、行動し、結果から関係を更新する。**

「らしさ」は見た目だけ生物的な行動を足すことでも、設計者が想定した正解行動への近さでもない。経験・現在条件・関係の強弱によって、認識と選択が持続し、変化する仕組みを指す。誤認や失敗も通常の過程として扱う。

この方針は場所、目印、経路、食料、他者、目的達成の認識に共通する。問題のたびに専用の正解判定や強制行動を追加して解決する方向へ戻さない。

## 共通の流れ

観測 → 関係するMBの想起 → 予測と候補の重みづけ → 行動 → 結果との照合 → 関係の更新。

- 強い関係を優先して呼び出す。絶対的な採用保証にはしない。
- 部分的な一致でも候補になり得る。完全一致、不一致の二択だけに閉じない。
- ρは何をどれだけ区別するか、感度は捉えた差への反応の強さとして分ける。固定感度という現在の個性設定を、この文書だけで学習対象へ変えない。
- Hは単なる未到着回数ではなく、見積もりに対して吸収できず残る差に対応させる。Hに応じた候補拡張・再検討を共通の仕組みとして用いる。
- 行動後の観測が予測と合えば関係を強め、外れれば再検討・更新へつなぐ。誤認から戻れるようにする。
- H増分0、許容範囲内、観測不足、目的達成を同一視しない。数値の0を禁止する必要はない。

具体的な更新式・重み・許容幅は実験で定める。この文書は万能な単一式や全候補の常時総当たりを要求しない。

## 親と子の見積もり（2026-11-05）

### 共通試行の終了と引継ぎ（2026-11-06）

局所行動は、識別子・対象キー・局所成果・固定見積もり・実績時間/消費・残差H・終了状態・証拠を
持つ試行として扱う。共通実装は `src/lw/learning/action_trial.jl`。
終了状態は achieved / failed / interrupted / handed_off。終了済み試行へ加算しない。
同じtickの結果を二重適用しない。子の終了処理は親の達成やHを直接変更しない。

最初の接続対象は `acquisition.jl` の探索・採取・釣り。その他の移動・加工・交換等は
既存の試行系を維持しており、この変更で全実行系が共通化済みとはしない。
今後の移行でも、同じ終了・証拠契約を優先し、機能ごとに独立した未達蓄積を追加しない。

探索の局所成果は「試行開始時には見えていなかった採取候補を、探索実行後に観測したこと」。
世界の隠れた残量を検査して正解を保証しない。観測候補は誤り得る。
既に見えていた候補だけを理由に、探索選択の翌tickに自動成功させない。
局所達成で探索を閉じ、次試行にpredecessorを残す。実際に食料を得るまでは親目的未達。
既存候補の再評価を成果に含める拡張は今回行っていない。

候補変更は中断、帰還等への目的変更・睡眠・認知停止・倒れた場合も中断として閉じる。
同じ対象での短い休息・援助応答では実績を増やさず保持できる。
同一対象を継続する間は見積もりを固定し、別試行の時間を過去の未達へ足さない。
方法/場所の要約は各試行を参照し、終了履歴は個体ごと直近64件。
終了履歴を用いた長期統計学習の一般化は今後の課題。既存の親MB見積もり学習は別に維持する。

探索の対象キーは `acquisition_key` に統一し、nothing/unknownを別の場所として扱わない。
同じ証拠による方法Hと場所Hは足さない。候補評価は局所反発と、それを超える方法反発だけを使う。
自力評価はmax(method_H, site_H)を使い、Hはconfidenceだけに作用させる。
`self_reliance.seconds = base_seconds * (1 + uncertainty)` とし、Hで時間を掛け増やさない。
したがって失敗圧が高いことと、実際の計画時間が長いことを記録でも区別できる。

旧版チェックポイントは凍結ソースで再現する。古い探索の累積状態を新方式へ自動変換したとは扱わない。

親MBは、候補を選ぶために必要な粗さで、各方法がいつ、どれだけの消費で、どんな成果を出せそうかを比べる。選んだ後は子MBが現場の観測に応じたρで動く。距離区分や秒数の初期値は環境ごとに定める。

見積もりには「どの関係の、どこまでの成果か」を持たせる。たとえば魚を食べる計画には、釣り場への移動、釣果待ち、拠点への帰還、加工をそれぞれ一度だけ数える。釣れた時点では入手までの見積もりを評価し、食べるまでの残りは親計画が保持する。

試行中は開始時の見積もりを基準にHを評価する。経験は差を観測した場所・方法・経路に返し、次の計画に使う。原因を特定できない未達は未達の記録として保持する。ある場所で待った時間を、他の場所までの移動距離に掛ける倍率へ変換しない。この方針は帰還・採取・釣りのほか、今後の狩猟・交換にも適用する。

`food_batch_expiry=true` で日単位の期限を有効化。既定falseは旧実験用で、魚のみ翌日腐敗の従来動作を残す。
釣り長期ランナーではtrue。ゲーム上の仮設定は果実5日、肉2日、生ドングリ30日、

未採取の食料には期限を付けず、採取・捕獲した日から数える（60日試験後の改訂）。
採取済み食品を地面へ置いた場合は期限を保持し、回収によって期限を延ばさない。
世界の未採取資源が減る要因として野生動物との競合を将来検討する。今回の変更では追加しない。
2026-11-06更新：未採取資源には期限がないため、自然餌場の再生と採取後の期限管理を併用可能にした。
自然餌場にだけ容量付きの補充を行い、既存の携行品・倉庫・落下食品の期限は更新しない。
魚も川の同一資源台帳へ補充する。詳細は季節食料実験の90日接続条件を参照。

倉庫は `(種類,品質,期限)` ごとの数量束、少数の携行品は既存の配列に期限を並べて保持する。
交換・譲渡・入出庫・地面への落下／回収は期限を保持。選択された種類・品質内での
物理的な取り出し順は古い期限順。加工は完成品の期限を設定し、腐敗済み品は加工対象にならない。

`expired_total` と `expired_by_kind` が全種類の腐敗数、`expired_fish` は従来どおり魚類のみ。

日替わりに期限を処理し、知覚側には新鮮0・劣化1・腐敗2という外観だけを公開する。
期限日や製造日、内部の束IDは公開しない。寿命が1日の食品は日単位では中間の外観段階を持たない。
所有食品と拠点で見える倉庫は既存の64秒観測間隔で集約し、見えない倉庫の外観は更新しない。
採取地点にも外観を渡し、劣化が見える候補の損失予測へ接続する。取引の公開倉庫ビューにも
外観を含めるが、相手の各束を指定する交渉や束別価格は未実装。現状の取引評価は主に本人の
観測・保存予測に基づく種類別評価である。

観測した劣化は暫定残存率を下げ、続いて腐敗した場合は直前の見た目と失敗経験を結ぶ。
これは粗い仮説であり、混合された束や交換があると取り違え得る。ρで注視を変える詳細化は未実装。
各食品の初期残存率は物理期限と別に置き、個体へ正確な期限を教えない。

### 使用期限と予測される損失（2026-11-05）

「もったいない」を、現在ある食料のうち使用機会を逃すと失う量の予測として扱う。
`food_expiry_forecast` と `food_expected_waste` が食事・備蓄・取引・調達を接続する。
魚、生の魚、塩焼きの既知の見た目には翌日残存率0.5の暫定感覚を置く。世界側の実際の
腐敗台帳を参照しない。観測した新鮮な食品の減少と腐敗物の増加から保存モデルを更新し、
その後の検査で同じ経験を二重に加算しない。現段階は失敗経験による更新が中心で、
残存率の初期値や予測が正しい保証はない。交換・消費の混在で取り違える可能性も残る。

残り時間、身体の余地、胃の内容、学習した代謝から今日食べられる量を粗く見積もり、
全食品に共通の一つの消費枠を使う。種類ごとに同じ消費枠を重複して与えない。
予測では傷みやすい順に枠を割り当てるが、実際の食事選択順は固定しない。
食事候補には期限前に使う機会の価値、取引には保有量の前後で減る予測損失、
追加調達には入手・帰還・加工後に余らせる量を接続する。係数2は暫定設定。
取引時の予測は保存し、成立時にも同じ条件で前後を評価する。相手の私的状態は読まない。
視覚的援助は既存の困窮観測・余裕条件を維持し、手持ち食品を渡す候補に予測損失軽減を加える。

満腹時の食事禁止、加工設備、有限在庫、実際の腐敗と廃棄の資源収支は別に保持する。
未来の食事を強制したり、食べられない腐敗物を有益な食料として復活させたりしない。
新しい記録項目は食事の `expiry_relief`、交換の `waste_before/after/relief`、
調達の `expected_extra_waste`、備蓄の `expiry`。細かな個体別の鮮度追跡は未実装。

初回動作試験 `outputs/expiry-forecast-3d-20261105` は4体・3日、釣れやすい条件、
同じ固定研修・廃棄所あり。224.67秒、全員生存、食料収支PASS。
釣果4匹はすべて腐敗し、3個廃棄、通常調理・塩焼き調理・交換は0。
Bの保存ログに期限付き食事候補と追加調達の予測損失が記録されたが、
腐敗削減の改善は未確認。274項目の関連検査PASSと長期行動の改善は区別する。

### 腐敗への反発と廃棄所（2026-11-05）

腐敗した見た目 `grey_flesh` の初期反発は8とするゲーム上の感覚設定。食べられない確認経験で強まり、利用可能な確認経験では弱まる。食事候補と交換・援助の評価で共用する。価値0は「受け取る不利益がない」ため、数量を増減する交換案へ無意味な添付物が入り得る。負の評価は受け取りを不利にするが、取引全体で補償される可能性まで禁止しない。

`food_facilities` の `accepts_waste=true` が廃棄所。既定はfalse。用途は初期知識とし、場所と利用半径は世界の設定。釣り実験では拠点の右0.8、利用半径2.1に設置する。廃棄への移動計画はまだなく、利用範囲内でのみ候補になる。拠点内では自分の倉庫（共有設定時は共有倉庫）から、範囲内なら所持品から1操作1個を移す。倉庫から廃棄所への細かな運搬は抽象化している。

廃棄は自動処分の固定行動ではなく、保有反発の軽減と作業費用から食事・加工・保留と同じ確率選択へ載せる。満腹・食事要求なしでも廃棄と保留を評価する。中毒ダメージ、悪臭の空間場、廃棄物の再利用は未実装。

物理処理は主観評価と分離し、廃棄物を `food_resources.waste` の種類別・設備別台帳へ移す。食事カウンタに加算しない。総量収支は地面＋所持＋倉庫＋消費＋廃棄。記録は直近64件と累計。古い保存状態は従来どおり凍結ソースで読む。新しい構造体への旧バイナリ移行は行わない。

別である。観測から計画の前提が崩れた場合は、旧計画を未達として残し、別の目的・

### 強い関係で足りる間は内部を展開しない（2026-11-02）

### 移動・交換を共通の関係勾配として扱う（2026-10-30追記）

**移動と交換は、関係拘束から現在の状態での勾配を見積もり、状態を変える候補を選び、結果から更新する共通の仕組みへまとめていく。** 分野ごとに独立した選択・学習規則を増やすより、既存の予測・確率選択・H・ρ・経験更新を共通化する。

| 共通の役割 | 移動 | 交換 |
| --- | --- | --- |
| 変える状態 | 位置・向き | 提示する物の組み合わせ・数量 |
| 目的への作用 | 目的地へ近づく見込み | 欲しい物や満足を得る見込み |
| 対抗する作用 | 障害物・消費・危険 | 手放す負担・作業費用・不成立の見込み |
| 局所修正 | 移動方向や歩幅を変える | 対価を追加・削減・交換する |
| 結果との照合 | 予測した接近・到着と実績 | 予測した応答・取得・満足と実績 |

ここでの勾配は「どの変化がどれだけ選ばれやすいか」を表す。物の種類や数量が離散的でも、隣接する候補の予測差として扱える。全分野を滑らかな関数や同一の数式へ無理に変換する必要はない。分野固有の観測・作用・実行制約を受け渡す部分と、予測・選択・更新の共通部分を分離する。

**数量は関係の勾配を変える変数として扱う。** 「石1個と食料2個」「石1個と食料3個」を互いに無関係な正解表にせず、同じ物同士の関係を想起し、今回の数量・在庫・身体状態から作用を見積もる。受け取る量が増える作用と、渡す量が増える負担は区別する。量の作用は比例に固定せず、飽和や必要度による変化も扱えるようにする。

数量による作用の強さと、経験を重ねたことによる予測の確かさも別に保持する。大量に交換した1回を、多数の独立した成功経験として数えない。具体的な数量は経験と世界の収支に残し、数量の完全一致を想起の必須条件にしない。

候補の予測変化・費用・不確実性から重みを作り、共通の確率選択へ渡す。予測から外れた未吸収分がHとなり、別方向や別条件への候補拡張・再検討につながる。未到着や未合意だけで毎回Hを加算しない。ρは位置や数量などをどの粒度で比較するかに関わり、差への感度とは分離する。

交換相手も独自の関係勾配を持つ。こちらの評価が改善しても相手の受諾は保証されない。相手の勾配は観測・提案・応答から推測し、非公開の評価値や在庫を直接読まない。移動の衝突判定と同様に、交換の同意・所有権・正確な数量収支は世界側で厳密に守る。

実装は、関係の想起 → 状態変化の候補 → 予測と費用 → 選択 → 実行結果 → 経験更新の境界を揃え、移動と交換の両方で検証しながらまとめる。**これは共通化の設計方針であり、現在すでに同じ評価器・候補生成器を使っているという宣言ではない。** 交換の現状と移行箇所は[交換経験による物同士の関係](LW_Item_Exchange_Relations.md)に記載する。

2026-10-30実装追記：移動のρによる局所方向修正と、物を含む交換の数量条件修正が、`relational_transition` と `relational_best` を共用するようになった。数量を関係キーから分離し、数量への応答を経験更新する。分野固有の効用・候補生成・実行制約は残り、全機能の統合済みを意味しない。

### 局所専用の正解判定へ戻さない

経路への合流を例にすると、「所定の地点で共通特徴2件、一致度0.65を満たしたら接続」という門だけでは、関係の強さに応じて進みながら確かめる過程を表せない。閾値を少し下げるだけで共通化したとはしない。

目指すのは、見覚えから成功経路が候補になり、部分的な一致から暫定的に利用し、その先の予測との整合によって利用の重みが変わる構成である。ただし、実際に経路へ接触しているのか、内部の進行判断だけが先行しているのかは診断で分ける。調査なしに全てを照合閾値の問題と決めつけない。

拠点や食料についても、内部で「達成したらしい」と判断することと、世界で実際に取得・到着・休息が成立したことは分ける。個体へ正解ラベルや未観測の座標を渡して誘導しない。誤認を許すことを、架空の取得や成功報告を許すことにしない。

## 世界の整合性と個体の認識は別

2026-11-01：[取引の複合勾配](LW_Compound_Trade_Gradient.md)を接続。不足改善を双方の必須条件にせず、物の価値・自分の将来不足・観測した困窮への援助・相手との関係を合成する。援助的な条件も専用の強制承諾ルールを作らず、この同じ評価から選ぶ。成立後も同じ尺度で学ぶが、相手の回復を確認したこととは区別する。

2026-11-01：初版の[倉庫観測](LW_Open_Stores.md)を接続。拠点内では個人倉庫を公開された観測として見られる設定経路を設け、交換の要求を観測した種類・数量へ制限する。相手の評価や内的必要度を公開するものではない。精密な視覚や知識形成が完成した扱いにはしない。

世界側の衝突、有限資源、二重取得防止、身体作用、操作ID、通信の重複排除などは厳密に扱える。認識を確率的にするために、世界の収支まで曖昧にする必要はない。

数値安定性、身体の実行可能性、計算予算などに必要な境界も排除しない。ただし、その境界を「個体が正解を知っている」という意味へ流用しない。確率的な認識も、根拠のない一様乱数選択を意味しない。

テスト用の固定見学・日次目標などは、[設定経路](RDL_Configured_Paths.md)として目的・適用範囲を明記する。埋め込みMB、経験から形成した関係、暫定的な試験用処理を混同しない。

## 実装・レビュー時の確認

1. その認識・選択は、個体が得た情報と経験に依存しているか。世界の正解を直接渡していないか。
2. 既存の照合、関係の強さ、予測、H、ρへ接続できるか。局所専用の合否判定を足していないか。
3. 部分一致・誤認・予測外れから、継続や見直しへ移れるか。固定成功や永久拘束になっていないか。
4. 強い関係と弱い関係、似た場面と異なる場面、予測どおりと予測外れで、重みや行動がどう変わるか。成功率だけでなく関係への応答を確認したか。
5. 厳密な世界制約と、個体の暫定的な判断を区別したか。必要な設定経路・未移行箇所は明記したか。
6. 移動・交換などで共通化できる予測・選択・更新を重複実装していないか。数量による勾配変化と、経験回数による確信の更新を混同していないか。

これは新たな承認手続きを追加するものではない。通常の実装判断とレビューの基準とする。既存挙動との完全一致は必須にせず、変更した意味、経験への応答、費用、未検証範囲を報告する。

### 他者関係のρによる詳細化（2026-11-02）

LWの`scene.social_peer_rho`（既定true、falseで比較可能）を接続。物を含む交換と食料専用交換は、現在観測された接触相手から共通の`social_peer_scope!`で詳細検討する相手を選び、その相手について候補・社会MB評価を展開する。低ρでは最大2人、高ρでは観測範囲の全員まで広げる。残りは件数として保留し、個々の記憶を消去・統合しない。

初版の制御は`ρ=1-exp(-(H/8)^2-4p^2)`。pは自身の予測食料不足を4食単位で正規化した値と、観測した相手の困窮・恐怖表情の最大値。ρは個別化の度合い、Hと必要度はその制御入力であり同一概念ではない。係数と最低2人は試験用の初期設定。

相手ごとの観測済み接触時間・交換経験・受けた援助・現在見える表情から、軽い重みを作り非復元抽選する。未知の相手にも正の初期重みを残す。強い関係は注目されやすいが、取引価値の高さや採用を保証しない。抽選は既存の個体・目的別RNGを使用し、選ばれた後の候補順序は元の相手順を保つ。届いた提案の応答・逆提案はこの抽選を通さず、1日1回の自発開始制限も維持する。

これは候補展開前の認知的詳細化を近似する第一段階で、全員の幾何観測・関係更新・援助判断の間引きはまだ行わない。低ρの集団MBを学習する機能も未実装。`social_relationships.*.peer_resolution`に対象数・詳細化数・保留数と直近64件のρ・H・相手を保存する。行動変化を伴うため、性能改善と長期生存への効果は別途実験で評価する。

### 所有物の目的別・間欠観測（2026-11-02試験）

`scene.item_attention=true`で、所有物の詳細観測を毎tickの一括作成から、交換・拾得の判断機会へ移す。既定はfalseで従来比較を残す。移動・障害物・食料・他者の表情の観測周期は今回変更しない。

- 交換：既存の交換検討間隔と未解決提案を確認し、検討が必要なときだけ現在の所有物・公開倉庫を詳しく見る。接触可能な相手から届いた提案は待機中でも確認する。応答・成立通知は毎tick受け取り、観測の省略で学習が止まらない。

実験では行動や学習結果の変化を許容し、観測回数・交換・生存・処理時間を評価する。機械的な軽量化のような完全一致を合格条件にしない。

### 場所・方法・上位要求の勾配

食料確保のような上位目的では、場所/対象に結び付いた未達残差と、方法をまたがず保持する未達残差を分ける。上位の不足不安は、各方法の時間・消費・不確実性への重みを変える。経験的な関係評価と、現在の余裕による一時的圧を混同しない。局所の入手成功はその関係の未達だけを解消し、身体維持の達成や他地点の成功を意味しない。

釣りでの初版接続、数値仮定、未移行範囲、検査は [魚・食料確保の階層勾配](LW_Acorn_Training_Quest.md) の2026-11-04追記を参照。狩猟等も同じ評価APIへ接続する方針だが、狩猟実装済みという意味ではない。

## 食要求と食体験を分離する（2026-11-05）

要求は「以前食べておいしかった」という記憶から予測する。実際に食べた際の快は、
その時の栄養状態・満腹度・身体エネルギー・嗜好・品質から世界／身体側で生成する。
予測と実感は一致しなくてよく、結果を味の経験へ戻す。栄養不足を直接、特定食品を
要求する命令に置き換えない。食料不安による備蓄要求と味の期待は別の評価成分とする。

今回、`food_expected_taste` から現在の栄養需要・満腹度による味の先読みと、
それを記憶平均へ半分混ぜる固定処理を削除した。経験済みの食品／品質は味の経験平均を
そのまま予測に使う。食事・加工見積もり・交換の食品評価で同じ関数を使用する。
未経験食品には身体嗜好と品質によるシナリオ初期値が残るが、最初の実食で経験値に置き換わる。
実食時の身体依存評価と、その結果の蓄積は維持する。平均による更新速度は現行のまま。

固定削減の初段であり、取引開始の場所・携行食料条件、日次回数制限、候補生成の上限、
価値の合成係数は今回変更していない。物理的な所有権・容量・資源保存は保持する。
今後は目的の不足（備蓄不安、料理に足りない材料、記憶から食べたい食品）を共通の
予測差として扱い、取引・採取・代替・保留を比較する。これを実装済みとは扱わない。

### 援助要求：不足予測・不安・自力の見込み（2026-11-06）

内部H（食料換算の不足残差）と表出する不安を分離する。不安は
`4 * max(0, H / max(1, required) - 0.25)^2`。許容幅25%と係数4は
全員共通の暫定評価係数で、生物学的な定数・学習済み個性ではない。
調達開始の評価には小さな不足Hも残す。表情・社会判断は共通の
`food_anxiety`を使う。H増分0を解決や達成と同一視しない。

援助要求は、表出不安があるか身体reserveが70を下回った場合に検討する。
70は既存の備蓄予測の身体維持床に合わせた暫定尺度。関係ONでは従来の
空腹分岐による迂回を除き、どちらの動機も既存64秒の再検討間隔を共有する。
関係OFFの旧実験経路は変更しない。この間隔は要求回数の上限ではない。

自力の見込みは、既存の調達候補の所要時間（帰還・加工を含む）、不確実性、
方法・場所の未解消Hと、備蓄・胃内容・維持床以上の身体余力から評価する。
代謝率で余力を時間へ換算し、予測所要時間まで足りる度合いを連続値で求める。
候補がない場合も未知の探索を不確実性1として見積もり、成功扱いにはしない。
未知の地面食料や相手の私的状態は参照せず、新しい経路探索も起動しない。

共通の候補分布で、自力継続に `+4*confidence`、援助候補に
`-4*confidence` を加える。自力成功の保証や強制順序ではなく、失敗や
時間不足でconfidenceが下がると援助も相対的に選ばれやすくなる。
係数は当面共通で、個性差は未導入。拒否経験は既存の相手別MB・援助ループ
へ反映する仕組みを維持し、別の拒否罰を重ねない。

要求記録にはreserve・不足量・表出不安・自力の見込みを追加する。
備蓄の経過予測も診断記録へ残す。加工見込みは既存候補に含まれる範囲で、
全レシピを再探索する仕組みではない。自力予測には誤認と古い候補の影響も残る。

検証：`self_reliance_checks.jl` 13項目、`food_security_checks.jl` 159項目PASS。
`aid_forecast_checks.jl` は援助関連69項目PASS後、旧取引fixtureの
`bounded deterministic fixtures did not produce trade_accept`で停止。
変更前の保存ソースを別領域へコピーし、検査に合わせて3体へ揃えた場合にも
同じ取引fixtureの失敗を再現。今回の変更による新規不具合とは確認されていない。
この既存検査の修理は未実施で、全検査PASSとは報告しない。

### 作業集中中の観測（2026-11-06）

釣り・加工の継続中は通常の外界観測を省き、作業・身体・MB結果更新を残す。
動体検知は観測を再開するきっかけであり、危険の確定や強制退避ではない。
古い観測を新しい成功経験として再学習しない。`scene.task_focus=false`で無効化可能。
初版の64秒再確認、対応範囲、同じ24日目の比較結果と挙動差は
[作業集中実験](../../experiments/fishing/task_focus_report.md)を参照。

### 数値設定の隔離（2026-11-06）

身体・認知・ゲーム・暫定固定判断の数値を混同しない。
同じ数値であっても、意味の異なる閾値は別の名前で保持する。
現行値を変えない隔離と、挙動を変える調整を別作業にする。
配置、値の意味、検証、未隔離範囲は [数値設定一覧](LW_Parameter_Catalog.md) を参照。
