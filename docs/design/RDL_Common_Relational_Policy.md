# 共通実装方針：関係拘束の強さを頼りに世界を渡る

2026-10-28。ユーザーとの反復した設計確認を、今後の実装・レビューの注意事項としてまとめる。GameAIの開発方針であり、RDL Core定義の改訂ではない。既存コードすべてがこの方針へ移行済みという意味ではない。

## 基本

**個体は正解を照合して世界を渡るのではなく、観測と経験から生じた関係拘束の強さを頼りに予測し、行動し、結果から関係を更新する。**

「らしさ」は見た目だけ生物的な行動を足すことでも、設計者が想定した正解行動への近さでもない。経験・現在条件・関係の強弱によって、認識と選択が持続し、変化する仕組みを指す。誤認や失敗も通常の過程として扱う。

この方針は場所、目印、経路、食料、他者、目的達成の認識に共通する。問題のたびに専用の正解判定や強制行動を追加して解決する方向へ戻さない。

## 共通の流れ

観測 → 関係するMBの想起 → 予測と候補の重みづけ → 行動 → 結果との照合 → 関係の更新。

- 強い関係を優先して呼び出す。絶対的な採用保証にはしない。
- 部分的な一致でも候補になり得る。完全一致、不一致の二択だけに閉じない。
- ρは何をどれだけ区別するか、感度は捉えた差への反応の強さとして分ける。固定感度という現在の個性設定を、この文書だけで学習対象へ変えない。
- Hは単なる未到着回数ではなく、見積もりに対して吸収できず残る差に対応させる。Hに応じた候補拡張・再検討を共通の仕組みとして用いる。
- 行動後の観測が予測と合えば関係を強め、外れれば再検討・更新へつなぐ。誤認から戻れるようにする。
- H増分0、許容範囲内、観測不足、目的達成を同一視しない。数値の0を禁止する必要はない。

具体的な更新式・重み・許容幅は実験で定める。この文書は万能な単一式や全候補の常時総当たりを要求しない。

## 同じ議論へ戻らないための注意

経路への合流を例にすると、「所定の地点で共通特徴2件、一致度0.65を満たしたら接続」という門だけでは、関係の強さに応じて進みながら確かめる過程を表せない。閾値を少し下げるだけで共通化したとはしない。

目指すのは、見覚えから成功経路が候補になり、部分的な一致から暫定的に利用し、その先の予測との整合によって利用の重みが変わる構成である。ただし、実際に経路へ接触しているのか、内部の進行判断だけが先行しているのかは診断で分ける。調査なしに全てを照合閾値の問題と決めつけない。

拠点や食料についても、内部で「達成したらしい」と判断することと、世界で実際に取得・到着・休息が成立したことは分ける。個体へ正解ラベルや未観測の座標を渡して誘導しない。誤認を許すことを、架空の取得や成功報告を許すことにしない。

## 世界の整合性と個体の認識は別

世界側の衝突、有限資源、二重取得防止、身体作用、操作ID、通信の重複排除などは厳密に扱える。認識を確率的にするために、世界の収支まで曖昧にする必要はない。

数値安定性、身体の実行可能性、計算予算などに必要な境界も排除しない。ただし、その境界を「個体が正解を知っている」という意味へ流用しない。確率的な認識も、根拠のない一様乱数選択を意味しない。

テスト用の固定見学・日次目標などは、[設定経路](RDL_Configured_Paths.md)として目的・適用範囲を明記する。埋め込みMB、経験から形成した関係、暫定的な試験用処理を混同しない。

## 実装・レビュー時の確認

1. その認識・選択は、個体が得た情報と経験に依存しているか。世界の正解を直接渡していないか。
2. 既存の照合、関係の強さ、予測、H、ρへ接続できるか。局所専用の合否判定を足していないか。
3. 部分一致・誤認・予測外れから、継続や見直しへ移れるか。固定成功や永久拘束になっていないか。
4. 強い関係と弱い関係、似た場面と異なる場面、予測どおりと予測外れで、重みや行動がどう変わるか。成功率だけでなく関係への応答を確認したか。
5. 厳密な世界制約と、個体の暫定的な判断を区別したか。必要な設定経路・未移行箇所は明記したか。

これは新たな承認手続きを追加するものではない。通常の実装判断とレビューの基準とする。既存挙動との完全一致は必須にせず、変更した意味、経験への応答、費用、未検証範囲を報告する。
