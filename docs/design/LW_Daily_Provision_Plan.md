# 当日の食料確保・帰還をまとめる親計画

2026-11-03。`daily_delivery=on` のLW実験へ接続。Juliaのみ。

## 局所観測用の固定設定と、共通化する機構

**今回の「今日中に食料を拠点へ持ち帰る」は、計画・見積もり・修正・学習の
働きを切り分けて観測するための局所観測用の固定設定（設定経路）である。**
ここでの「観測」は実験者による機構の検証を指し、個体の局所視覚とは区別する。
普遍的な行動原理、埋め込みMB、自律的に形成された目的として扱わない。

| 今回固定して観測する条件 | 他の行動へ共通化する機構 |
| --- | --- |
| 食料を取得し、拠点へ持ち帰るという目的・成立条件 | 目的に対する関係・経験から、段階と候補を組み立てる |
| 一日という期限、翌日の再開始 | 与えられた制約の下で時間・消費・不確実性を見積もる。期限なしも扱える設計を目指す |
| 探索・採取・帰還という段階名、初期の選好と終了後の滞在 | 子の行動を変更しても親の経過・費用・見積もりを保持する |
| 初期見積もり128操作、再評価間隔64秒などの実験値 | 予測残差とHから継続・変更・撤退を評価し、経験で予測を更新する |

加工・狩猟・取引・援助などへの適用では、食料・拠点・日末を必須条件として
持ち込まない。全体が未達でも、途中で得た関係や成立した子目的は別に学ぶ。
目的そのものの形成・変更も将来の対象であり、今回の固定目的で完成とはしない。

現状は共通化の最初の適用例で、汎用の計画機構への抽出は未完了。
選好と滞在方針はconfigured_pathsへ分離済みだが、日末期限・段階名・初期値・
更新間隔にはlearning側へ直接書かれた箇所も残る。配置だけで共通機構と判定せず、
今後は実験設定と再利用可能な機構を分けていく。今回の明記は実行設定の変更ではない。

## 目的と段階

### 加工の切り離し（2026-11-03）

移動・親計画の局所観測では、加工必須食料を一旦外す。
`navigation_edible_profile.jl` で未加工ドングリの配置・初期所持・備蓄を
加工不要の果実へ置き換え、`scene.food_processing=false` とする。
位置・数量・個体条件は維持するが、味・栄養・その場で食べられる性質も
変わるため、純粋な処理時間削減の比較とは扱わない。
navigation_cycle / navigation_four_actor_longrunの入力生成へ接続した。
直前の4体10日条件を変換した入力は
`experiments/rock_gate/navigation_edible_10d_input.json` に保存した。
実行時は4体の凍結個体一覧との一致検査を必須とする。入力だけで4体化しない。
この条件での10日本試験はまだ開始していない。

従来の「空腹・原料所持・拠点内なら加工」は固定の設定経路であり、
個体が加工の必要性や手順を認知・計画できた証拠ではない。
加工の再導入では、原料→処理→可食という関係、場所・道具・時間、
現在の空腹を満たすまでの見積もりをMBで扱う課題を分けて検討する。
世界の加工レシピと過去の実験は残す。生ドングリを食べられる物へ改変しない。
未指定の既存実験は従来の加工設定を維持する。

「今日中に食料を拠点へ持ち帰る」は今回の実験で与える目的であり、
自律的な目的形成の完成を意味しない。初日の設定見学中は開始しない。

`mb_map[actor].daily_plan.active` に開始時刻、日末期限、全操作数、
行動消費、取得元、荷下ろし数を保持する。未知探索・既知採取・帰還へ
切り替わっても同じ計画である。日を越えて未帰還でも期限を更新しない。
終了した計画は翌日、新しい日末期限で開始できる。
新計画の子候補を作る際は、前計画に残った未完了の子試行を未達として閉じる。
前日の子試行の期限を新しい一日へ持ち込まない。同一計画内の段階変更では閉じない。

既知／未知の判断は、現在視認している食料の相対距離、到着モードに残る
暫定的な食料位置、既存の部分照合で現在地から使えると判断された食料への
成功経路を使う。使えなければ未知探索。真の食料座標・隠れた残量は読まない。
視野から消えた瞬間に全忘却しないが、記憶は正解保証ではない。
照合信頼度を重みに使い、到着仮説の棄却や採取の空振りから未知探索へ戻れる。
成功経路の想起は既存chunk機能が有効な場合に利用する。

## 続けるか、空振りでも帰るか

原則64秒間隔と食料視認の変化・採取結果で再評価する。
既知採取と未知探索の所要時間モデルを分け、帰路の見積もりを足した
時間・消費を残り時間・身体reserveと比較する。帰路は視認距離、
観測済み有向MB経路、完了した帰還段階の経験を使う。
未知部分の初期値128操作は経験がない場合の仮定。

継続と帰還は `BasicLoop` の確率分布を使用する。必ず帰還、空振り禁止と
いった制約は置かない。既存の帰還要求は帰還側の弱い事前重みになる。
身体の補給要求・食料不安も残す。初期の採取／荷物／補給の重みと終了後の
滞在方針は `configured_paths/daily_delivery.jl` に隔離する。

帰路の厳密な到達可能性・所要時間分布は保証しない。未知帰路や、学習した
平均を別の地形へ使う予測には誤差がある。重みと64秒間隔は初期実験値。
長期的な帰還改善は別途検証する。

## 成功と未達を混ぜない

段階別の実測時間・行動消費を128件まで保存し、完了経験から次回の
見積もりを更新する。未完了記録も残すが、到着時間へ偽装して平均しない。
現在の段階学習は完了例の平均であり、未達例を含む精密な生存時間推定は
まだ適用していない。完了例への偏りは残る。

全体は `roundtrip:known_food` / `roundtrip:unknown_food` として記録し、
`returned`、`food_success`、`on_time` を分ける。食料がなくても実際に戻れたら
帰還は成功、持ち帰りは未達。初期所持品を拠点で降ろすだけでは、その日の
探索成功・計画終了にしない。取得元と実際の荷下ろし履歴を対応付け、
拾い直しても二重取得にしない。食べた新規食料の代わりに初期所持品を
降ろしても、新規食料の持ち帰りとは扱わない。
今回の取得元追跡は採取・回収を対象とし、交換・援助経由の取得は未接続。

成功した持ち帰り全体の時間・消費を、次回の全体予測へ使う。
計画開始時に全体予測を固定し、途中の段階変更や新しい学習で延長しない。
固定予測を超えた時間は感度を適用して親計画Hへ反映する。
空振り帰還は帰還段階の成功にはなるが、持ち帰り全体の成功時間へは加えない。

既存の下位food/home親にも修正を入れる。探索・経路から到着モードへ移った
元試行を保持し、接近中の操作と消費を加えてから実際の確認結果を学習する。
局所の到着試行が先に閉じても、元の探索を永久に未達として残さない。
単なる視認では成功にせず、誤認で接近をやめた場合は元試行へ費用を戻す。
二重の完了学習は防止する。下位と上位は異なる粒度の記録であり、成功件数を
合算して物理的な帰還回数にしてはいけない。

## 接続・診断

実装は `learning/mb_daily_plan.jl`、`learning/mb_parent.jl`、
`learning/mb_plan_budget.jl`、`simulation/day.jl`。
`daily_delivery=off` の既存目的選択は維持する。
元の `configured_daily_delivery` は荷下ろし集計として残るが、目的選択は
新しい計画が担当する。旧固定request関数は互換検査用に残る。

`daily_plan.decisions` に段階・信頼度・帰還確率・残り時間・帰路既知性、
`records` に全体結果、`models` に段階別経験を保存する。
全体の時計は常に経過する。行動消費とは別に基礎代謝の観測率を予測消費へ
加え、休息による回復を負の行動費用にはしない。状態・乱数は通常の
日末チェックポイントに含まれる。旧ソースの保存状態を無断で流用しない。

検査は `mb_daily_plan_checks.jl`。既知／未知、空振り帰還、日跨ぎの期限、
段階を越えた費用、初期荷物・再取得、成功時の元試行学習と誤認時の復帰、
通常LWへの接続・全操作数・食料収支・JSON保存を確認する。

実行結果：専用52項目PASS。統合部分は600秒を一日とする短縮時計で2日分。
日末保存からの再開結果も連続実行と一致した。
既存の資源予算・未達学習・身体要求・日次荷下ろし・到着モードも回帰確認。
到着の統合検査には `outputs/enclosed-arrival-rho-3d-20261027/ordinary/input.json`
を使用。先に長期試験用の別入力を渡した際は短縮時計内に食料到着が起きず、
到着回数を要求する検査に不適合だった。検査の期待条件は弱めていない。
実時計設定の3日／30日試験や、Bの長期停止の解消は今回未検証。
