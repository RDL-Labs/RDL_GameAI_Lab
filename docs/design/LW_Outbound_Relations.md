# 探索目標の選択と、拠点からの関係形成

2026-10-28。`scene.mb_exploration_relations=true` で有効。既定OFF。目的関連目印方式と併用する3日試験用の有限実装。

## 選ぶ時点から関係を持つ

個体自身の拠点観測を起点に、実行できた外向きの移動によって観測場面間へ関係を引き継ぐ。food目的のshape目印への歩行が選ばれた時点で、出発場面と目印ラベルの関係を保存する。帰還成功・成功経路chunkの形成を待たない。

関係には出発場面、特徴ラベル、拠点からの関係強度、予測上の強度、観測の支持・矛盾、移動失敗、接近・到達らしさを保持する。物体の真のID、拠点の真の座標、逆順の行動列は使わない。

出発点の強度は拠点観測で1、連続した実移動では距離に応じて `exp(-distance/60)` を掛けて伝える。同じ場面に戻ったときは強い既存関係を保持する。これは拠点からの経験的なつながりであり、帰還可能確率ではない。数値と減衰距離60は実験用の初期設計。

目標の予測上の強度は出発点の0.5倍。次の時刻の同色特徴を、観測角度と予想距離の差から連続的に照合する。支持と矛盾を更新し、接近の証拠と `exp(-observed_distance/2)` による到達らしさを保持する。単一閾値で到着成功にはしない。見失った場合は不明、物理的に動けなかった場合は実行失敗として分ける。実移動距離は身体の結果、対象距離は視覚観測を用いる。

複数の目標へ向かうときも、現在の場面が持つ拠点からのつながりを出発点として使える。これは一般的な任意深さの関係推論ではなく、連続した移動経験に沿う場面関係の伝播である。

## 候補への接続

帰還目的では、共通の `mb_correspondences` により現在場面と記憶した出発場面を照合する。同じラベルの目印候補へ、予測上の強度、接近・到達らしさ、支持・矛盾・失敗、場面照合の重みを合わせ、`log1p(strength)` を加点する。強い根拠一つを用い、記録数で票を増やさない。

探索中は新たな帰還加点を付けず、選ばれた目標との関係を同時に育てる。foodへの従来の関係重みは維持する。帰還向きの移動や経路を自動生成せず、帰還できることを保証しない。出発点からの関係を頼って目印を選び、逆に遠ざかる誤認もあり得る。

## 境界・診断

- 対象は既存shape歩行候補。光、他者、任意の物体、固定見学の目的まで共通化したものではない。
- 色ラベルと場面の仮説であり、同色別物の混同や視野内での再対応付けは残る。
- 関係256件、場面1280件、直近選択64件まで。容量到達後は既存関係のみ更新する。後続実装で[睡眠時の類似関係圧縮](LW_Relation_Compression.md)を追加。以下の3日結果と既存90日試験は圧縮前の記録。
- 身体移動と視覚の観測が同じ一秒のreceiptに結び付いたときだけ更新する。再読込した観測からの二重更新はしない。
- `mb_map[actor].exploration_relations` に生成・選択・観測・不明・失敗・帰還候補への加点・使用数と関係を保存する。
- 既存のH・方法評価は維持。ここで記録する矛盾を親Hへ重複加算しない。関係形成・到達らしさだけで親目的成功やchunk報酬を作らない。

検査：`mb_exploration_relation_checks.jl` は前提を含む96項目PASS（専用14）。初回の予測関係、実移動からの裏付け、次の目印への継承、失敗と不明、逆辺・成功報酬の非生成、二重処理防止を確認。

入力生成：`node experiments/rock_gate/prepare_goal_cue_trial.cjs OUTPUT.json --outbound-relations`。実験runnerで日数3、seed20261007を指定する。自然岩地形、有限食料1080、新規3体、初日観察、危険OFF、感度A0.5/B1/C1は前回と同じ。

関連：[共通方針](RDL_Common_Relational_Policy.md)、[目的関連目印](LW_Goal_Related_Cues.md)。

全員最後は拠点付近。食料は初期1080、消費9、野外1059、共有12、追加0。前のgoal_cues方式30日試験の最初の3日と、日末reserve・位置・荷下ろし回数は同じ。関係を作り候補に反映する接続は確認したが、行動改善や到達の裏付けは未確認。目印歩行を選ぶ機会自体が少ない。

出発経験の場面関係はA90/B85/C56件。Aの支持観測は接近の証拠にはならず、到達らしさも約0.0000115と小さい。Cは後続の有効な場面観測による更新がなく、未裏付けの予測関係のまま。観測場面そのものがない場合の欠測は現行missingカウンタに含まれないため、missing=0を全件観測済みと読まない。
