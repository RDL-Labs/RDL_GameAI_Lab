# RDL GameAI ρ解像度遷移設計

**文書種別:** Design / TD operational extension  
**状態:** DESIGN ONLY / 未実装・未検証  
**依存:** T0最低動作仕様（SPEC）v2.5 / `TD_よく使う概念語彙_ρ_無限解像度仮設_v0.1` / `RDL_GameAI_ρ活用指南.md`  
**主題:** ρを固定profileではなく、目的・未解決・危険・操作段階に応じて有限に上下する操作変数として扱う

## 0. 目的

`ρ_B` は有限境界 `B` の内部で、関係差をどこまで細かく区別して観測・記述・比較・操作するかを表す操作解像度である。

既存GameAIではLOW / MID / HIGHの固定profileをObservation Adapterとして扱っている。本書ではその次の設計候補として、同じ個体・同じ目的でも必要な区別の細かさが変化することを扱う。

> **必要な関係差に応じて `ρ_B` を有限に上下させる操作を「解像度遷移」と呼ぶ。**

ρは常時最大化しない。現在目的を満たすのに十分な最小のρを使い、必要になった局所だけ高ρ化し、不要になれば下げる。

```text
通常
ρ_low
↓
現在の区別では不足
↓
ρ_mid
↓
なお不足
↓
ρ_high
↓
目的上必要な差を取得
↓
ρを下げる
```

高ρほど常に良い、賢い、正確という意味ではない。

## 1. Bとρの役割分担

```text
B
= 何を、どの問い・目的のもとで一まとまりとして扱うか

ρ
= そのB内部をどこまで細かく区別するか
```

例として `B = 帰還のための風景` を維持したまま13方向から36方向へ細分化するなら主にρ変更である。一方、風景全体から特定の塔だけへ対象を絞る場合はBの狭窄・変更を含む。

B変更とρ変更が同時に起こることは許すが、provenance上は可能な限り分離する。

## 2. 日常移動と注意深い移動

既知で安定した環境では粗い解像度で十分な場合がある。

```text
いつもの道
+
既知の地形
+
大きな障害なし
+
現在予測と大きな差なし
↓
ρ_low
```

ここでは大きな障害、粗い進行方向、主要landmark、基本的な通行可能性程度を扱う。

一方、暗所、段差、急斜面、狭所、未知の場所、混雑、危険物、不安定な足場では、局所的なρ上昇が候補になる。

```text
ρ_low
↓
粗い地形情報では不足
↓
ρ_mid / ρ_high
```

高ρでは足元、局所勾配、段差、障害との距離、接地可能領域、移動可能方向などを細かく区別する。

> **注意深く移動することの一部は、局所的なρ上昇として記述できる。**

ただし注意そのものをρと同一視しない。注意にはBの狭窄、sampling frequency上昇、処理priority変更、他処理の抑制なども含みうる。

## 3. 目的接近に伴う解像度遷移

対象へ近づくほど自動的にρを上げるのではなく、目的達成に必要な関係差が細かくなるほどρを上げる。

食料取得の例:

```text
遠距離探索
「食料らしい対象がある」
ρ_low

↓

接近
「そこまで到達可能か」
「地形・障害はどうか」
ρ_mid

↓

取得直前
「手が届くか」
「足場は安定しているか」
「対象は取得可能か」
ρ_high

↓

取得操作
「掴めたか」
「対象が動いたか」
「身体位置が対応しているか」
ρ_fine
```

したがって探索→接近→操作に伴って、広域・粗から局所・細へ遷移しうる。

## 4. 高ρは局所化できる

ρを上げる場合、B全体を高解像度化する必要はない。

```text
粗い全体観測
↓
曖昧領域を発見
↓
そのsectorだけρ↑
↓
識別
↓
全体処理へ復帰
```

風景認識なら全周囲を粗く保持し、曖昧な角域だけray密度やfeature detailを増やす。この局所遷移は計算量削減に有効である。

## 5. ρは画像解像度だけではない

ρは知覚画像だけでなく、既存TDと同様に複数の操作解像度へ適用できる。

```text
観測的解像度
空間的解像度
時間的解像度
概念的解像度
記述的解像度
操作的解像度
```

必要なら補助的に `ρ_B^space` / `ρ_B^time` / `ρ_B^concept` 等を使えるが、記号体系の過剰増殖は避ける。

## 6. 思考・概念のρ

同じ対象でも問いによって必要な概念解像度は違う。

キノコの例:

```text
ρ_low
→ 「キノコがある」

ρ_mid
→ 色
→ 傘
→ 柄
→ ひだ

ρ_high
→ ひだの付き方
→ 柄の基部
→ つば / つぼ
→ 傷つけた際の変化
→ 生育環境
→ 周辺樹種
→ 類似候補との差
```

高解像度画像があっても概念側で「茶色い」「丸い」しか区別しないなら、思考側のρは粗い。

> **思考の高ρ化とは、これまで同一視していた関係を、より細かな候補・特徴・条件へ展開することとして扱える。**

## 7. Hとの関係

Hは未解消として残存する差であり、ρとは異なる。

```text
H↑
≠
必ずρ↑
```

未解決への候補には、ρ上昇、再観測、reposition、方法変更、B変更、他個体への照会、保留などがある。

例えば粗い観測では二つの対象を区別できないならρ上昇が有効かもしれない。しかし対象自体が遮蔽されている場合、ρだけ上げても解決しない。

```text
区別不足
→ 局所ρ↑

観測不能
→ 再観測 / reposition / 別sensor

問いが不適切
→ B変更

方法不足
→ 方法変更
```

## 8. ρ変更とF/F'/E/Hの比較契約

T0 SPECでは `ρ_B` が異なれば `RIB_B → F/F' → E → H` の有限記述自体が変化しうる。

したがって `F_lowρ` と `F'_highρ` を無条件に同一trialで比較しない。

ρ変更時は、少なくとも次のいずれかを明示する。

1. 同じ比較次元へ有限射影できる。
2. ρ変更自体を比較契約に含める。
3. 旧trialを閉じ、新しいρで新trialを開始する。
4. 比較不能としてdeferする。

> **高ρで新しい差を発見したことを、低ρ時点ですでに存在したEとして遡及計上しない。**

> **高ρ化によって差が細分化・解消されたように見えても、旧Hが自動的に0になったとはしない。何が解消されたかを比較契約単位で判定する。**

## 9. 高ρが常にE/Hを増やすわけではない

ρを上げることで新しい差を発見し、E/Hが増える場合がある。

一方で、粗いρでは区別不能だった条件が細かいρで識別でき、未解決が減る場合もある。

したがって `ρ↑ → E↑` や `ρ↑ → H↑` を一般則にしない。

## 10. 解像度遷移の基本形

```text
ρ_low
↓
通常運転

現在ρで十分か？
├─ yes
│   ↓
│ 維持
│
└─ no
    ↓
不足理由を検査
    │
    ├─ 区別不足
    │    ↓
    │  局所ρ↑
    │
    ├─ 観測不能
    │    ↓
    │  再観測 / reposition
    │
    ├─ 問いが不適切
    │    ↓
    │  B変更
    │
    └─ 方法不足
         ↓
       方法変更
```

高ρ化後、必要差が取得され目的上十分になればρを下げることを許す。

## 11. ρを下げることも操作である

熟練やM_B形成によって、以前は高ρが必要だった判断が低ρで成立する可能性がある。

```text
以前
ρ_high が必要

経験・M_B形成後
↓
粗い差だけで十分予測可能
↓
ρ_mid / ρ_low
```

> **熟練とは、高ρで処理できることだけでなく、低ρでも必要な判断が成立することとして現れる場合がある。**

## 12. M_Bとの関係

十分に形成されたM_Bは粗い観測からでも安定した解釈を形成できる場合がある。

```text
M_B weak + ρ_low
→ ambiguity

M_B strong + ρ_low
→ sufficient interpretation
```

逆に強い反証、未知条件、危険条件では既存M_Bと現在ρの組合せが不足し、ρ上昇が候補になりうる。

必要解像度は `M_Bの説明力 × 現在ρ × purpose/B` の関係で変化すると考える。

## 13. 注意の分解

注意を単一変数とせず、例えば以下へ分解する。

```text
Attention
├─ Bを狭める
├─ ρを上げる
├─ sampling frequencyを上げる
├─ 処理priorityを上げる
└─ 他候補への資源配分を下げる
```

ρはこのうち、対象内部の差をより細かく区別する側面を担当する。

## 14. GameAIへの初期適用案

最初から画像処理を導入せず、既存lightweight World / Luantiの有限観測を段階化する。

### 通常探索 — ρ_low

- 粗いskyline
- 粗いlandmark
- 粗いrange band
- 基本通行可能性

### 対象発見・接近 — ρ_mid

- ray増加
- 局所地形
- landmark角度関係
- target周辺障害

### 取得直前 — ρ_high

- 前方局所surface
- height difference
- reach
- target/body correspondence
- pickup条件

### 曖昧な風景

通常sectorは低ρのまま、曖昧sectorだけ高ρ化し、全周囲を常時高解像度化しない。

## 15. 風景積分への応用

風景そのものを高解像度画像として毎tick保持する必要はない。

```text
ρ_low
→ 現行程度の粗いskyline / landmark relation

ρ_mid
→ 24〜36方向程度のpanorama signature

ρ_high
→ 曖昧sectorのみ細分化
```

成功地点、大きな方向転換、比較上重要な再検査時などにのみkeyframe候補を保存し、常時詳細風景記録を避ける。

## 16. 移動以外への応用

ρ遷移は対象認識、道具選択、危険識別、食物識別、会話解釈、社会関係、問題解決にも適用できる。

```text
現在の粗い分類では候補を区別できない
↓
概念ρ↑
↓
細かな差を展開
```

空間adapter固有のray数や角度幅は、この一般概念そのものとは分離する。

## 17. 解像度遷移のコスト

高ρは無料ではないと仮設する。

- 観測量増大
- 計算量増大
- 判断時間増大
- 記憶量増大
- 他対象への注意低下
- sensor操作増加

後続設計では、高ρ化による識別価値とコストを分けて記録する。初版から最適化を要求しない。

## 18. ρ振動の防止

次のような無意味な振動は避ける。

```text
low → high → low → high → low
```

有限実装では最低保持時間、操作予算、trial単位、hysteresis、解消確認などを検討する。ただしρの理論定義には含めない。

## 19. 保存すべきprovenance

ρ遷移を実装する場合、最低限以下を保存する。

```text
B / purpose
old_ρ
new_ρ
transition reason
target / sector
source observation
resolution profile / rule version
cost / operation count
outcome
comparison contract
```

さらに、ρ変更によって何が新しく区別可能になったかを可能な範囲で残す。

## 20. 停止境界

```text
ρ↑
≠ 知能が上がる
≠ 正しさが上がる
≠ T1再構成
≠ ξが減る
```

ρ変更は有限境界内部での観測・記述・比較・操作解像度の変更であり、既存M_Bそのものの再構成とは別である。

遮蔽、sensor欠如、誤ったB、方法不足などでは、ρを上げ続けても解決しない。

## 21. 暫定運用原則

```text
常時高ρにしない

必要な差だけ細かく見る

高ρ化は局所化する

H↑をρ↑と同一視しない

観測不能を高ρで解決しようとしない

B変更とρ変更を分ける

ρ変更をまたいだF/F'比較を無条件に行わない

必要がなくなればρを下げる

熟練による低ρ化を許す

ρは知覚だけでなく概念・時間・操作にも利用できる
```

## 22. 一文圧縮

> **解像度遷移とは、有限境界 `B` の内部で必要な関係差に応じて操作解像度 `ρ_B` を有限に上下させる運用である。通常は目的を満たす最小のρを用い、区別不足・操作接近・危険・曖昧性等に応じて必要な局所だけ高ρ化し、解決後は再び低ρへ戻す。ρ変更はB変更・E/H・T1再構成とは区別され、高ρ化が常に差や未解決を増減させるとは仮定しない。**

## 23. 実装前の最小比較案

最初の実装ではdynamic ρを一般化しすぎず、固定した有限scenarioで比較する。

1. 同じWorld / B / purposeで `ρ_low` と局所 `ρ_high` を比較する。
2. 曖昧sectorだけを高ρ化し、全体高ρとの計算量・結果差を記録する。
3. target接近時のみ LOW→MID→HIGH と遷移し、取得後にLOW/MIDへ戻る。
4. ρ変更をまたぐ比較trialを意図せず混在させない。
5. 同じM_Bでもρによって候補・E/H記述がどう変わるかをshadowで保存する。
6. 改善を成功条件にせず、適用機会・コスト・比較可能性を保存する。

本書はdynamic ρの実装開始を自動的に指示しない。既存の固定ρ回帰を維持し、別opt-in実験として導入する。
