# 拠点内の呼びかけと交換経験からの相手予測

開始HEAD: `2d8bf60`。倉庫非公開の通常LWでは相手の食品数が未知で、食品の提示候補が作れない経路があった。
他者の在庫を開示する代わりに、本人が欲しい物・出せる物の発言を観測根拠として通常交渉へ渡す。

## 接続

`scene.camp_trade_calls=true` で有効、既定false。private typed food、incidental_items、item_exchangeが必要。
本人の味経験・食事観察にある品目を共通の食品評価で想起する。現在は「欲しい物＋出せる代替品」の呼びかけ。
純粋な売却だけの呼びかけ、割り込み入札、自然言語による理解は今回の範囲外。

拠点内の聞こえる個体へ次tickに配達する。相手は自分の在庫と評価で応答を決める。
倉庫全体を読むのでなく、発言した数量のみ `announced_food_offers` に追加する。
実行時の所有権・現物確認、通常の交渉・拒否・交換・経験更新は既存経路を使う。

応答した双方は共有場所で会い、通常の接触距離で交渉する。関心のない個体は家の認知停止を続ける。
睡眠中、作業中、未決の別取引・援助がある相手を強制的に起こさない。
同時に呼びかけた二人も、相互に応答できる。片方の待機を排他的なbusyとして扱わない。

成立経験の `exchange_relations` から品目→供給者の支持を取り出し、全体呼びかけと個人呼びかけを比較する。
相手が現在持つと確定するわけではない。期待した返答が来ないと、その呼びかけ関係に残差が残る。
誰かを見かけた回数だけで供給成功を学習しない。

## 暫定固定と限界

`src/lw/configured_paths/camp_trade_calls.jl` に隔離。

- 拠点と個人宅を覆う円内なら声が届く。壁・音量減衰は省略。
- 発話者の識別と品目の意味理解は既知。既存の語句学習・人物認識の完全な接続ではない。
- 自発呼びかけは一日一回。通常交渉の開始回数制限も維持。
- 発言・集合待ちの有効期間は128シミュレーション秒。広告は品目ごとに1個。
- 最初の有効な返答を選ぶ。同時返答はID順。将来は相手との関係から選ぶ。
- 集合先は既知の拠点中央。移動自体は通常実行・障害物処理を使う。

固定の声・集合場所・返答選択は将来の語句・注意・場所MBへ置換する。学習から自然発生した仕組みとは区別する。
`incidental_items.<actor>.camp_trade` に件数、直近128記録、待機、呼びかけ関係Hを保存。
既存チェックポイントに含まれる状態へ置くため、別の永続状態フィールドは増やさない。
新しい呼びかけ選択のRNGは個別BasicLoopとして保存する。

## 検査

```powershell
julia --startup-file=no --threads=1 --project=. experiments/social_relationships/camp_trade_calls_checks.jl
julia --startup-file=no --threads=1 --project=. experiments/social_relationships/camp_trade_lw_checks.jl
julia --startup-file=no --threads=1 --project=. experiments/social_relationships/personal_house_idle_checks.jl
```

局所は偏った備蓄と味経験を持つ3体。32シードの通常交渉で交換経験まで確認する。
接続検査は短縮した昼間と、明示的に味経験を付与した検査用保存状態を使う。長期の自然な交流頻度を測るものではない。

## 結果

Windows / Julia 1.13.1 / 1 thread。

- 局所110項目PASS（既存語句側の品目想起4項目を含む）。32シード中11シードで通常交渉の交換が成立。食品総数を維持。
- 実際の成立経験から、供給した相手への呼びかけ確率0.59398、全体呼びかけ0.40602。
  この値は局所入力での1状態であり、全期間の個人取引率ではない。
- 通常LW接続9項目PASS。Bが自宅から応答→共有場所へ移動→交換成立。
  その後のBは経験のあるAを宛先に選んだ。関心のないCは応答しない。
- 既存の個人宅・睡眠検査34項目PASS。
- 同一の検査用保存状態から、連続進行と日末保存・再開で行動回数、incidental_items全スナップショット、dailyが一致。
  全内部キー・全RNGを直接比較した主張ではない。

初回の接続fixtureは魚を日跨ぎさせて腐敗し、相手へ渡せる食品を失っていた。
腐敗仕様を緩めず、保存可能な加工ドングリと果実へfixtureを変更した。
通常条件の30日試験・交流頻度・計算負荷の比較は未実施。
