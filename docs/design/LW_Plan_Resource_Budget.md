# 所要見積もりと実行余裕を分ける

2026-11-03。`mb_plan_budget.jl`。food/homeの親MBに接続。

経験からの所要操作数・消費見積もりは、長くても改ざんせず残す。
別に現在のreserve、観測済み累積代謝からの平均消費率、当日の残り時間を
計画条件として与える。この一日区切りは現在の生活実験の計画時間窓であり、
普遍的な認知制約や将来の期限学習の完成ではない。

候補では期待所要時間と利用可能時間、期待操作消費＋所要時間中の代謝と
現在reserveを比べる。各超過率に `2log1p(超過率)` の減点を与える。
候補を禁止せず、元の関係・報酬・失敗・Hによる確率選択と合成する。
食料取得や将来の消化吸収は保証された補給として先取りしない。

実行開始時に期限を固定する。選び直しや到着モード移行で延長しない。
実行中は凍結した期待所要量から実績を差し引き、残り時間・現在体力と
比較する。対数化した超過率をdelay/energy感度で評価し、既存の予測残差・
子経路残差と最大で合成する。既に加算した圧を二重加算しない。
期限超過も別に残るため、統計上の上限が長いだけではH増分ゼロを保証しない。
行動・到着を強制する固定ルールは追加しない。

診断用に候補/試行のestimate.planningへ期限・利用可能量・予測消費・減点を、
親の評価記録へplanning_pressureを残す。コンテキストなしの単体呼出しは
従来の予測計算を維持する。実行アダプターはMB有効時に毎tick更新する。

限界：同じ予測を持つ候補同士は同じ減点になる。休息報酬の文脈混同、
探索から到着への成功学習の分断、見積もりの統計的増大そのものは未修正。
計画全体の実行可能性を厳密に証明するものでもない。今回の変更だけで
Bの長期停止が解消するとは主張しない。日末保存はソースハッシュで保護され、
旧試験のチェックポイントを変更後のソースで通常再開することはできない。

検査：`mb_plan_budget_checks.jl`で長い予測の保持、資源超過時の減点/H、
期限の非延長、到着モードへの期限継承を検査。
`body_purpose_checks.jl`で通常シミュレーション内の接続を検査する。
