# 個人倉庫の食料交換・初版

2026-10-29。Julia 1.13.1 / Windows / Julia・OpenBLAS各1スレッド。実装前HEADは`719aaec`。

## 接続したもの

拠点で「自分の種類・個数」と「欲しい種類・個数」を提案し、相手が受諾・拒否する。受諾時に双方の在庫を再確認して一括交換する。提案だけでは予約・移動しない。拒否、期限切れ、移動や在庫変化による不成立もある。無条件の手渡しは従来の別行動として残す。

提案・応答は共通の`BasicLoop`による確率選択。判断へ渡すのは本人の備蓄、接触相手、提示条件だけで、相手の在庫・空腹・好みは見せない。既存の味、身体状態、種類別在庫の限界価値を使う初期評価式を与える。固定交換比率はなく、各1〜4個の条件から選ぶ。個々の条件・相手に対する報酬と失敗が次の選択へ作用する。

成功の評価は選択時の重みを固定し、成立した瞬間の本人在庫の前後差から実利得を計算する。予測未達・実損のうち許容幅0.05を超えた部分をHへ渡す。利益があっても予測未達なら部分成功として扱う。待機tick、提案しない選択、本人による拒否は中立。取引中はナビゲーション経路を保持する。

初期価値式、加工係数、通信の30秒期限、64秒の提案再検討間隔は与えた仕様であり、学習された市場・所有概念ではない。対案交渉、借金、貨幣、他者の選好推定は今回含まない。[詳しい仕様](../../docs/design/LW_Typed_Food_Processing.md#個人倉庫間の物々交換)。

## 3日試験の条件

- 人3体、兎30体、3日。seed=20261007、兎seed=20261028。
- 果実1080個、近隣の原料192個、初期手持ち原料各1個。総数1275、有限・補充なし。
- 個人倉庫、消化ON、腐敗・狩猟・危険OFF。初日見学、日次持ち帰り、既存の帰還・睡眠等の設定を維持。
- [前回の個人倉庫試験](../personal_food/report.md)と入力を構造比較し、差は`scene.food_exchange=true`だけ。交換成立のための倉庫への追加配給は行わない。
- 拠点内でも相手と距離1.25以内・遮蔽なし・聴取可能な接触を要する。初日の見学中・夜間は提案しない。

## 制御例と回帰検査

- 食料・個人倉庫・世界の交換検査232項目PASS。種類と総量保存、1対2の交換、在庫変化時の全体取消、第三者による拒否の無効化、接触・期限、再送・不正再送、本人だけの前後在庫、保存復元を確認。
- 方策検査74項目PASS。原料20個のAと果実20個のBを使う8シードの短い試行で、提案77、成立4、拒否73。報酬を得た方法8、失敗試行73を確認。これは通常マップとは別の制御例。
- 同検査内で、別取引によって待機中の在庫が変わった場合に、古い予測利得で報酬を付けず実利得との差を評価すること、0同等と達成の区別、待機中のH不変、終端結果の一度だけの解決、保存後の次の選択系列一致、取引中の経路保持を確認。
- 3日資源・生活25、個人倉庫15、交換接続6、2日末からの再開結果全体一致1＝47項目PASS。再開側は53.595秒。
- 既存の層境界566項目PASS。合計919項目PASS。親MB・経路監査もPASS。
- 交換の単体・方策検査をJulia ecology CIへ追加。今回の記録はローカルでの検査結果で、クラウドCIの成功を示すものではない。

3日試験後、再送時に整数1とBool/Floatの同値比較で型検査を迂回できる点を補強した。入力検査を再送比較の前へ移しただけで、正常な整数の判断・交換の処理は変えない。この修正には14項目の不正再送検査を追加して世界検査を再実行したが、3日全体は再実行していない。凍結ソースと最終`src`の差はこの1ファイル・検査順の変更のみ。
