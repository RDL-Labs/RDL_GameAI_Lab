## 既存モデルとの関係

- `src/body/composition.jl`: 動物用のavailable/fat/protein、へたり込み・死亡を保持。
- `src/body/digestion.jl`: 人の味・栄養需要とreserveへの供給。三成分の順序は糖質・タンパク質・脂質。
- 新しい `src/body/macronutrients.jl`: 独立した試作モジュール。既存型・保存形式は変更しない。
  既存の分率順序を使うが、今回の分率は**エネルギー相当量**であり、食品の既存感覚用分率を
  栄養グラムとして流用しない。既存RDLBodyのincludeにも追加しない。

## 状態と収支

糖の蓄え（血糖濃度ではない）、脂肪、身体タンパク質、利用可能なタンパク質材料、
消化中の三成分を保持。修復需要は目標身体タンパク質との差から算出する。
単位Eは全区画で共通の抽象的エネルギー相当量。タンパク質の質量や必須アミノ酸は未分離。

毎更新: 消化→維持更新・活動損耗と材料再利用→不足時の糖新生→維持活動費の支払い→
睡眠/覚醒修復→余剰蓄積。糖と脂肪は同時に支払い、脂肪は糖を直接増やさない。
糖新生は材料を減らし効率0.8で糖へ。余剰糖と材料の脂肪化効率0.85。
脂肪化の通常速度上限は糖に適用し、容量を超える糖・材料はその更新で処理する
（初版の簡略化。全変換を厳密な速度制限にしたものではない）。
脂肪容量を超えた分は排出として記録。脂肪吸収そのものにはこの変換損失を課さない。

`初期総量 + 受け入れた摂取 = 現在総量 + 消費 + 変換損失 + 排出`

修復で材料を身体へ移す分は消費と二重計上しない。補助エネルギー費だけ消費へ。
支払えなかった需要はunmetに記録し、存在しない燃料を差し引かない。
身体タンパク質下限は50、下限以下の損耗は止める。死亡・へたり込み判定はこの局所版では
未接続。能力は組織量による診断値のみで、固定スケジュールを自動変更しない。

身体要求値（`body_demand`）は糖不足・脂肪不足・材料/組織不足の重み付き和から
消化中の供給による抑制を引いた0..1値。身体から認知側へ渡す入力の近似であり、
主観的な空腹感そのものではない。各成分の要求値も別に保持する。
未来の食事予測、味、MB、ホルモン、血糖濃度そのものは未接続。
空腹感や食欲は将来、身体要求と経験・予測・状況を統合する別の層として検討する。
2026-11-20: 旧`hunger`を`body_demand`へ改称。係数と計算式は変更していない。
