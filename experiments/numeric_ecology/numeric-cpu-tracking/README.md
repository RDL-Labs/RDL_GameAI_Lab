# ID追跡のON／OFF

`NUMERIC_ID_TRACKING=on|off` で切り替えます。既定は `on` です。

- **ON**：生成したIDの対応表をすべて保持します。以前の数値版と同じです。
- **OFF**：600シミュレーション秒ごとに、現在の状態から参照されなくなったIDの対応表を回収します。空いた数値スロットは再利用します。

固定語彙の共通表と、現在のMB・経験・使用回数・重複判定などに必要な参照は維持します。睡眠学習やモデル自体を無効化する設定ではありません。元のコードでは経験IDも機能的な参照に使われるため、すべてのID発行を止めることはしていません。診断記録として現在の出力に残っているIDも、その出力から参照される限り保持します。

回収時には全ローカル状態、辞書・集合・配列、関数のクロージャに保持された参照を走査します。循環参照に対応します。外部へ渡したID単体を別途保持して追跡する用途にはONを使ってください。OFFでは不要になった番号を再利用するため、番号単体の永続的な一意性は保証しません。保存した結果はその時点のレジストリと一緒に読みます。

数値スナップショットは空きスロットも保存するversion 2です。前のversion 1ファイルは元の `numeric-cpu-full/export_snapshot.jl` で読みます。

```powershell
$env:NUMERIC_AGENT_COUNT='3'
$env:NUMERIC_ID_TRACKING='off'
julia --startup-file=no --project=source/julia run.jl INPUT.json OUTPUT.json
```

`tracking_checks.jl` は基礎31項目と、ON/OFF、参照保護、クロージャ、循環参照、スロット再利用、復元の11項目を検証します。`run-off-30.ps1` はこのPC用の30体・1日検証です。実行中の自動スリープ抑止と30分の停止上限があります。

この変更は独立した `outputs/numeric-cpu-tracking` に置き、以前のON結果は `outputs/numeric-cpu-full` に残しています。辞書を固定長配列へ変更するGPU向けの改修は含みません。

## 確認結果（2026-10-15）

- 3体・1日：同じ版のON/OFFと、元の文字列版の全結果が一致。
- OFFの数値保存：別プロセスで復元した全結果が一致。
- 3体・3日：元の30日試験の最初の3日と、日次記録・各日の開始状態が一致。睡眠・日跨ぎ後の参照を確認。
- 30体・1日：前の数値版ONの全結果と一致。終了コード0。内部状態・出力の文字列数0。
- 基礎と回収機構の42項目、各シナリオの既存検証24項目が合格。

30体・1日の比較：

| 項目 | ON（前の数値版） | OFF |
|---|---:|---:|
| 最大ワーキングセット | 4.17 GB | 2.47 GB |
| ID表の格納枠 | 3,332,794 | 159,667 |
| 保持しているID表のバイト列 | 88,827,737 bytes | 2,877,387 bytes |

最大ワーキングセットは約41%減少しました。OFFは28回の回収で累計3,228,004件分を回収しました。OFFの終了時占有枠は111,935で、最後の回収後に生成した未回収の項目も含みます。

OFFの全体時間は約366秒、シミュレーション呼び出しは約346秒でした。コンパイル込みの単発実行で、独立した検証の同時実行もあったため、厳密な速度改善の測定ではありません。詳細は `validation.json`、一致判定は `comparison.json` に保存しています。
