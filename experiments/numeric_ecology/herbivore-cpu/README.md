# 同じマップの草食動物CPU試験

既存の30体試験の `map-spec.json` を保存し、地形の範囲・川の数式と位相・森林・岩場・障害物・開始位置を引き継ぎました。元のモデルや結果は変更していません。地形分類は `lw_day/landscape.jl` と同じ式、線分と障害物の判定は元の `RDLMigrationProbe` です。固体の低い障害物も、この動物版では通行を遮ります。

## 草と個体

- 128×128の範囲を2×2の4,096マスに分け、草地・川岸・森林の通行可能な3,853マスに草を配置。
- 水面・岩場・障害物と重なるマスは草なし。元の点在食料はこの動物モデルでは利用しません。
- 草は消費すると減り、空から上限まで2シミュレーション日で再生。観測頻度で再生量が変わらない遅延更新です。
- 同じマスを複数体が食べるときは、要求量に比例して同時配分。先に処理された個体が独占しない方式です。
- 個体の位置・エネルギー・消化中の草・眠気・状態・直前のマス・短期目標を数値配列に保持。状態はUInt8、マス参照はInt32。
- 状態は探索・採食・休息・睡眠・逃走。長期記憶、MB、経験ID表は使用しません。
- 草がなければ隣接8マスを感知し、直前のマスへ戻る選択を少し避けます。目標の再確認は10秒ごと。マップ全体の食料位置を個体へ渡しません。
- 基準試験は捕食者なし。近くの危険から逃走に切り替わる経路は個別テストで検証。

消化・栄養・睡眠・速度は仮のゲーム用数値です。既存の日長17,280シミュレーション秒を流用し、実際の兎の生理・実時間を再現していません。草は一種類で、味・繁殖・捕食による死亡・個体同士の身体衝突は未実装です。エネルギーが0の時間を計数しますが、死亡処理はありません。

## 結果：30体・3日

- 1,555,200回の個体更新を完了。
- シミュレーション呼び出し約1.85秒（コンパイル込み）、プロセス最大RSS約290MB。この数値にはJulia起動とモジュール読込時間を含みません。
- 全個体でエネルギー切れ0。各個体の移動距離は約22.6〜57.8マップ単位。
- 時間配分：探索0.37%、採食5.89%、休息71.41%、睡眠22.33%。草と栄養が豊富なため、活動量は少なめです。
- 草の初期量＋再生量＝残量＋消費量、消費量＝消化量＋消化中の量、全個体の更新回数、有限値、最終位置の通行可能性を検証。
- 状態切替、競合時の公平配分、再生の観測頻度独立性、草なし時の移動、危険時の逃走について21項目が合格。

以前のMB・学習付きモデルとは処理内容が異なるため、この時間差は同じモデルの高速化率ではありません。CPU実装であり、GPUカーネルは未実装です。

## ファイル

- `Herbivores.jl`：数値配列と状態機械。
- `checks.jl`：個別検証。
- `run/result.json`：日次集計と全個体の最終状態。
- `run/grass.csv`、`run/trajectory.csv`：草の初期・最終量と60秒間隔の位置。
- `map-overview.svg`：全体地形と開始地点周辺の拡大図。
- `plot_map.py`：図の再生成。Pythonは可視化のみで、シミュレーションはJuliaです。

実行例（このディレクトリから）：

```powershell
julia --startup-file=no --project=../numeric-cpu/source/julia checks.jl
julia --startup-file=no --project=../numeric-cpu/source/julia run.jl
```
