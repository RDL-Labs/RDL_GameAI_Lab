# 全面数値ID版 — CPU実験

追跡ON／OFFを追加した次の実験版は `../numeric-cpu-tracking/README.md` を参照してください。このディレクトリは比較用の元版として保持しています。

既存のJulia統合シミュレーションの判断・学習ルールを保ち、実行経路の文字列データを64ビットの `NID` に置き換えた独立版です。元リポジトリと完了済み負荷テストは変更していません。

## 数値化した範囲

- 個体、行動、状態、観測フィールド、色、適用条件、MB・親子参照。
- 経験・試行・操作・メッセージの識別子、モデルの辞書キーと分類値。
- 接頭辞判定、比較・並び替え、複合ID生成、乱数種に使うSHA入力。
- 経験をJSON文字列にして識別する処理も、数値バイト列からIDを生成する処理へ変更。
- 生成対象は統合実行経路と検証の44ファイル。対象一覧は `source-files.txt`。

`NID` は8バイトの値型です。同一性は数値比較で判定します。既存の辞書順による同点処理とSHAの入力を維持するため、文字列の元表現は独立した `Vector{UInt8}` のレジストリに保持します。これは情報の意味を失わずに数値IDへ移す方式であり、名前の情報を捨てる圧縮ではありません。ハッシュ衝突時にはバイト列を照合します。

入力JSONは開始前に変換します。表示用JSONは終了後に復号します。数値結果は `.numeric.bin` にレジストリとともに保存し、別プロセスで復元可能です。ID単体は別のレジストリで意味を保証しないため、保存時にレジストリを必ず含めます。結果スナップショットは実行スタックの保存ではなく、途中再開機能を追加したものではありません。

## 検証

- `core_checks.jl`: ID、辞書順、数値参照、乱数種、JSON表現、文字列監査。
- `run.jl`: 元の安全性・睡眠・保存則検証に加え、入力、終了時のローカル状態、出力オブジェクトの文字列数を監査。
- `compare.py`: 3体・1日の全結果と文字列版を厳密比較。オブジェクトのキー順のみ無視し、数値の許容誤差は使いません。別プロセスの保存復元結果も比較。
- 30体・1日は、完了済み30体・3日テストの初期状態と初日の日次記録を比較。30体・3日全期間の一致を保証する検証ではありません。

実測値は各 `.metrics.json`、比較結果は `parity-report.json`、30体のメモリは `30agents.memory.jsonl` に記録します。時間にはコンパイルを含み、速度比較用の厳密なベンチマークではありません。

2026-10-15の確認結果：基礎31項目、各シナリオの既存検証24項目が通過。3体・1日の全結果、数値保存の別プロセス復元、30体の初期状態・初日記録は、すべて差分ゼロでした。終了時ローカル状態と出力オブジェクトの文字列数もゼロです。30体・1日は全体約391秒、最大ワーキングセット4,173,377,536バイトでした。動的レジストリは3,332,794項目まで増えており、長期実行の前にメモリ削減が必要です。測定中に独立した検証も実行したため、時間は性能改善の根拠として扱いません。まとめは `validation.json`。

## 実行

Juliaプロジェクトは `source/julia` です。必要なJuliaパッケージを用意してから実行します。

```powershell
$env:NUMERIC_AGENT_COUNT='3' # 1..30; 与えるspecの個体配列も整合させる
julia --startup-file=no --project=source/julia run.jl INPUT.json OUTPUT.json
julia --startup-file=no --project=source/julia core_checks.jl
julia --startup-file=no --project=source/julia export_snapshot.jl OUTPUT.json.numeric.bin RESTORED.json
```

`run-30agents.ps1` はこのPC用の絶対パスを含む30体検証用スクリプトです。実行中だけ自動スリープを抑止し、30分で停止します。

`build.jl` は前段の `../numeric-cpu/source` を読み、数値版ソースと `registry.jl` を再生成します。生成物を手修正せず、変換規則と数値コアを変更します。元のランタイムは commit `5b09a58c3009f59044cc08d2a551f939a3fa7790` に基づくローカル30体実験です。

## 残る制約

文字列データの数値ID化と、GPU向けの固定長配列化は別です。`Dict{NID,Any}`、可変長配列、CPU上の動的レジストリが残るため、この版はGPUカーネルとして実行できません。静的なフィールド名やNamedTupleのスキーマはJuliaの型メタデータです。ファイルパス・例外文・テスト名は外部境界の文字列として残します。

レジストリは実行中に生成したIDを保持し続けるため、長期・多個体実行ではメモリ増加要因になります。ID生成には数値バイト列の組み立てと照合が必要です。数値化だけによる高速化は保証しません。次の性能改善は、動的識別子を個体番号・時刻・連番の構造化キーへ移すことと、固定スキーマの記録を型付き配列へ移すことです。
