# 日末チェックポイント v1

毎日、睡眠・社会記憶の整理と日次集計の後、終了処理より前の状態を保存する。
`day-005.jls`から再開すると6日目の最初の処理から始まる。
`days=10`は追加10日ではなく、通算10日目までを意味する。

## 使用方法

通常の岩囲い等の実験引数に `--checkpoints` を追加すると、
`OUTPUT/ordinary/checkpoints/day-001.jls` などを毎日保存する。

同じ実験引数、別のOUTPUTに `--resume-from OLD/ordinary/checkpoints/day-005.jls`
を追加すると6日目から再開する。続きも毎日保存するなら `--checkpoints` を併用する。
初期散策フェーズや初期化を6日目からやり直すことはない。

通常のnative入口でも使用可能:

```sh
julia --startup-file=no --project=. integrations/lightweight_julia/run.jl OUTPUT --spec input.json --checkpoint-dir CHECKPOINTS
julia --startup-file=no --project=. integrations/lightweight_julia/run.jl NEW_OUTPUT --spec input.json --resume-from CHECKPOINTS/day-005.jls --checkpoint-dir NEW_CHECKPOINTS
```

岩囲いランナーは観測用にソースをコピーしてフックを入れるため、その保存物は同じ岩囲いランナーの同じ観測オプションで再開する。無加工のnative入口とはソースハッシュが異なる。

## 保存と互換性

- 世界、身体、所持品、備蓄、食料再生、踏み跡、学習、目的、未完了操作、個体別乱数、履歴を一つのオブジェクトグラフとして保存。共有参照を維持。
- 観測、次の行動候補、実行用クロージャは翌tickに再構築する。
- Juliaバージョン、src配下のコードハッシュ、入力条件、保存状態のキーを検証。最終日数だけは変更可能。
- 異なるコードでの実験分岐はv1では拒否する。診断フックの変更もコード差分になる。互換性を宣言する移行機構は未実装。
- 既存チェックポイントは上書きしない。一時ファイルから移動して完成品を公開する。
- `.jls`はローカルの信頼できるJulia保存形式。異なる版や外部配布用の交換形式ではない。
- 再開元パス・SHA256はnative manifestへ記録する。
- 再開後のresultは再開前の日次履歴を含む。一方、岩囲いランナーの位置・境界通過ログは再開後のみ。`observer-scope.json`に明記する。日別経路図は旧実行の位置履歴と合わせる必要がある。
- 日ごとの独立ファイルに累積履歴を含むため、長期間ではディスク容量が増える。ローテーションや差分保存は未実装。
- 以前の実験は完全状態を保存していないため、過去のJSONからこの再開形式を復元できない。

## 検査

`checkpoint_checks.jl INPUT`は短縮時計（1日120秒）で2日実行する。
保存なし・保存あり・1日目から再開の結果全体を比較し、不一致設定・不適切な日・上書きを拒否する。
`save DIR` / `resume DIR` を別プロセスで実行して、プロセスを越えた復元も検査する。
短縮時計は検査専用で、本番の人間時間換算を変更しない。
