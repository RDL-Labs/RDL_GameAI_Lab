# 探索・帰還中に落ち物を拾う：接続と3日試験

2026-10-30、Windows Julia 1.13.1、CPU 1 thread。Python不使用。

## 変更

`scene.incidental_items=true`で、通常の食料探索・帰還に入る前に、手の届く落ち物の拾得と続行を子BasicLoopで確率選択する。拾う時刻・個数・品目は指定しない。身体対応、予定／疲労休息、初日の見学、帰還後の荷下ろしなど、先に選択済みの優先行動は維持する。

初期の関心は、未経験の見た目を確認する弱い仮値。拾得の実行結果、消費、似た見た目の経験から候補を更新する。種類IDを報酬表として読まない。親のfood/home目的と既存経路を保持し、拾得の操作数・実消費は既存見積もりの実績へ加える。親の達成・報酬を拾得成功で代用しない。

詳細と未接続範囲は[設計](../../docs/design/LW_Portable_Items.md)。最初の版は距離1.25以内の立ち止まる拾得。遠い物まで歩く寄り道、持ち物を保管・譲渡・交換する自律判断は未接続。

## 2026-10-30: 観測からの取得・交渉の接続

`incidental_items=true`で、拾得と所有物交渉が共通の観測特徴による初期関心、BasicLoopの確率選択、予測と結果の差による更新を使う。全行動を単一の候補生成器に統合したわけではなく、拾得・提案・返答は別の子ループ。食料の対価評価は既存の`food_trade_weights`と同じ在庫の対数効用を使う。物の種類IDや相手の好み・倉庫を読まない。

初期関心は `0.20 + 0.10 * light / (0.02 + light)`。標準の光る石(light=0.02)は0.20から0.25へ、非発光物は0.20のまま。見た目が同じ別種類にも同じ式が作用する。拾得では経験からの馴染み、交渉では自身の類似所持品によって限界関心を減らす。これは初期評価の仮定であり、学習済みの用途や貨幣価値ではない。

- 地面の無所有物は従来どおり任意拾得の候補。
- 他者の持ち物が見え、拠点で接触できる場合は、譲渡依頼・自分の物との交換・自分の食料1個を対価とする交換を候補にする。贈与も提案できる。
- 一方の対価が空の提案を世界側でも許可するが、どちらの場合も受け手の明示的な受諾が必要。空の両側や食料だけの提案はこの世界APIでは引き続き拒否する。既存の直接`item_give`は世界能力として残るが、新しい自律方針では使わない。
- 受け手は自分の所持・食料・身体状態・関係経験で受諾/拒否を選ぶ。隠れた物を申し出られた場合、見えていなければその価値を推測で補完して受諾しない。
- 提案時には報酬を与えない。受諾、拒否、期限切れ等の通知で凍結した見積もりを解決し、実際の自身の資産変化から主観価値を評価して社会MBへ渡す。相手と同じ価値になる必要はない。通知の再適用で二重学習しない。
- 所持品は従来の距離12・視野/遮蔽条件で他者から見える。個人倉庫は非公開。今回新たに公開したのは交換可能な接触相手の一覧であり、非公開在庫ではない。

診断は各個体の`incidental_items.social`に候補数・続行・提案・受諾・拒否、最大64件の期待値/実績/条件を保持する。世界側の`exchanged`には無償譲渡も含まれるので、取引条件と併読する。候補数増加だけで吸引が増えないよう正規化し、1回32候補、方法履歴129件以下、提案間隔64秒で制限する。

現段階は拠点での接触中の接続。遠方の相手へ物欲で近づく、非公開品を尋ねる、保管・処分の自律選択、食料だけの交換候補との完全な同時選択は未実装。初日見学・夜間睡眠・荷下ろし等の既存優先処理は維持。長期自然環境で交換が増える保証はしない。

検査: `social_checks.jl`は観測のプライバシー、明示的な同意、共有の関心、結果待ちと再送を検査。`social_integration_checks.jl`は1日512秒に短縮した2日・3体の拠点接触fixtureで、スクリプトによる行動指定なしに提案18・成立6・拒否11・不成立1、保存再開の所有物/選択状態/社会MB一致を確認。これは接続の動作検査であり、通常の2日/90日の生活試験ではない。既存の拾得方針・統合検査もPASS。新規2系統をJulia CIへ追加（クラウド結果は未確認）。

## 2026-10-30: 不利な条件の受諾抑制と逆提案

物品を含む交渉では、所持品の限界関心・食料の必要性と味・関係MBの経験値から条件を評価する。暫定式は `主観的純益 = 資産価値差 + 0.02 × 関係経験benefit − 0.002`、許容帯は-0.01以上。全てのMBを新たな一つの勾配器へ統合したものではなく、既存の身体/味評価、特徴照合、社会MBを組み合わせる初期評価アダプタである。提案・逆提案・受諾とも明確な主観的損失の候補を外し、残る候補の選択と拒否は共通BasicLoopで確率的に行う。実際の損失が完全になくなる保証ではなく、評価間違いや提示後の状態変化はあり得る。

受け取った条件が許容できない場合、見えている相手の別の物/追加の物、食料の追加要求、自己負担の削減を候補にする。相手の食料在庫は読まず、希望条件として提示する。同じ見た目・同じ条件になる修正は一候補へまとめる。対象は現段階では物品を含む取引で、食料だけの既存専用交渉は別系統。

世界の`item_counter`は原提案の受け手のみが実行でき、条件と自身の資産/接触を検証してから、原提案を`declined(reason=countered)`で閉じ、新しい提案を作る。この操作では資産は移らず、相手の新たな受諾が必要。`counter_of`・`root_id`・`round`を保存し、最大8回、最初の30秒期限を延長しない。失敗した逆提案は原提案を消さない。旧提案を後から受諾しても資産は動かない。

提案側だけでなく逆提案した側の返答ループも、結果通知まで待つ。逆提案を送ったことを報酬にしない。`incidental_items.social.counterproposed`で件数を記録し、結果の`subjective_gain`・`reason`・条件・直前提案IDも保存。世界の`declined`には逆提案への置き換えが含まれるため、単純な拒否数として解釈しない。
