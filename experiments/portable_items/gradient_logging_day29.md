# 最長日でのMB勾配ログON/OFF比較

2026-11-01。軽量化版7df4747の30日試験で、日次保存時刻差が最大だった29日目（177.51秒）を再実行した。次点は27日目177.43秒で、突出した異常日を選んだわけではない。

## 比較条件

両方とも同じ`day-028.jls`から再開し、29日目だけ進めた。記憶、身体、在庫、環境、乱数状態、過去28日の日次履歴・診断ログを共通の初期状態とする。元の入力・凍結ソースを使用し、終了日を29にする以外は入力を変更しない。

通常の再開ではログ設定も保存状態から復元される。この実験では元のチェックポイント形式・入力同一性・ソースハッシュの検査を通した後、復元直後に各個体の`gradient_logging`だけをONまたはOFFに設定した。元ファイル・本体コードは未変更。変更と計測フックは実験用ランナー内でメモリ上の関数に追加し、そのソースを出力へ保存している。入力JSONのフラグは元のままで、実効設定はprovenanceに記録した。

Julia 1.13.1、1スレッド、別プロセスでON→OFFの順。各プロセスで512シミュレーション秒をウォームアップし、その試行は破棄して元チェックポイントを読み直した。初期512秒で通らない処理のコンパイルを完全に排除した計測ではない。日末保存あり。1組のみで、順序を反転した反復は未実施。

## 数値

| 指標 | ON | OFF |
| --- | ---: | ---: |
| 29日目の計算＋日末保存 | 186.582秒 | 183.742秒 |
| うちチェックポイント保存 | 7.001秒 | 6.868秒 |
| 読込・初期化・最終集計を含む本体呼出し | 205.474秒 | 203.467秒 |
| 本体呼出しの累積割当 | 90.763 GB | 90.699 GB |
| 本体呼出しのGC時間 | 15.686秒 | 15.717秒 |
| プロセスピークRSS（ウォームアップも含む） | 3.120 GB | 3.037 GB |
| 新規勾配ログ | 829件 | 0件 |
| 最終チェックポイント | 183.823 MB | 184.016 MB |

単位は10進。本体呼出しの時間・割当・GCには再開時の読込を含むが、ウォームアップと最終JSON出力は含まない。「29日目の計算＋日末保存」は最初のtickからチェックポイント保存後までの壁時計時間。日次スナップショット作成を含む。元の177.51秒は継続運転中の時刻差であり、今回の再起動・計測フック・ウォームアップとは条件が異なる。

OFFは29日目の時間で2.84秒（約1.5%）短かった。単発の小差なので、安定した1.5%高速化と断定しない。累積割当の削減は約63.3 MB、約0.070%にとどまった。初期3日より判断が多い日でも、新規ログ作成を止めるだけで大幅な高速化は得られなかった。

ONで作成したログはA320・B328・C181件。この日には物を含む取引系41件、食料専用系16件の成立がある。記録は成立だけでなく継続・拒否等の判断も含む。

## 保存サイズについて

OFFでも過去のログを消していない。OFF側は28日目末の直近記録を保持し、ON側は29日目の記録へ置き換える。最終の勾配ログJSON換算サイズはON約5.936 MB、OFF約6.321 MBで、今回は古い記録の方が大きかった。そのためOFFのチェックポイントやJSONが少し大きいことは、新規記録を止めたことと矛盾しない。

これは「最初からログなしで29日回した場合」の容量・速度を測った実験ではない。過去の診断ログを含む読込・日次履歴・保存の費用は両側に残る。

## 一致検査

`compare_gradient_day.jl`で10項目PASS。

- 同じ元チェックポイントSHA256、凍結ソースハッシュ、計測フックのソースハッシュ、入力JSON。
- 実効ログフラグはON/OFF。
- 新しい日次結果は各1日分。
- ログ・ログフラグ・計測値を除いたresult/summary全体が一致。学習済みMB・行動・最終状態を含む。
- 元の30日試験29日目の身体状態・行動回数とも一致。

元試験との比較は身体状態・行動回数まで。追加で調べた元試験とON再実行のチェックポイントのファイルSHA256は一致しなかったため、元試験の内部状態全体やバイト列まで同一とは主張しない。ON/OFF間の全JSON結果一致とは別の確認範囲である。実行時のstderrは両方空。
