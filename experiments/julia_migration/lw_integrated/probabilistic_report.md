# H による確率選択としての慣性（2026-10-22）

`movement_inertia=on` は単独候補による継続を廃止し、共通 BasicLoop の確率選択を有効にする。食料・帰還・安全の各ループで同じ選択式を使う。off は従来の決定的選択を比較用に残す。

- 前回の候補が現在も実行可能なら選好対象とする。存在しない場合は現在の評価順位で選ぶ。
- 親Hと選好候補のHが0なら、候補が複数ある場合の選好確率は99%。残り1%は他の候補に分配する。
- `c = exp(-max(親H/閾値, 候補H/閾値))` とし、99%分布と現在の評価点のsoftmax分布を `c` で混合する。親Hが増えると温度も上がる。
- 親Hによる候補数制限は確率選択では行わない。知覚・身体・安全上の実行可能性は引き続き候補生成側が判断する。
- 前回の歩行結果が現在の身体観測と結び付く場合、既存の方向候補の向きだけを前方へ更新する。候補の追加、優先点の上乗せ、単独選択はしない。食料・危険・目的変更・前方通行不能時にはこの更新を行わない。
- 継続候補の評価質問は通常候補のまま維持する。「歩けた」だけを成功とする慣性専用の質問は作らない。目標未解決なら親Hは増える。取得・帰還の実作業は既存のwork候補を通じて親Hを解消する。
- 視覚の反復Hは診断値として残すが、継続の強制解除には使わない。

入力seedと個体・目的から独立した乱数列を作る。診断用の候補比較は乱数を消費しない。同じ入力・同じJulia版で再現可能。途中再開時のエージェント乱数状態の保存は今回の対象外。

`probabilistic_checks.jl`: 確率総和、非ゼロの代替候補、親H/子H、極端な点差、乱数再現、診断の非干渉、5000回の選択、継続候補の権限を検証（117 assertions PASS）。既存の構造認識・共通移動場63件、地面関連等80件もPASS。

注意: 99%は1選択あたりの値。Hの更新周期・閾値は既存のままであり、長時間の持続を保証しない。視野から出口を意味的に認識する処理は追加していない。既存の地平線・スカイライン候補等の局所評価は保持しているが、親目的未解決Hは選択分布に反映される。
