# Codex初回指示 — Julia移行実験 J0〜J2

**状態:** 実験指示案 / 未実行  
**対応計画:** `RDL_GameAI_Julia_Migration_Experiment_Plan_v0.1.md`  
**確認済み基準HEAD:** `52a94225484f7e1771c4b4c3703c3eb9eef39730`

## 目的

RDL_GameAI_Labの既存挙動を維持したまま、小さな処理をJuliaでも実行・検査・改修できるかを調べる。今回の範囲はJ0〜J2だけ。本線の切替、全面移植、H/ρの新方針実装はしない。

## 作業開始時

リポの上位AGENTS.mdと実験対象配下の規約があれば先に読む。既存作業・未コミット差分を壊さない。`reset --hard`、`clean`、強制push、無断のブランチ移動はしない。

現在HEADを取得し、上記基準との差分を記録する。異なるHEADを黙って同じ基準と呼ばない。必要なら既存作業を変更しない分離worktree等を使う。今回の追加コードは原則 `experiments/julia_migration/` 内、実験出力は `outputs/julia_migration/` 内へ置く。

未導入のツールは導入成功を確認するまで利用可能と扱わない。環境導入が失敗した場合は、失敗箇所と実施済み範囲を残し、性能結果を捏造しない。

## J0：計測基準の固定

commit、OS/CPU、Python版、依存環境、World/個体/seed、`human_scale_v1`、観測間隔1秒、movement_inertia、ログmodeを記録する。

現行の `long_ground_campaign` で180 World秒のevents/offを同条件で実行する。詳細な既存コマンド例は計画書§10を使う。出力先は試行ごとに変える。eventsの監査と、offの最終状態比較を混同しない。比較から除く非意味項目は事前allowlist化する。

別runでcProfile等を使い、監督プロセスでなく実処理workerを計測する。観測生成、幾何、候補処理、履歴コピー/走査、ログ/observer/後処理を分け、重い上位処理を記録する。プロファイラ付き時間は言語間速度比に使わない。

この短窓で夜間・翌日の費用まで測れたとは主張しない。night/Sleepのボトルネックを検証するなら、別の状態fixtureまたは明示した時間窓として提案する。

## J1：独立したJulia環境

Juliaの正確なパッチ版を確認して固定し、実際のProject.toml/Manifest.tomlを保存する。初版は単一スレッドで、通常の関数・構造体・配列、標準Test、必要最小限の入出力とBenchmarkToolsを使う。

既存Pythonの必須依存を変更しない。独自DSL、複雑なマクロ、GPU、分散処理、型の自動増殖は導入しない。JuliaCallでの本線接続は今回行わない。

## J2：小さな同等移植

第一候補は `integrations/lightweight/world.py` の `ray_hit` / `segment_hit` と、それらをまとめて処理するバッチ関数。式・判定境界・順序を保存し、空間索引や近似への変更を混ぜない。

Python側から固定入力と参照出力を生成し、SHA-256を保存する。JuliaでWorldや乱数を同seedだけから作り直さない。境界例20件以上、固定生成例1,000件を初回目安とする。大規模性能用入力は別区分にする。

検査対象には零長線分、円内部始点、背面、接線、端点、margin、閾値の直前/直後、負座標、不正形状、非有限値の宣言した扱い、再実行、入力不変性を含める。

hit/miss・状態・選択対象は厳密一致。距離等の許容差は事前登録し、既存portable replay規則と座標範囲を確認する。計画書の仮案はatol=1e-12 World単位、rtol=1e-12。数値が許容差内でも離散判定が変わるなら不合格とする。結果を見て丸めや期待値を変更しない。

初回・準備後の時間、入力整形、メモリ確保量とGCを別々に測る。ベンチマークでは同じ状態を繰り返し消費しないよう、必要な復元を明示する。実際のバッチ規模と拡大規模を分ける。

初稿後、追加境界例またはバッチの小変更を一つ処理し、既存テストを削らずに修正できたか記録する。AIによる継続改修のしやすさも今回の評価対象とする。

## 変更しないもの

- 既存本線の行動選択、M_B/E/H/θ、ρ、観測頻度、時間profileの規則。
- canonical T1の検査・選別・再構成、既存モデル採用の権限。
- World真値と個体観測の境界、在庫と身体の効果、休息・割込みの条件。
- 既存回帰テストの期待値。既知の別問題が見つかれば分離して報告。
- mainの既定backend。Julia必須化や長時間CI起動をしない。

## 提出物と停止位置

環境の再現手順、入力/出力fixtureとhash、Juliaモジュール、差分テスト、計測コード、生の計測値、最初の不一致、短いreportを保存する。

reportは次を分ける。

1. 実行した内容と結果。
2. 既存資料に書いてあるだけで今回未実行の内容。
3. 推測と、次に必要な検査。

正しさ、冷間時間、反復速度、メモリ、AIによる改修結果をまとめ、J3へ進む／先に修正／移植対象を変える／保留のいずれかを提案して停止する。**一つのカーネルが速くても、GameAI全体が同倍率で速くなったとは書かない。**

Hによる検索範囲拡大、ρ遷移、JuliaCall接続、World本線への有効化、1日・30日・90日運転は、この初回指示に含まれない。
