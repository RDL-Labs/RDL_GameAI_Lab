# 季節的な食料再生：180日試験

2026-11-01。実装と短時間の動作検査後、180日の新規実行を行う。長期結果は完了後に評価する。

## 世界側の再生

`scene.food_season`を設定した場合のみ、従来の満量補充を日次の成長へ置き換える。`food=renewable`、`regrowth_days=1`が必要。未指定なら従来方式を維持する。

成長率（餌場容量に対する1日あたりの比率）は、平均と振幅から `平均 + 振幅*cos(2π*(経過日+phase_days)/period_days)` で与える。1日分を積分し、絶対経過日から累積生産量の整数差を算出する。小数分を毎日切り捨てない。餌場ごとの固定した丸め位置により整数の発生を分散し、乱数は消費しない。実際の追加は日境界で行うため、個数としては段階的になる。

各餌場は元のstock（regrowth_capacityを指定した場合はその値）を上限とする。満杯で入りきらない生産は失われ、後の採集時にまとめて湧かない。既存の食料を減らす操作はしない。携行品・倉庫・有限指定の食料・落とした荷物は再生対象外。種類別追加量と全体収支を既存の台帳へ計上する。

周期や再生率は世界の設定であり、個体の観測・食料予測へ直接渡さない。季節を明示的に学習する新機構は追加していない。今回の波は人の地上食料のみで、兎の草の再生規則は変更しない。

## 実行前に固定する条件

- 入力：[input_180d.json](input_180d.json)。前回の食料余裕あり30日入力から、期間・再生モード・各餌場の再生許可・季節設定のみ変更。
- 新規開始180日。人3体、兎30体。シード20261007。同じ地形・食料位置・種類・個体差。
- 初期食料225＝地上42＋携行3＋個人倉庫60×3。全員の倉庫は従来と同じ果実。初期備蓄の差し替えや途中補給はしない。
- 60日周期、初期は豊富。全餌場に空きがある場合の瞬間的な供給率換算は最大5個/日、最小0.25個/日、平均2.625個/日。実際は整数化・空き容量で減る。
- 低供給期は経過30・90・150日付近。前回の消費約3.4個/日より低い時期と高い時期を作る。ただし備蓄があるため、困窮や交換成立を保証しない。
- 危険off、夜間不安on、初日の設定観察・日次持帰り設定あり。学習full、個人倉庫、消化、食料不安、援助、交換、MB勾配記録は既存設定を維持。
- MB勾配は各個体の直近64判断。日次チェックポイントにも保存。全判断の完全な履歴ではない。
- Julia 1スレッド、ソース凍結、毎日の保存あり。ネイティブ入口・本体・継続ランナーの上限を180日へ拡張。

実行：`julia --startup-file=no --project=. experiments/portable_items/run.jl experiments/seasonal_food/input_180d.json outputs/seasonal-food-180d-20261101`

完了時には同ランナーが日数・物品保存・毎日の食料収支を検査する。継続には日次保存と同じ凍結ソースを用いる。既存の`experiments/acorn_food/continue.jl`も180日・再生食料の継続に対応する。

## 検証と観察対象

`checks.jl`で、180日分の生産波、少量再生、容量上限、有限品・荷物の除外、在庫非減少、設定検証、旧満量補充、短縮時計での6日統合・種類別収支・再開一致・180日の実行境界を検査する。短縮時計の動作検査は、実時計180日の行動評価とは区別する。

開始前の検査：季節再生203項目、食料交換232項目、依存方向641項目PASS。長期試験そのものの合格を意味しない。

本試験では日ごとの追加食料・地上残量・個人備蓄・身体reserve・食料不安H・採集・援助・交換提案と成立・処理費用を見る。豊富な時期に備蓄し、乏しい時期に取り崩すかを確認する。前回とは再生と期間が変わるため、単純な交換件数の大小だけで学習効果を断定しない。

過去30日は約58分。単純換算で180日は約6時間だが、日次保存と記憶・履歴の増大により延び得る。これは速度比較実験ではない。
