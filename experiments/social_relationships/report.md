# 個体間の関係・援助と交換への接続

2026-10-29。Julia 1.13.1 / Windows / Julia・OpenBLAS各1スレッド。変更前HEADは`0714672`。

## 実装

本人→相手の方向で、接触時間・援助の成否・交換への応諾・本人の交換利得を別々に保持する。援助と交換で得た相手との経験を、依頼先・依頼・譲渡・交換の候補重みへ接続した。片方の評価をもう片方へコピーしない。

関係は候補の有限な重みとして作用し、身体の要求・実在する在庫・物理的な接触条件を上書きしない。明示的拒否は再依頼や再提案の見込みへ使い、悪意や損害へ変換しない。未応答・実行不能は別軸に保つ。後の成功で見込みを回復できるよう、関係ON時は過去の拒否H最大値による旧抑制を置き換える。

依頼先の選択もONでは共通のH依存確率へ接続した。援助・交換の個別条件の経験は既存の目的・方法側に残す。関係表の重みを物理的な交換利得へ加算しない。[仕様・初期係数・適用範囲](../../docs/design/LW_Social_Relationships.md)。

## 接続検査で確認した応答

同じ食料・在庫・乱数条件の受諾確率を比較した。

| 相手との経験だけを変えた条件 | 受諾確率 |
| --- | ---: |
| 過去の交換で損をした | 0.2130 |
| 未経験 | 0.2739 |
| 過去に援助を受けた | 0.3154 |

一つの実交換について、Aには正の実利得、Bには負の実利得がそれぞれ記録された。相手の在庫・価値判断を参照せず、本人の交換直前直後の在庫差を使った。提案時には成功を記録せず、本人が結果を受け取ってから一度だけ更新する。

これは固定した初期価値式・係数の下で、観測経験によって関係の見積もりと選択が変化した検査であり、友情・性格・所有概念を自律的に発見したという結果ではない。

## 同時に修正した依頼receiptの欠落

最初の3日試験では世界の譲渡45件に対して援助として認識されたのは28件だった。残り17件はすべて、実際には依頼を実行していたのに`request_not_executed`へ誤分類されていた。

例は、24秒にAがBへ依頼、25秒にAが別件を拒否、26秒にBがAへ譲渡、27秒のAの観測で未実行と判定する経路。`results[a]=D(op=>r)`が別件の拒否結果へ置き換わり、未決の依頼の実行receiptを失っていた。変更前HEADにも存在する不具合で、新関係表は既存の誤分類をそのまま受け取っていた。

最新の結果と未決依頼の実行結果を最大2件だけ保持するよう修正した。解決後は次の結果更新で古い分を外す。実行不能だった依頼を成功へ変えることはない。旧処理での失敗再現、修正後の世界操作、途中保存、件数上限を31項目で確認し、同じ入力の3日試験を最初から再実行した。[修正前の監査](evidence/receipt-before-fix.json)。以下の最終結果は修正後のもの。
