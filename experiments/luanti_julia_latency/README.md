# Luanti → Julia 最小通信・判断実験

2026-10-21 / Windows、Luanti 5.17.0、Julia 1.13.1。
Python不使用。実Luanti専用サーバーのmodからlocalhost HTTPでJuliaを呼ぶ。
既存 `src/ecology/herbivore/decision.jl` の状態機械を直接使用する。

## 範囲

3/6個の論理個体が250msごとに個別リクエストを送る。各条件約22秒。
入力は固定エネルギーと周期的な草・危険信号。実地形の視覚、移動するentity、
生態系の身体更新、LWの探索・Sleep・履歴・MB評価は含まない。
返ったID・連番・期待状態を全応答で照合し、個体の状態へ適用する。
未完応答がある個体は次の送信をスキップし、その数を記録する。
したがって旧試験の深さ8の待ち行列を再現するものではない。

専用server stepは10ms。RTTはLua送信直前から非同期callback受信までで、
HTTP・Julia処理・Luantiのcallback待ちを含む。ネットワーク時間単独ではない。
Julia処理時間はbody読み取り後のJSON解析・判断・最初の応答JSON生成まで。
最終wrapperの生成、socket読書き、accept待ちは含まない。
Julia判断関数を事前に1回呼び、集計は最初の4送信周期を除外する。
3体→6体の順に同じJuliaプロセスで測る。繰り返し比較ではない。

両条件とも照合エラー0、スキップ0、終了時未応答0。最大未応答数は3/6。
分位点はソート後floor((n-1)*p)の要素。短時間の単一試行で長期安定性は示さない。
RTTの約10msには設定したserver stepによる受信処理待ちが含まれる可能性があるが、
step別比較をしていないため寄与率は未測定。

旧Luanti/Python試験の約2.05秒は長期履歴を含む別の観測処理であり、
この結果からJulia化の速度倍率や旧遅延の解消を主張しない。
次は実観測とLW判断処理を接続し、同一負荷で履歴増加に伴う時間を測る。

## 再現・保存

リポジトリrootで `./experiments/luanti_julia_latency/run.ps1`。
`-Luanti` / `-Julia` で実行ファイルを変更可能。
MINETEST_USER_PATHをoutputs内の専用フォルダへ一時変更し、ユーザーのゲームやWorldを変更しない。
作成した2プロセスは終了時に片付ける。HTTPは127.0.0.1:18765、Worldは127.0.0.1:30987。
HTTP処理は有限実験専用で、本番用の堅牢なサーバーではない。

成功ログ: `outputs/luanti-julia-latency-20261021-224526/`。
各worldフォルダに全応答のlatency.json、summary.json、Luantiログを保存。
最初の制限環境での試行 `outputs/luanti-julia-latency-20261021-224444/` は
接続失敗で監査不合格。成功集計から除外し、失敗ログは保持する。
同じ実験を制限外で再実行して上記が得られた。
