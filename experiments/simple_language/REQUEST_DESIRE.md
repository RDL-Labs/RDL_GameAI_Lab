# 要求品目を本人の食品評価へ接続

2026-11-17。魚在庫ゼロ→「魚 欲しい」という固定を撤去。

`configured_want_desire` は通常取引と同じ `food_trade_weights` を使う。
味の経験・身体状態・加工予測を参照し、現在の備蓄に1個追加した
対数効用差と `trade_compound_gradient`（食料不安・期限による廃棄予測）を評価する。
正の合成勾配が最大の品目を要求する。相手の非公開在庫は参照しない。
これは要求対象の選択であり、無償入手や取引成立の保証ではない。

発話時の品目と勾配内訳を記録し、その品目を返答後の提案まで保持する。
新規提案は要求品目が純増する候補に限定する。支払いや他の品目の
組合せ・相手の拒否・逆提案は既存の取引判断を継続する。
要求以外の品目を一切含めない変更や、双方同一品目の相殺は今回の範囲外。

暫定固定は実験ON時のみ：1日1回、8秒待機、既知語句の表、直接振り向き、
最初に認識した返答相手との交渉。初期A〜Dに各食品語を教え、Eは未学習。
将来は発話・待機・相手選択も学習へ移す。最大勾配の要求選択は現在決定的。
既存保存の語彙を自動上書きしないため、旧保存は未知語が残り得る。
旧pendingに品目がない場合だけ、旧実験の魚要求として復元する。

局所検査：`experiments/simple_language/want_living_checks.jl`。
果実／魚への備蓄依存の切替、発話と保持品目、返答から本人認識・提案・
所有権収支を確認する。長期20+20日比較は今回まだ実施しない。
